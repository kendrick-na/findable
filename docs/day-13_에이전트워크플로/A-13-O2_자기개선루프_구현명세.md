## 2. P0-① 타임아웃 가드 명세

현재 `generateAnalyst`/`generateStrategist`엔 타임아웃이 없다(grep 0건). AbortSignal 주입.

```
// 명세 (의사코드 — 실코드 아님)
const TIMEOUT_MS = Number(process.env.FINDABLE_CREW_TIMEOUT_MS ?? 60_000)

async function generateAnalyst(agentKey, prompt) {
  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), TIMEOUT_MS)
  try {
    const result = await CREW_AGENTS[agentKey].generate(
      [{ role: "user", content: prompt }],
      { structuredOutput: { schema: analystOutputSchema }, abortSignal: controller.signal }
    )
    ...
  } catch (error) {
    // AbortError면 errorMessage = "CREW-408 timeout 60s"
  } finally {
    clearTimeout(timer)   // ⚠️ 반드시 clear — leak 방지
  }
}
```
- ⚠️ **[확인필요]**: Mastra `Agent.generate`가 `abortSignal` 옵션을 실제 지원하는지 버전 확인(AI SDK v6는 지원, Mastra 래퍼 통과 여부는 실측). 미지원 시 `Promise.race([generate, timeoutReject])`로 폴백.
- 주석(orchestrator.ts:16)의 "재시도 1회"도 이때 **실제 구현하거나 주석 삭제**(거짓 약속 제거).

## 3. P0-② 크래시 stuck 감지 명세

현재 프로세스가 죽으면 `crewStatus="processing"` 영구 stuck. `catch`는 예외만 잡고 크래시는 못 잡음.

두 가지 방어(택1 또는 병행):
1. **stuck 타임스탬프 기반**: `crewStartedAt`이 존재하고 15분 초과 + status=processing → 조회 시 "stale"로 간주, 재실행 허용. (조회 라우트에서 판정, 스키마 무변경)
2. **durable 실행 전환**: `after()` → Vercel Workflow(WDK) step 기반. 크래시 시 자동 resume. ⚠️ 큰 변경 → Day16 배포 트랙과 함께.

> P0에선 **1번(stale 감지)** 만. 저위험. 2번은 Day16 후보로 백로그.

## 4. P1 자기평가 1패스 (Reflection) 명세

### 4-1. critique 스키마 (신규)
```
const critiqueSchema = z.object({
  score: z.number().int().min(0).max(100).describe("산출물 품질 0~100"),
  passed: z.boolean().describe("score >= 임계(70) 여부"),
  issues: z.array(z.string()).describe("발견된 문제 (없으면 빈 배열)"),
  refinementHint: z.string().describe("개선 방향 1문장 (passed면 빈 문자열)"),
})
```

### 4-2. 흐름 (analyst 1명 기준)
```
1. output = generateAnalyst(sonnet)          // 생성
2. output null이면 → 종료 (기존 폴백)
3. critique = generateCritique(haiku, output) // 평가 (싼 모델)
4. critique.passed면 → output 그대로 반환
5. 아니면 → refined = generateAnalyst(sonnet, prompt + critique.refinementHint)  // 개선 1회
6. refined 반환 (재평가 안 함 — N=1 종료조건, 비용 가드)
```

### 4-3. critique 프롬프트 골자
```
"다음은 GEO 분석 산출물이다. 아래 기준으로 0~100 채점하라:
 - findings가 제공된 실제 데이터를 인용하는가 (환각 아닌가)
 - whyItMatters가 50자 이내이고 임원이 이해 가능한가
 - dataGaps가 정직한가 (모르는 걸 아는 척 안 하는가)
 70 미만이면 passed=false, refinementHint에 개선 방향 1문장."
```

### 4-4. 종료 조건(④) — 무한루프 방지 강제
- refine은 **최대 1회**(N=1). 재평가 루프 없음.
- refine 진입 전 **경과시간 체크**: crew 전체 예산(예 8분) 80% 소진 시 refine 스킵 + `dataGaps`에 "품질 미검증(예산초과)" 추가.
- → self-improving이되 **bounded**. 비용·지연 상한 보장.
