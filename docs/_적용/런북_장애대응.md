## 2. audit 잡 stuck 급증 ("결과가 안 나와요")

| 항목 | 내용 |
|------|------|
| **증상** | 사용자가 진단 결과 화면에서 무한 대기. `status=processing`·`crewStatus=processing`이 15분 넘게 고정. 문의 반복. |
| **원인 후보** | Vercel 함수 급사(kill·크래시)로 정리 코드 미실행. 함수 상한(maxDuration) < crew 타임아웃 → 함수가 먼저 죽음(D16-4). AI 엔진 장애로 crew 무한 대기. |
| **대응 순서** | ①**stuck 스윕 수동 트리거**: `/api/cron/sweep-stuck-jobs` 호출(헤더 `Authorization: Bearer $CRON_SECRET`) → 오래된 잡을 `failed`로 정리(멱등). ②Logtail에서 `audit.crew.*`·`cron.sweep-stuck-jobs.swept` 확인. ③특정 엔진 장애면 §3으로. ④빈발 시 sweep cron 주기 단축(하루1회→15분, 유료플랜 필요) 검토. |
| **관련** | Day13~17 핵심 이슈. sweep cron = `apps/web/app/api/cron/sweep-stuck-jobs` (⚠️web·api 이중구현 정리 필요 = BL-Day17-01). |

## 3. AI 엔진 장애 (특정 엔진 오류 급증)

| 항목 | 내용 |
|------|------|
| **증상** | 특정 엔진(Letsur·Google·Perplexity·Naver 등) timeout·오류 급증. 진단 점수 이상·일부 엔진 결과 누락. |
| **원인 후보** | 외부 AI 제공사 장애·rate limit·크레딧 소진·API 스펙 변경. |
| **대응 순서** | ①Logtail에서 어느 엔진이 실패하는지 특정. ②해당 엔진 **env 플래그로 비활성**(예: 네이버 = `FINDABLE_DISABLE_NAVER_BRIEFING`) → 나머지 엔진으로 서비스 유지. ③제공사 상태페이지 확인. ④크레딧 소진이면 충전·렛서 게이트웨이 한도 확인. ⑤복구 후 플래그 원복. |
| **면책 근거** | 이용약관 제5조 "외부 AI 엔진 장애로 인한 서비스 중단은 책임지지 않음" (이미 고지됨). |

## 4. 결제 실패 급증

| 항목 | 내용 |
|------|------|
| **증상** | checkout에서 결제 오류·429. 결제했는데 플랜 미반영 문의. |
| **원인 후보** | PortOne 장애. `payments/verify` 검증 실패. 웹훅 미도달. |
| **대응 순서** | ①**PortOne 콘솔**에서 결제 건 상태 확인(승인/실패/대기). ②`apps/web/app/api/payments/verify` 로그 확인. ③결제됐으나 플랜 미반영이면 **수동 대사(對事)**: PortOne 결제내역 ↔ DB 플랜 상태 대조 후 수동 반영. ④PortOne 장애면 상태페이지 확인·안내 공지. |
| **주의** | 실제 활성 PG = **PortOne 단독**(Stripe는 미배포 api 잔재). 환불 = 이용약관 제4조 "결제일 7일 이내 미사용분". |
