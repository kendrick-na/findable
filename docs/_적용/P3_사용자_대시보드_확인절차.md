## ⚡ 지금 순서대로 하면 되는 것 (요약 — 5분)

**사이트 2곳만 열면 된다: Clerk 대시보드 / Vercel 대시보드.** 아래 6개 끝나면 "완료"라고 말해줘 → 내가 배포하고 "추적 시작"으로 실검증한다.

### Clerk 대시보드 (clerk.com → Findable production instance)
1. **Domains / Allowed origins**: `https://www.findable.co.kr` 와 `https://app.findable.co.kr` **둘 다** 있는지. 없으면 추가.
2. **Sessions / 쿠키 설정**: 쿠키 도메인이 `.findable.co.kr`(맨 앞 **점**)인지.
3. **Webhooks → Add Endpoint**: URL = `https://app.findable.co.kr/webhooks/auth`, 이벤트 7개 체크(user.created/updated/deleted, organization.created/updated, organizationMembership.created/deleted). 저장하면 **Signing Secret `whsec_...`** 이 나옴 → 복사(4번에 씀).

### Vercel 대시보드 (vercel.com → findable-app 프로젝트 → Settings → Environment Variables → Production)
4. **`CLERK_WEBHOOK_SECRET`** = 방금 복사한 `whsec_...` 값. (없으면 새로 추가.)
5. **`AI_GATEWAY_API_KEY`** 가 있는지 확인. **없으면** www(findable) 프로젝트의 같은 키 값을 복사해 추가. ← *P2로 러너가 app에서도 돌게 되어 새로 필요해진 유일한 키.*
6. **`NEXT_PUBLIC_APP_URL`** 값이 `https://app.findable.co.kr`(`app.` 포함)인지. `DATABASE_URL`은 이미 있을 것(확인만).

> ※ `AUDIT_DUAL_WRITE_ENABLED`는 지금 **건드리지 마라**(OFF 유지). P5에서 데이터 채울 때 켠다.
> ※ 위 상세 근거·왜 필요한지는 아래 A~D 섹션에.

## A. P3 — Clerk/도메인 3값 정합 (로그인·세션 안정화의 근본)

전략리뷰 결론: "3주 로그인 재발"의 근본은 컴포넌트가 아니라 **아래 3개 런타임 값의 정합**이다.
satellite는 **불필요**(Clerk은 같은 상위도메인 subdomain끼리 세션 기본 공유. www·app 둘 다
`*.findable.co.kr`이라 satellite 없이 세션이 흐른다). satellite는 최상위 도메인이 다를 때만.

### A-1. Clerk allowed origins (두 subdomain 등록)
- 위치: Clerk 대시보드 → **production instance** → Domains(또는 Paths/Allowed origins)
- 확인: `https://www.findable.co.kr` 와 `https://app.findable.co.kr` **둘 다** 등록됐는지
- 하나만 있으면: 없는 쪽에서 Clerk 요청이 거부돼 로그인/세션이 깨진다

### A-2. 쿠키 도메인 = `.findable.co.kr` (맨 앞 점 필수)
- 위치: Clerk production instance의 쿠키/세션 도메인 설정
- 확인: `.findable.co.kr` (앞에 **점**). 점이 있어야 www·app 두 subdomain이 **같은 세션 쿠키**를 공유
- `findable.co.kr`(점 없음)이면: subdomain 간 쿠키 공유 안 됨 → app에서 로그인 풀림

### A-3. `NEXT_PUBLIC_APP_URL` = `https://app.findable.co.kr` (`app.` 필수)
- 위치: Vercel → **findable(web)** 과 **findable-app** 두 프로젝트 → Settings → Environment Variables → Production
- 확인: 실값이 `https://app.findable.co.kr` 인지. **`app.` 이 빠져 `https://findable.co.kr`로 돼 있으면 버그 원인**
- `app.` 누락 시 영향(코드 실측): 파트너 승인 메일 링크·홈 CTA·헤더 sign-in/sign-up 링크가 전부 www로 오배선 + 세션 쿠키 스코프 어긋남
  - 사용처: `apps/app/app/actions/partner/decide.ts`, `apps/web/.../components/cta.tsx`, `apps/web/.../header/index.tsx`, `apps/web/app/api/audit/[jobId]/lead/route.ts`
- ⚠️ 이 env는 여러 곳이 "app 링크"로 쓰므로, 값을 바꾸면 위 링크 전부에 영향. 바꾸기 전 왜 www로 돼 있었는지(의도였는지) 확인 후 수정.

## B. P2 배포 시 env 점검 (러너가 이제 app에서도 실행됨)

P2로 러너(`runAuditJob`)가 `@repo/audit` 공유 패키지가 돼서, **app 서버액션이 직접 실행**한다.
즉 러너 실행에 필요한 env가 **app Vercel 프로젝트에도** 있어야 한다(예전엔 www에서만 돌아서 www에만 있으면 됐음).

findable-app 프로젝트 → Settings → Environment Variables(Production)에 아래가 있는지 확인:
- `DATABASE_URL` — 러너가 AuditJob·Tracking write
- AI Gateway 키(엔진 호출용, 러너가 queryAllEngines 실행) — www에 있는 것과 동일 키
- `AUDIT_DUAL_WRITE_ENABLED` — 20번 Tracking 적재 flag. **지금은 OFF/미설정 유지**(라이브 영향 0). P5에서 켤 때 설정.

없으면: app에서 "추적 시작" 클릭 시 러너가 DB/엔진 접근 실패로 AuditJob이 failed 처리된다.

## C. P2 라이브 실검증 (배포 후 1회)

app은 로컬 빌드 불가(Clerk env 빈값)라 배포 전엔 실행 검증이 안 된다. 배포 후:
1. app 대시보드 로그인 → brand 페이지 → **"추적 시작"** 클릭
2. 성공 토스트("추적을 시작했어요") 뜨는지
3. 잠시 후 AuditJob이 생성되고(status processing→completed) 대시보드에 반영되는지
4. (flag ON 시) Tracking 행이 쌓이는지

이 경로는 이제 **app 서버액션 → 러너 직접 호출**이라 CORS가 원천적으로 없다. 401이 떠도
"satellite 설정" 문제가 아니라 A-1~A-3 정합 문제다.

## D. P1 — Clerk 웹훅 이설 후 사용자 몫 (신원 소유자 살리기)

P1으로 Clerk 웹훅(org/user를 Prisma DB에 적재)을 미배포 apps/api → 배포된 apps/app으로
이설했다(커밋 `e2704a5`). 웹훅이 실행 0회였던 게 org 0행/AuditJob 54행의 직접 원인이었다.
코드는 완료됐고, 아래 2개를 대시보드에서 설정해야 실제로 살아난다:

### D-1. Clerk 웹훅 구독 URL을 app 도메인으로 (재)등록
- 위치: Clerk 대시보드 → production instance → Webhooks(또는 Configure → Webhooks)
- 설정: Endpoint URL = `https://app.findable.co.kr/webhooks/auth`
  - (이설 전 apps/api 도메인으로 등록돼 있었다면 이 URL로 교체. 없었으면 신규 생성.)
- 구독 이벤트: `user.created`, `user.updated`, `user.deleted`, `organization.created`,
  `organization.updated`, `organizationMembership.created`, `organizationMembership.deleted`
- 저장 시 Clerk가 **Signing Secret**(`whsec_...`)을 발급 → D-2에 사용

### D-2. `CLERK_WEBHOOK_SECRET`을 findable-app Vercel env에 설정
- 위치: Vercel → **findable-app** 프로젝트 → Settings → Environment Variables → Production
- 설정: `CLERK_WEBHOOK_SECRET` = D-1에서 발급받은 `whsec_...` 값
- ⚠️ 빈값이면 웹훅이 `{ok:false}` 200만 반환하고 DB 적재를 안 한다(안전 실패). 값 넣고 재배포해야 작동.
- 재배포 후 검증: Clerk 대시보드 웹훅 → "Send test event"(organization.created) → app DB에
  Organization row가 생기는지. 또는 실제 신규 org 생성 → org row 확인.

### D-3. (선택) 기존 org 0행 backfill
웹훅은 **이후** 이벤트만 적재한다. 이미 존재하는 org/user는 웹훅이 안 채운다.
당장은 ensure-org 폴백(트리거 시 lazy upsert)이 메꾸므로 급하지 않으나, 완전 정합을 원하면
Clerk의 기존 org/user를 일괄 backfill하는 1회성 스크립트가 필요(P5에서 데이터 채울 때 함께 검토).
