## 1. 현재 진단 (코드 실측)

### 1-1. 대시보드 = **너무 적다**

`apps/app/(authenticated)/page.tsx` 실측 구성:
```

최근 측정 이력
파트너 CTA · 업그레이드 사다리
```

**문제 3개**
1. KPI 4장 중 **2장이 운영지표**(총 측정 횟수·마지막 측정) — 고객의 성과가 아니다
2. **평균 포지션이 없다** — 업계 3대 지표 중 하나가 빠졌다
3. **Sentiment가 없다** — `metrics.sentimentDistribution`에 데이터는 있는데 화면에 안 온다

### 1-2. 무료진단 결과 = **너무 많다** (반대 문제)

## 2. 🔴 리서치가 준 가장 중요한 답 — 가치 역전의 진짜 원인

**내가 처음 생각한 처방(진실거울을 대시보드로 복사)은 틀렸다.**

증거 기반 실패 사례(Docker·Evernote·Zoom·PlanetScale·Heroku)가 같은 패턴을 보여준다 —
[The Free Tier Trap](https://www.getmonetizely.com/blogs/the-free-tier-trap-why-free-isnt-always-a-winning-strategy-for-startups) ·
[Second Order Labs](https://secondorderlabs.com/articles/growth/freemium-conversion-stalls-once-the-free-tier-solves-the-core-job-too-well/):

> **Docker**: 무료 티어가 핵심 문제를 완전히 해결해서 유료 전환 유인이 사라짐.
> *"indispensability가 최악의 과금 전략이었다"*

**진짜 문제는 섹션 개수가 아니다. 무료가 "반복 확인할 이유"까지 다 줘버린 것이다.**

### 정답 = 축을 바꾼다

| | 무료 | 유료 |
|---|---|---|
| **주는 것** | **1회성 진단** = "지금 우리가 AI에 얼마나 보이나" (aha) | **시간·비교·알림** = "이게 변하고 있나" |
| 업계 선례 | Slack(메시징 무료) · Figma(파일 무료) · GitHub(저장소 무료) | Slack(**히스토리** 유료) · Figma(**팀 라이브러리**) · GitHub(**CI 분**) |

> **유료가 이겨야 할 축은 "더 많은 정보"가 아니라 "시간이 지나도 이 정보가 유효한가"다.**

⚠️ 과도한 게이팅 리스크: **최대 30%가 경쟁사로 이탈**([Artisan](https://www.artisangrowthstrategies.com/blog/feature-gating-economics-how-saas-companies-decide-what-goes-free-vs-paid)).
전환율 현실: 프리미엄 무료→유료 **2~5%**, 상위 PLG도 5~10%.

## 3. 업계 표준 대조 — 창작할 것 vs 따를 것

### 3-1. 히어로 KPI = **따를 것** (15개 툴 수렴)

| 지표 | 채택 툴 |
|---|---|
| **Visibility %** | Profound·Peec·Rankscale·Evertune·Goodie·Trakkr·Gauge·Otterly·Athena — **전원** |
| **Position** (평균 순위) | Profound(5.1)·Peec·Evertune·Trakkr·Otterly(2.05) |
| **Sentiment** | Profound(GOOD/중립/BAD)·Peec(0~100)·Goodie·Gauge·Otterly |
| **0~100 점수** | Evertune "AI Brand Score"·Semrush "AI Visibility Score"·Rankscale |

**Peec 공식 3축** = Visibility / Position / Sentiment ([docs.peec.ai](https://docs.peec.ai/understanding-your-performance))

⚠️ **주의**: Visibility와 SoV는 **다른 지표다.** Visibility=몇 %의 답변에 등장 / SoV=경쟁사 대비 점유율. 지금 우리는 SoV만 있다.

**그리고 전원이 순위를 병기한다** — Profound *"43.8%, 339위"*. **숫자만으론 좋은지 나쁜지 모른다.**

### 3-2. KPI 개수 = 3~5장

| 근거 | 값 |
|---|---|
| Stripe 실제 | **4장** |
| Google Search Console | 4개 지표, **기본 2개만 ON** |
| 정제 권고 | **Tier1 3~5 + Tier2는 드릴다운** |

⚠️ *"진행형 공개가 인지부하 55% 감소"* 류 수치 = **1차 출처 추적 실패 → 인용 금지**

### 3-3. 라벨 = **질문형으로 창작** (Trakkr 차용)

Trakkr는 지표명 대신 **질문**을 쓴다 — 비개발자에게 직관적:
```
Citations  → "어디에 등장하나?"
Rankings   → "내 위치는?"
Perception → "AI가 나를 어떻게 말하나?"
Crawler    → "AI가 내 콘텐츠를 찾을 수 있나?"
```
Stripe도 같은 원칙: 라벨은 **시스템 구조가 아니라 사용자 의도** 기준(*"Chargeback Events"* ❌ → *"Disputes"* ○).

### 3-4. 0점 상태 = **따라잡아야 하는 표준** (내 최초 판단 정정)

처음엔 *"경쟁사가 안 한다 = 우리 차별화"*로 봤으나 **15개 툴 조사로 반박됨.** 이미 관행이다:

| 툴 | 방식 |
|---|---|
| **Semrush** | **"Your brand not mentioned"** 태그 + **"Topic Opportunities"**(경쟁사는 인용되는데 우리는 빠진 프롬프트) |
| **AthenaHQ** | 갭을 **단일 원인 도메인까지 추적** — *"seranking.com이 30개 답변 중 4개에 인용됨"* ← **가장 구체적** |
| **Otterly** | 크롤가능성 체커 + 콘텐츠 감사 + *"invisible 페이지를 AI 소스로 바꾸는 콘텐츠 브리프"* |
| **Goodie** | *"경쟁사는 인용되는데 당신이 안 보이는 토픽"* |
| **Gauge** | Action Center — **임팩트/난이도 순 우선순위** |

**우리가 이겨야 하는 기준선 = AthenaHQ의 "단일 원인 추적".**

### 3-5. 🎯 진짜 공백 = **처방** (15개 툴 전체 리뷰어 합의)

> *"측정은 잘하는데 **무엇을 해야 할지는 안 알려준다**"*
> — Peec(*"모니터링 툴이지 최적화 툴이 아니다"*) · Ahrefs(*"데이터는 주는데 방향이 없다"*) ·
> Goodie(*"데이터만 보여주고 막막하게 남긴다"*) · Rankscale — **독립적으로 반복 지적**

**Findable엔 `/actions`·GEO 액션·처방이 이미 있다. 이게 카테고리 1군이 못 하는 것이다.**
→ **처방을 1급 시민으로 승격**하는 것이 전략의 핵심.

### 3-6. Ahrefs에서 훔칠 지표 1개

**"Found, but not cited"** — 답변에 **이름은 나오는데 링크가 없는** 상태([방법론](https://ahrefs.com/blog/brand-radar-methodology/)).
대부분 경쟁사가 이 둘을 구분하지 않는다. 우리는 `engineResponses`에 데이터가 있어 **구분 가능**.

## 4. 화면 개선안

### 4-1. 대시보드 (더하기 ⬆️)

**히어로 3장 + 보조 1줄**
```
┌─────────────────────┬─────────────────────┬─────────────────────┐
│ AI가 우리를 아나?    │ 몇 번째로 말하나?    │ 좋게 말하나?         │
│ 42%      ↑ 3%p      │ 1.8번째             │ 긍정 15%            │
│ 10번 물어 4번 등장   │ 경쟁사 평균 2.4번째  │ 긍정 3 · 보통 17    │
└─────────────────────┴─────────────────────┴─────────────────────┘
  측정 12회 · 2일 전 · AI 5곳 중 3곳에서 등장     ← 작게, 회색
```
- 라벨을 **질문형**으로 (Trakkr 차용 + 토스 "쉽게 말하기")
- 힌트에 **비교값 병기** (Stripe: 맥락 없는 절대값 금지)
- 운영지표는 **한 줄로 강등**
- **스파크라인**을 각 카드에 삽입 — Ahrefs·Stripe **공통 표준**(숫자+델타+미니선그래프 3종 세트)
- 숫자 옆 **티어 라벨** — 02번 §D2: *"숫자+티어 라벨이 맨 숫자를 이긴다"*

> ### ✅ 사용자 승인 = **A안** (2026-08-06 세션N-5)
> 운영지표(총 측정 횟수·마지막 측정)는 **삭제가 아니라 회색 한 줄로 위계 강등**. 정보는 유지.
> **B안(KPI 6장) 기각.** 근거 3개:
> ① 리서치 *"KPI를 늘리지 말고 줄일 것"*에 정면 위배 (Stripe 4장·GSC 기본 2개 ON)
> ② Carbon **Presentation 선언**과 충돌 = *"한 화면에 두 의도 섞는 문서화된 실패 모드"*
> ③ **§2 전략과 충돌** — 6장은 *"더 많은 정보"로 이기려는 것*. 유료 축은 **시간·비교·알림**이어야 함(Docker형 실패 재발 경로)
> 🎯 3장으로 좁혀두면 4-3 이벤트핀·4-4 CSV 같은 **유료 전용 지표가 들어갈 자리가 남는다**(Tier1 3~5 / Tier2 드릴다운).
> ⚠️ **실고객 0명 상태의 판단.** 실고객이 *"측정 언제 했는지가 제일 궁금하다"* 고 하면 전제가 깨진다 — 되돌리기 쉬운 쪽이 A안이라는 점도 선택 이유.
