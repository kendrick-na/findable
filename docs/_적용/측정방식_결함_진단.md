# Findable 측정 방식(audit 파이프라인) 결함 진단

> 2026-07-27. 계기: 설화수(sulwhasoo.com) 실측 결과에서 "Daum이 설화수를 모름", 경쟁벤치 본인
> 미발견↔SoV 79% 모순, 무관 도메인 인용, 마크다운 깨짐 등 다수 오류. 나현덕님 지적: "다음만 볼 게
> 아니라 측정 방식 자체의 결함 원인을 파악하라." → 증상이 아니라 **파이프라인 설계 결함**을 계층별로.

---

## 0. 한눈에 — 측정은 어떻게 작동하나 (현재)

```
도메인 입력(sulwhasoo.com)
  → inferBrandName() → "Sulwhasoo" (⚠️영문만, "설화수" 아님)
  → generateAuditPrompts() → 프롬프트 4개 생성
  → 7개 엔진(chatgpt·claude·perplexity·gemini·hyperclova·naver·daum) × 4프롬프트 = 28개 호출
      · 글로벌 4개: LLM이 문장으로 답변 생성
      · 한국 3개: hyperclova=LLM / naver·daum=검색 API 스니펫(LLM 없음)
  → 각 응답마다: detectBrandMention(문자열 포함?) · SoV · 순위 · 감성 · 출처 추출
  → aggregateAudit(28개) → SoV·커버리지·출처 집계
  → 결과 페이지 렌더 (+ 클라이언트서 경쟁벤치·매출번역 계산)
```

**결함은 이 사슬의 3개 지점에 겹쳐 있다: ①입력(브랜드명) ②질문(프롬프트) ③판정(문자열 매칭·엔진 이질성).**

## 1. 근본 원인 — 3층 구조적 결함

### 🔴 1층: 프롬프트가 "브랜드"를 안 묻는다 (설계 결함)
`apps/web/lib/audit/runner.ts:54-77` generateAuditPrompts. ko 4개:
1. `{브랜드}와 같은 카테고리의 인기 브랜드 5가지 추천해줘` — **경쟁사 나열형**
2. `{브랜드} 경쟁사 대표 브랜드를 순위로 알려줘` — **경쟁사 나열형**
3. `{브랜드} 추천해줘` — 브랜드 자체형
4. `{브랜드}의 장단점은?` — 브랜드 자체형

- **`both` 모드(기본): `ko.slice(0,2)+en.slice(0,2)` → 4개가 전부 경쟁사 나열형**(runner.ts:73-76). 브랜드 자체를 묻는 질문이 **0개**.
- 문제: "설화수 경쟁사 알려줘"의 답변은 **경쟁사만 나열**하고 설화수 본인은 서두에만 나오거나 아예 안 나옴. 그런데 뒤의 판정(2층)은 "답변에 설화수 문자열 있냐"로 언급을 재니, **구조적으로 미언급·미발견을 유발**.
- 즉 "설화수가 AI에 안 뜬다"가 아니라 **"우리가 AI에게 설화수를 안 물어봤다".**

### 🔴 2층: 판정이 단순 문자열 매칭 + 입력 브랜드명이 영문뿐 (판정 결함)
- `detectBrandMention`(utils.ts:9-31) = `text.toLowerCase().indexOf("설화수")` 단순 substring.
- 입력이 도메인뿐이면 `inferBrandName("sulwhasoo.com")="Sulwhasoo"`(runner.ts:34-42) → **한글 "설화수"가 후보에 없음**. 한국어 답변엔 "설화수"만 있고 "Sulwhasoo"는 없어 → **미언급 오판정**.
- `brandVariants`(entityVariants=한/영 병기)를 넘기면 해결되나, audit 진입점(도메인만 입력)에선 안 넘어옴(runner.ts:84 `?? [brandName]`).

### 🔴 3층: 엔진마다 측정 방식이 다르다 (이질성 결함) — Daum 문제의 진짜 원인
동일 지표로 비교하는데 **엔진이 만드는 텍스트의 성격이 완전히 다름**:
| 엔진 | 텍스트 생성 방식 | brandMention 판정 대상 |
|---|---|---|
| chatgpt·claude·perplexity·gemini | **LLM 서술** — "설화수의 경쟁사는…"이라며 브랜드 되뇜 | 자연히 "설화수" 포함 → 언급O |
| hyperclova | LLM 서술 | 포함 경향 → 언급O |
| naver | 검색 API 스니펫 | 스니펫에 브랜드명 있을 때만 |
| **daum** | **카카오 검색 스니펫 raw**(LLM 합성 없음, korean-adapters.ts:271-279) | **경쟁사 나열형 검색이라 스니펫에 "설화수" 없을 수 있음 → 미언급** |

→ **Daum만 유독 "모름"으로 나오는 건 설화수가 다음에 없어서가 아니라, Daum은 "검색 스니펫"을 재고 그 스니펫이 경쟁사 질문 결과라 브랜드가 안 담긴 것.** 사과-오렌지 비교.

## 2. 파생 오류들 (위 3층에서 번짐)

### 🔴 A. 경쟁벤치 "본인 미발견" ↔ GEO SoV 79% 모순
- **GEO SoV**(index.ts:149-156) = `언급응답수 / 성공응답수`. 답변 전체 어디든 "설화수" 있으면 카운트 → 글로벌 LLM이 되뇌어서 79%.
- **경쟁벤치**(competitor-extract.ts) = **번호목록 줄에만** 브랜드 있어야 발견. 경쟁사 나열 답변의 번호목록엔 경쟁사만 → 설화수 미발견.
- 두 지표가 **다른 텍스트 영역을 봐서** 모순. 상호검증 없음. + `cleanBrandName` 과도 절단(`:22-30,86`)이 매칭 더 악화.
- ⚠️ 추가: SoV 계산 자체도 부실 — `estimateShareOfVoice`(utils.ts:135-157)는 "대문자 영어 토큰 수"로 나눠 **한글 브랜드엔 무의미**(설화수는 titleCase에 안 잡힘). 지금 GEO SoV는 이 함수가 아니라 index.ts의 응답비율을 쓰지만, 엔진별 sov 필드엔 이 엉터리 함수가 관여.

### 🔴 B. 인용 출처 오염 (marginalrevolution·pcworld·businessinsider)
- 글로벌 엔진: `extractCitedSources(text)`(utils.ts:85-102) = 답변 본문의 **URL을 정규식으로 무조건 긁음**(global-adapters.ts:99).
- LLM이 환각/예시로 뱉은 무관 URL이 그대로 "인용 출처"로 집계. 도메인 관련성·화이트리스트 검증 0.
- perplexity는 실제 citation(provider metadata)이 있는데 그걸 안 쓰고 본문 URL만 씀.

### 🟡 C. "28개 엔진" vs "7개"
- metrics는 **응답 단위(28=7×4, 중복)**로 저장(index.ts:119-120).
- 결과 본문은 `new Set()`로 dedup→7 표시(정상, audit-result.tsx:933-953).
- **OG 이미지만 dedup 안 함**(og/audit/[jobId]/route.tsx:66-67,200) → "28개 엔진" 헤드라인.

### 🟡 D. 마크다운 `**` raw 노출
- excerpt = LLM 마크다운 원문(runner.ts:149).
- 렌더 3곳 모두 파서 없이 JSX 직접 출력(truth-mirror.tsx:262, audit-result.tsx:2265·1874). `whitespace-pre-line`은 줄바꿈만 보존, 마크다운 해석 안 함.

## 3. 수정 방향 (우선순위 — 신뢰도 영향순)

### P0 — 측정 정확도 (신뢰 붕괴 방지)
1. **프롬프트 재설계**(1층): both 모드에 **브랜드 자체형을 반드시 포함**(추천/장단점/비교). 경쟁사형과 브랜드형 믹스. → runner.ts:73-76
2. **입력 브랜드명 한글화**(2층): 도메인만 입력 시에도 브랜드 한/영 변형 확보. inferBrandName 개선 or 진입 폼에 브랜드명 유도. brandVariants 실제 전달. → runner.ts:34-42,84
3. **Daum 판정 정합**(3층): Daum은 "검색 스니펫에 브랜드 있냐"가 아니라 **"브랜드로 검색 시 결과가 있냐/브랜드 관련 문서가 잡히냐"**로 판정하거나, 검색결과→LLM 합성 추가. 최소한 "LLM 서술 엔진"과 "검색 스니펫 엔진"을 **다른 지표로 표기**(사과-오렌지 명시). → korean-adapters.ts
4. **두 SoV 지표 정합**(A): 경쟁벤치 brandFound를 번호목록 외 전체 텍스트로 확장, 또는 두 지표 정의 일치. GEO SoV 정의를 UI에 명확히("응답 언급률"). → competitor-extract.ts

### P1 — 표시 신뢰
5. **출처 오염 필터**(B): perplexity 등 provider citation 우선, 본문 URL은 도메인 관련성/화이트리스트 필터. → utils.ts:85-102, global-adapters.ts
6. **마크다운 렌더**(D): ReactMarkdown 도입 or 마크다운 토큰 스트립. → truth-mirror·audit-result
7. **28/7 정합**(C): OG route dedup. → og/route.tsx

### 재측정 상시화 (수정과 별개, 테스트 편의)
- rate-limit(이메일+도메인 24h)에 어드민 우회 로직 존재(route.ts:60-69). 나현덕님 이메일 화이트리스트 등록 or dev 우회. 상세는 별도.

## 4. 핵심 결론 (나현덕님 질문 답)
- **"어떤 식으로 AI에 질문하나?"** → 도메인→브랜드명 추정 후 "경쟁사 알려줘"류 4개 프롬프트를 7엔진에 던짐. **문제=브랜드 자체를 안 묻고(both 모드), 브랜드명이 영문뿐이며, 엔진마다 텍스트 성격이 달라 같은 잣대로 못 잼.**
- **"설화수가 다음에서 안 뜰 리 없다"** → 맞음. 다음이 설화수를 모르는 게 아니라, **다음에 "설화수 경쟁사"를 검색한 스니펫에 설화수 문자열이 없어서 미언급으로 오판**. 측정 버그이지 실제 노출 부재 아님.
- **전반적으로** → 진단 "결과값이 이상한" 건 데이터가 아니라 **측정 설계**의 문제. 위 P0 4건이 신뢰의 핵심.
