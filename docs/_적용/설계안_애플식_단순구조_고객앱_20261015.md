# 설계안 — 애플처럼 쉬운 고객 앱 (모든 기능을 흡수하되 화면은 4개) (2026-10-15)

> 상태: **설계안(코드 없음). 배포된 제품의 구조 재설계라 대표 승인 전에는 코드를 만들지 않는다.**
> 기준 절차: UI/UX 품질 스킬(설계안 8층 · 완성 기준 · 판정 3문). 근거: 애플 HIG·토스·NN/g·Atlassian 1차 출처 규칙(스킬 `reference/criteria.md`, `b2b.md`).
> 경쟁사 화면 근거: 실계정 화면 기록(Findable 37화면 + 경쟁사 5곳 약 100화면, 2026-08-14~21) + 이번 세션 화면 재확인. 경쟁사 성과 수치는 자사 주장.
> 우리가 만든 현재 화면은 "잘된 예"로 쓰지 않는다. 아래 원칙은 전부 1차 출처 규칙과 경쟁사 실화면에서 가져왔다.

## 1. 질문에 대한 답

**"추천한 기능 전부를 단순하게 반영하기 어렵나?" → 어렵지 않다. 단, 기능 하나당 화면 하나로 만들면 불가능하고, 기능을 "엔진·카드·알림"으로 흡수하면 가능하다.**
15개 넘는 기능을 고객이 보는 **큰 화면 4개 + 필요할 때 열리는 흐름 3개**로 정리했다(아래 3절). 화면에 직접 나오는 기능은 일부이고, 나머지는 사용자가 존재를 몰라도 알아서 돌아가는 뒷단이다(애플의 "그냥 된다").

## 2. 경쟁사 화면을 뜯어본 결과

### 2-1. 메뉴 수와 평가 (실화면 기준)

| 제품 | 사이드 메뉴 | 화면 구조 | 평가·관찰 |
|---|---|---|---|
| **Peec** | **5개**(Overview·Prompts·Sources·Models·Settings) | 결과: 엔진 드롭다운 + 표 한 장(브랜드·가시성·감성·위치), 탭 4개 | 후기에서 "UI가 가장 깔끔"로 일관. **약점: 무엇을 고칠지(액션)가 없음** |
| Profound | 약 10개(Analytics 5 · Action 4 · Reports) + 상단 탭 5 + 필터 5 | 큰 점수 + 변화 + 순위표를 나란히, 주기 비교 | 데이터 깊이는 최고. G2 후기 "dashboard is confusing, needs better onboarding" |
| Otterly | 사이드 8 + 필터 4(기간·태그·엔진·국가) | 인용 화면: Top Winners/Losers 빈 상자 + 7열 표. 체험 배너·데모 예약 카드가 상시 | 단순함을 의도했으나 빈 상태("No data")와 데이터가 공존하는 버그, 체험 압박 UI |
| Scrunch | 사이드 약 13개(관찰·이해·설정 그룹 + 하위 4) | 시작 화면이 **1분 45초 영상 시청 → "시청 완료"를 눌러야 다음 단계** + 5단계 체크리스트 | 기능은 많으나 입구가 무겁다. 영상 강제는 실패 판정(기존 N-46) |
| AthenaHQ | 단일 워크스페이스 + Action Center | **GEO Score 한 개를 hero**로 임원 보고 단순화, 처방 5종 + 초안 자동 생성 | "모니터링만 하면 뭘 고칠지 모른다"는 카테고리 공통 불만을 정면 해결 |
| HubSpot AEO | 무료 1회 진단 → 유료 | **점수 산식 공개** + 점수 의미 자연어 해석 + 5차원 | 신뢰는 투명성에서 나온다 |
| haloX(국내) | 그룹형 사이드바 | 온보딩 모달 4단계, 전략맵(SEO 키워드 클러스터) | 온보딩 모달은 공통 표준, 키워드 SEO 축은 우리와 다름 |

우리 현재 구조 [관찰: 코드·화면 맵 2026-08-21]: 고객 사이드 메뉴 **9~12개**(대시보드·브랜드·추적 질문·측정 이력·출처·경쟁사 비교·지금 할 일·알림·요금제 + 사이트 점검·인사이트·콘텐츠 성과). 경쟁사 중 가장 쓰기 쉽다는 평가를 받는 곳은 **가장 메뉴가 적은 곳(Peec 5개)**이고, 가장 무겁다는 평가는 메뉴가 많은 곳이다.

### 2-2. 베낄 것
| 패턴 | 출처 | 우리 적용 |
|---|---|---|
| 큰 점수 하나 + 변화 + 순위를 **한 화면에 나란히** | Profound·Peec·Athena | "오늘" 화면의 주인공 |
| **점수의 의미를 문장으로** + 산식 공개 | HubSpot | 모든 숫자 옆 한 줄 해석 |
| 처방 + 초안까지 자동 | Athena Action Center, Profound Actions | "먼저 할 일 1개" |
| 주간 요약을 **밖으로 밀어주기**(Slack·메일) | Profound | 주 1회 묶음 알림 |
| 온보딩 가이드는 **필요한 순간에 맥락으로** | Profound·haloX(투어) | 실데이터 기반 안내(데모 데이터 금지) |
| 엔진별 압축 표시(아이콘+순위 한 줄) | Peec·Profound·haloX | 질문 목록 |

### 2-3. 베끼면 안 되는 것 (반면교사)
| 패턴 | 출처 | 이유 |
|---|---|---|
| 영상 강제 시청 후 시작 | Scrunch | 입구가 무겁고 이탈을 부른다 |
| 데모 데이터로 투어 | Otterly·Profound | 내 데이터가 아닌 것으로 설명하면 신뢰가 깨진다 |
| 순환 카피로 가짜 진행감 | Profound·Otterly | 정직성 위반 |
| 빈 화면 무표시 로딩, 영구 스켈레톤 | Peec·Otterly | 오류로 오해 |
| 일부를 흐리게 가린 유료벽(blur) | Peec | 가치를 보기 전에 돈을 요구 |
| 빈 상자 + 데이터 공존("No data" 옆에 데이터) | Otterly | 못 믿게 된다 |
| 브랜드명 텍스트만 입력해 자동 생성 | Otterly | 다른 업종으로 오분류(실제 사고) → URL 기반 우선, 텍스트 단독은 확인 단계 |
| 메뉴 10개 이상 | Profound·Scrunch | 길을 잃는다 |

## 3. 설계: 화면 4개 + 흐름 3개

### 3-1. 한 줄 철학
**"고객이 매일 묻는 건 하나다: 지금 AI 답변에 우리가 나오나, 그리고 오늘 뭘 하면 되나."** 그 한 질문에 맞춰 구조를 잡는다.

### 3-2. 사이드 메뉴 (4개)

| 메뉴 | 한 문장 역할 | 들어가는 기능 |
|---|---|---|
| **오늘** | 지금 상태와 오늘 할 일 1개 | F0 진단서, G6 오해 교정, G10 이름 충돌·네이버, G11 먼저 할 일 |
| **내 브랜드** | AI에게 우리를 어떻게 알려 줄지 | G1 팩트시트, G8 사이트 상태, 추적 질문, G3 내 글, G4 등록 체크 |
| **성과** | 고친 뒤 무엇이 달라졌나(그리고 매출) | G7 변화 기록, G12 AI 유입, 경쟁사 비교, 인용 출처, 이력 |
| **설정** | 알림·연동·구독 | 주간 알림, GA4·서치콘솔 연동, (고급) 봇 로그 G9, 대행사 모드 G14, 결제 |

→ 지금의 9~12개 메뉴를 **4개로**. 경쟁사 중 가장 단순한 Peec(5개)보다 적다. 기존 화면은 삭제가 아니라 위 4개 안으로 들어간다.

### 3-3. 흐름 3개 (메뉴가 아니라 "할 일을 누르면 열리는 전체 화면")
1. **고치기 흐름**: 할 일 카드 → 원인 한 줄 → 초안·코드 조각 미리보기 → [승인] → 적용 안내 → **자동 재검사** → 성과에 기록. (G2·G3·G15·G6이 이 흐름 안에서 움직임)
2. **등록 흐름**: 구글·네이버·빙 등록을 한 번에 따라 하기 (G4)
3. **처음 시작 흐름**: 도메인 입력 1개 → 자동 진단 → 바로 "오늘" 화면

### 3-4. "오늘" 화면 — 스케치

```
┌──────────────────────────────────────────────────────────────┐
│ ○○ 브랜드                                    [알림 1] [설정]  │
│                                                              │
│  지금 AI에게 "○○ 추천해줘"라고 물으면                          │
│  ┌───────────────────────────────────────────┐              │
│  │  12번 중 3번 나와요      25%   ▲ 3%p (지난주) │  ← 주인공   │
│  │  "아직 낮은 편이에요. 네이버에서는 더 나와요."    │  ← 판정 문장 │
│  └───────────────────────────────────────────┘              │
│                                                              │
│  오늘 먼저 할 일 1개                                          │
│  ┌───────────────────────────────────────────┐              │
│  │ 같은 이름의 호텔과 헷갈려요                      │              │
│  │ 홈페이지 첫 줄에 "분야"를 붙이면 구분됩니다      │              │
│  │ [초안 보기]                       약 10분      │              │
│  └───────────────────────────────────────────┘              │
│                                                              │
│  ▸ 왜 낮은지 더 보기 (4)        ▸ 나머지 할 일 (3)            │
│  ▸ 놓친 기회(추정) ₩…                                          │
└──────────────────────────────────────────────────────────────┘
```

### 3-5. "내 브랜드" — 아이폰 설정 앱 방식 (행 목록 → 상세)

```
  브랜드 정보      이름·설명·공식 링크            불일치 2건 ›
  사이트 상태      읽힘·색인·AI 접근              이상 없음 ›
  추적 질문        12개                           ›
  내 글            발행 6 · 초안 2                 ›
  등록 현황        구글 ✓ 네이버 ✓ 빙 미등록       ›
```
→ 한 화면에 행 5개, 각 행은 **상태 한 줄**. 누르면 상세. 탭 대신 목록(탭은 IA 실패를 덮는 데 자주 쓰인다 — NN/g 계열 원칙).

### 3-6. "성과" — 시간축 한 장
- 맨 위 한 문장: "지난 4주 동안 ○○을 AI가 말한 비율이 18%→25%"
- 큰 숫자 3개: **언급 비율 · AI 유입(최소 N명, 하한 추정) · 놓친 기회(추정)**
- 아래 타임라인: **한 일 → 변화**("10/15 홈페이지 첫 줄 수정 → 이후 2주 +4%p, 비교 질문은 +1%p")
- 접힌 카드: 경쟁사 비교 · 인용 출처 · 측정 이력

### 3-7. 기능 15개 이상이 어디에 사는가

| 기능 | 고객이 보는 형태 | 위치 |
|---|---|---|
| F0 "0% 진단서" | "왜 낮은지" 카드 4장(접힘) | 오늘 |
| G6 오해 교정 | 진단서 카드 + 고치기 흐름 | 오늘 → 흐름 |
| G10 이름 충돌·네이버 | 진단서 카드 | 오늘 |
| G11 먼저 할 일 | **주인공 카드 1개** | 오늘 |
| G1 팩트시트 | "브랜드 정보" 행 | 내 브랜드 |
| G8 사이트 가드 | "사이트 상태" 행 + 주 1회 알림 | 내 브랜드 + 알림 |
| G3 콘텐츠 + G15 규칙 | "내 글" 행 + 고치기 흐름 | 내 브랜드 |
| G4 등록 마법사 | "등록 현황" 행 + 흐름 | 내 브랜드 |
| G7 증명 + G12 AI 유입 | 성과 타임라인·큰 숫자 | 성과 |
| 경쟁사 비교·출처·이력 | 접힌 카드 | 성과 |
| G9 봇 방문 기록 | 고급 연동 | 설정(고급) |
| G13 수요 추정 | 질문 추가할 때 보조 정보 | 내 브랜드(추적 질문) |
| G14 대행사 모드 | 브랜드 전환·리포트 | 설정 |
| G2 적용 연동 | 고치기 흐름의 "적용" 단계 | 흐름 |
| G5 외부 출처 | 할 일 카드의 한 종류(체크리스트) | 오늘 → 흐름 |

→ **새로 생기는 메뉴 0개.** 모든 기능이 4개 메뉴와 3개 흐름 안에 들어간다.

## 4. 매출 관점에서의 설계

고객의 최종 목표는 "AI 답변에 더 나오고 → 방문이 늘고 → 매출이 늘어나는 것"이다. 화면이 이 사슬을 끊지 않게 한다.

| 사슬 | 화면에서 | 근거·주의 |
|---|---|---|
| ① 나오나 | 오늘 hero(언급 비율 + 판정 문장) | 이름 있는 질문과 없는 질문을 **합치지 않음** |
| ② 고칠 것 | 먼저 할 일 1개 | 병목 하나. 처방 수십 개 금지 |
| ③ 방문 | 성과의 "AI 유입 최소 N명" | **하한 추정**. 앱·웹뷰 소실, AI 개요 클릭은 오가닉으로 잡히는 한계를 화면에 표기 |
| ④ 매출 | "놓친 기회(추정)" 한 줄 | 대표 확정 공식(연매출 × 7% × (1 − 정확 노출률))을 쓰되 **추정·기준 공개**. 연매출 입력은 **선택·구간 선택**(민감해서 3초 안에 답하기 어려운 질문) |
| ⑤ 증명 | 타임라인 "한 일 → 변화" | 대조 없이 인과 단정 금지, 불확실성 표기 |

⚠️ 매출 증대를 **보장하는 문구는 어디에도 쓰지 않는다.**

## 5. 애플처럼 쉬운 이유 — 원칙을 규칙으로 (1차 출처 규칙)

| 원칙(출처) | 우리 규칙 |
|---|---|
| 한 화면 한 목적(토스 One Thing per One Page) | 화면마다 역할 한 문장. 못 쓰면 합친다 |
| 가치 먼저, 요구는 나중(토스 Value First, Cost Later) | 가입 전 무료 진단 결과, 로그인 후 첫 화면에 숫자와 다음 행동 |
| 컨트롤 수를 제한(HIG Prioritizing content) | "오늘" 첫 화면 컨트롤 ≤6, 주인공 1개 |
| 부차는 접기(HIG Progressive Disclosure) | 진단서 4장·나머지 할 일·고급 연동은 접힘 |
| 주인공은 실제 사용자 데이터(HIG Deference) | 데모·예시 금지, 빈 상태에서도 내 도메인 기준 안내 |
| 3초 안에 답할 질문만(토스 Easy to Answer) | 온보딩 질문 **도메인 1개**. 시장·별칭·경쟁사는 자동 감지 후 나중에 수정 |
| 기본값 미리 채움(HIG Entering data) | 업종·시장·경쟁사 후보는 기본값(경쟁사는 기본 미선택 — 오분류 방지) |

## 6. 설계안 8층 표

| 층 | 할 것 | 근거 | 🔴 안 할 것 |
|---|---|---|---|
| ①IA | 사이드 메뉴 4개, 흐름 3개. 기존 9~12개 화면은 4개 안으로 이전(삭제 아님) | 최소 메뉴가 가장 쉽다는 경쟁사 평가(Peec 5개), HIG 컨트롤 제한 | **새 메뉴 추가 금지**, 탭으로 IA 문제 덮기 금지, 기능마다 화면 만들기 금지 |
| ②플로우 | 시작: 도메인 1개 → 자동 진단 → 오늘. 고치기: 카드→미리보기→승인→재검사→성과 | 토스 Value First, 적용 후 재검사 원칙 | 영상 강제, 투어 오버레이, 데모 데이터, 설정 5단계 강제 |
| ③레이아웃 | 오늘: 주인공 1(점수) + 할 일 1(카드) + 접힘. 내 브랜드: 행 목록. 성과: 한 문장+숫자 3+타임라인 | NN/g 대시보드(핵심 정보 빨리 전달), Atlassian 위계 | 동일 크기 카드 격자(주인공 없음), 큰 숫자 3개 초과 |
| ④인터랙션 | 승인 한 번, 되돌리기, 자동 저장 | 닐슨 통제와 자유 | 확인 대화상자 남발, 필수 튜토리얼 |
| ⑤비주얼 | 한 가지 강조색, 큰 숫자, 여백으로 관계 표현 | Atlassian 근접·위계·리듬 | 장식 그래프, 같은 간격 반복 |
| ⑥카피 | 고객 말: "12번 중 3번 나와요". 지표 이름·내부 용어 금지 | 닐슨 기억보다 인식 | "SoV", "엔티티", "인용률" 같은 용어를 첫 화면에 |
| ⑦상태 정직성 | 0과 "못 잰 것"을 구분, 측정 조건 표기(웹검색·질문 유형·반복) | 우리 오진 사례 | 못 잰 것을 0으로 표시, 가짜 진행 카피 |
| ⑧기본기 | 모바일 390·PC 1440 둘 다, 접근성 axe | 스킬 완료 기준 | 한쪽 뷰포트만 확인 |

### 4가지 상태 (빈/로딩/오류/부분실패)
| 상태 | 오늘 화면에서 |
|---|---|
| 빈(측정 전) | "○○의 첫 진단을 하고 있어요" + 도메인 기준 안내, 샘플 숫자 금지 |
| 로딩 | 정직한 진행 표시(진행률 없으면 "측정 중, 보통 N분" 범위만), 순환 카피 금지 |
| 오류 | 원인 한 줄 + [다시 시도] + 데이터가 남아 있으면 이전 결과 유지 |
| 부분 실패 | "엔진 6개 중 5개만 측정됨" 표기, 평균에서 제외 이유 설명 |

## 7. 완성 기준 (B2B·대시보드 유형)

| 기준 | 목표 |
|---|---|
| 첫 화면에서 가치가 보이나 | 예 — 숫자 + 판정 문장 + 다음 행동이 한 화면 |
| 주인공 | 1개(언급 비율), 나머지는 접힘 |
| 첫 화면 컨트롤 | ≤6 |
| 답 못 할 질문 | 0개(온보딩 도메인 1개, 나머지 자동/선택) |
| 첫 화면 안 CTA | 있음("초안 보기") |
| 주인공 = 실제 데이터 | 예 |
| 역할별 화면 | 소유자·멤버·보기 전용·대행사 4종 설계 |
| 빈 워크스페이스 | 설계 |
| 판정 3문 | ① 어떤 질문에 답하나: "우리가 AI 답변에 나오나, 오늘 뭘 하나" ② 보자마자 아나: 숫자 + "낮은 편이에요" ③ 다음 행동: 할 일 카드 → 전부 "예" |
| 측정 | 만든 뒤 `measure`·`align`·`squint`·`a11y`로 모바일·PC 두 장 전체 캡처를 눈으로 확인 |

## 8. 이 설계로도 안 고쳐지는 것 3가지 (솔직하게)

1. **효과 지연**: 구글·AI가 다시 읽는 데 수 주가 걸린다. 화면이 아무리 쉬워도 "오늘 고치면 내일 오른다"를 약속할 수 없다. → 성과 화면이 "다음 재측정 예정일"을 보여 줘야 한다.
2. **우리 고객이 실제로 이 구조를 쉽게 느끼는지는 미검증**: 이 설계는 경쟁사 실화면·1차 원칙·우리 사건에서 나왔다. **고객 5~10곳이 "오늘" 화면을 보고 5초 안에 뜻을 말하는지** 테스트 전에는 확정하지 않는다.
3. **측정 신뢰 문제는 화면으로 못 고친다**: 웹검색 꺼진 측정, 이름 없는 질문 미측정은 **측정 코드**의 일이라 동결 해제 후에야 가능하다. 그 전까지 "오늘" 숫자 옆에 측정 조건을 정직하게 표기하는 것이 한계다.

## 9. 만드는 순서와 승인

| 순서 | 만들 것 | 승인 시점 |
|---|---|---|
| 0 | **시안(클릭 가능한 목업) 3장**: 오늘·내 브랜드·성과 → 고객 5~10곳에 5초 테스트 | 이 설계안 승인 후 |
| 1 | "오늘" 화면 + F0 진단서 1차(측정 조건·이름 충돌·색인 카드) | 시안 테스트 통과 후 |
| 2 | 사이드 메뉴 4개로 통합(기존 화면 이전), 온보딩 도메인 1개로 축소 | 1단계 후 |
| 3 | "내 브랜드"(G1 포함), "성과"(G7·G12), 알림 | 순차 |
| 4 | 고치기 흐름 + G4 등록 흐름 | 순차 |

## 10. 대표님 확인이 필요한 것
1. **메뉴 4개(오늘·내 브랜드·성과·설정)** 구조로 가도 되는지
2. **시안(목업)부터 만들어 고객 5~10곳에 보여 주는 것**을 1단계로 해도 되는지
3. "놓친 기회(추정 ₩)"를 첫 화면에 둘지, 성과 화면에만 둘지(민감한 숫자라 선택)
