# UX-S1 시안 — 측정 전 확인 카드 (견적 → 승인 → 상한 고지)

> 2026-10-20 S4 작성. **문서 시안이다. 앱·웹 화면 코드는 만들지 않았고, 대표 승인(U-2) 전에는 만들지 않는다.**
> 근거: `O4_개발기획서_최종_20261020.md` 3-6⑥·4-3, `U_온보딩_UIUX_감사와_개선안_20261020.md` U6·3-2 E·승인 U-2, 레포 코드 읽기(아래 출처 표).
> 표기: [확인] 코드·문서에서 확인 / [확인 필요] 못 정함·못 확인 / ☐ 대표 결정.

쉬운 말 풀이: **측정 전 확인 카드** = 측정 버튼을 누르기 전에 「몇 번 묻고, 얼마나 걸리고, 오늘 몇 번 더 할 수 있고, 한도는 얼마인지」를 한 장으로 보여 주는 안내. **견적→승인→상한** = ① 이번에 얼마나 돌리는지 알려 주고 ② 사용자가 확인하고 시작하고 ③ 한도에 닿으면 멈추고 알려 주는 3단.

## 1. 한 줄 결론

**카드는 「횟수·시간·남은 횟수·플랜 한도·못 재는 경우」만 보여 준다(U-2의 b안). 원 환산(돈 금액)은 대표가 정하기 전까지 화면에 쓰지 않는다. 원가 숫자들은 코드 주석의 설계 추정이라 하나의 숫자로 합치지 않고, 어느 것도 실시간 청구액이 아니다.**

## 2. 화면 와이어프레임 (텍스트 — 새 컴포넌트 없이 6단계 확인 화면의 카드로 얹는 안)

```
┌ 측정할 준비가 됐어요 ─────────────────────────────────────┐
│ 브랜드 {브랜드}  ·  시장 {시장}  ·  다른 이름 {a}개  ·  경쟁사 {b}개 │
│                                                              │
│ 이번 측정 (시작 전 확인)                                       │
│   묻는 횟수      질문 {n}개 × AI {m}곳 = {n×m}번                 │
│   예상 시간      {시간 문구 — ☐ 대표 결정, 4절}                  │
│   오늘 남은 횟수  {플랜 규칙에서 계산 — 5절}                      │
│   플랜 한도      질문 {pl}개 · 브랜드 {bl}개 · 경쟁사 {cl}개      │
│                  자동 재측정 {주기 또는 "수동만"}                │
│   추가 청구      {☐ 사실 확인 후 문구 — 6절}                     │
│   못 재는 경우   AI가 답하지 않거나 오류가 나면 그 칸은 비율 계산에서 │
│                  빼고 이유를 보여드려요 (0으로 세지 않아요)        │
│                                                              │
│   [설정 저장하고 측정 시작]        [나중에]                     │
└──────────────────────────────────────────────────────────────┘
```

- `{n}` = 저장된 질문 수, `{m}` = **그 시점의 활성 엔진 수를 실행 시 계산**한다(숫자를 화면 코드에 박지 않는다 — 「AI 7곳 vs 6곳」 불일치 방지, 사실표 FACT-5).
- `{n×m}` 은 시도 칸 수이며 **엔진 단위 수**다. 응답 행 수와 섞지 않는다(기존 측정 범위 주석: 행 수를 세면 분모가 부풀려짐) [확인: `packages/audit/measurement-coverage.ts` 주석, K0 인용].
- 「못 재는 경우」 문장은 기존 분류 규칙과 일치한다: 측정 실패·판정 보류는 셀 수는 보여 주되 비율 분모에서 뺀다 [확인: `packages/audit/answer-buckets.ts` 분모 규칙].

## 3. 견적 → 승인 → 상한 흐름

| 단 | 보여 주는 것 | 사용자 행동 | 코드 근거 / 상태 |
|---|---|---|---|
| ① 견적 | 위 카드의 「묻는 횟수·예상 시간」 | 읽는다 | 횟수는 저장 질문 수×활성 엔진 수. 시간은 4절 |
| ② 승인 | 「설정 저장하고 측정 시작」 버튼 = 사용자의 확인 | 누르면 시작 | 기존 시작 버튼(`features/brand/start-tracking-button.tsx`)과 같은 자리 [U 문서 3-2 E] |
| ③ 상한 | 「오늘 남은 횟수」·「플랜 한도」, 한도에 닿으면 **시작 전에** 이유를 알려 줌 | 닿으면 멈춤 | 지금은 한도 안내가 **실패 뒤 오류**로만 나온다 [확인: U 문서 U6, `brandErrors.freeDailyLimit`] |

대행사용 「견적서 PDF·승인자 지정·월 상한」 3단 전체는 **후속**(U 문서 후보표: 대표가 요금 구조·원가 노출 방침을 정한 뒤, 8~12일 규모). 이 시안은 그중 「측정 전 고지」만이다.

## 4. 예상 시간 — 두 값이 충돌한다 (☐ 대표 결정)

| 위치 | 말하는 값 | 상태 |
|---|---|---|
| 관리자 측정 화면 문구 | 질문 20개를 5~6개씩 이어 측정해 **15~20분** [확인: `apps/app/app/(authenticated)/admin/measure/measure-console.tsx`] | 영업용 20문항 기준 |
| 가입 후 측정 대기 화면·무료 안내 | **1~3분** [확인: `measuring-view.stories.tsx` 주석, `history-auto-refresh.tsx` 주석, `ko.json` 무료 진단 푸터 「약 1~3분」] | 질문 수가 적을 때의 값으로 추정 [확인 필요] |

카드에는 **한 숫자를 박지 않는다.** 선택지:
- (가) 「질문 {n}개 기준 약 {x}분」 — 질문 수별 시간을 실측으로 정한 뒤(☐ 실측 필요)
- (나) 「질문이 많으면 15~20분까지 걸릴 수 있어요. 닫아도 계속돼요」 — 범위와 계속 진행 여부만(실측 없이 가능, **계속 진행되는지 [확인 필요]**)
- 권고: (나)로 시작하고 (가)는 실측 뒤. 위 두 곳의 「1~3분」 문구도 같은 사실로 맞춰야 한다(FACT-6).

## 5. 오늘 남은 횟수·플랜 한도 — 읽어 온 규칙

| 플랜 | 질문 한도 | 브랜드 | 경쟁사 | 자동 재측정 |
|---|---:|---:|---:|---|
| free | 5 | 1 | 3 | 수동만 |
| starter | 30 | 3 | 5 | 168시간(주간) |
| growth | 150 | 5 | 10 | 24시간 |
| scale | 500 | 제한 없음 | 20 | 24시간 |
| enterprise | 2000 | 제한 없음 | 20 | 24시간 |

[확인: `packages/auth/plan.ts` `PLAN_CAPABILITIES`] — 화면은 **이 표를 읽어서** 쓴다(숫자를 복사해 박지 않는다).

| 남은 횟수 규칙 | 상태 |
|---|---|
| 무료: **같은 도메인 24시간 1회**. 진행 중이면 중복 시작 불가 | [확인: `apps/app/app/actions/brand/start-tracking.ts` 24시간 조회, `ko.json` `freeDailyLimit`] |
| 유료(starter 이상): 위 24시간 제한은 적용되지 않음 | [확인: 같은 함수 `hasPlan(plan,"starter")` 분기]. **다른 상한(재시도 차단·전역 일일 예산 등)이 있어 「무제한」으로 표시하면 안 된다** [확인 필요: 유료에 표시할 「남은 횟수」 기준] |
| 이번 측정이 질문 한도를 넘는 경우 | 시작 전에 「질문 {pl}개까지만 측정돼요」를 먼저 알린다(☐ 문구) |

## 6. 추가 청구 — 문구를 쓸 수 없다 (☐ 사실 확인 후)

U 문서 초안은 「정액 플랜 안이면 없음」이었으나 **[확인 필요]**: 측정이 정액 플랜 안에서 추가 요금이 없는지, 무료 플랜 첫 측정의 처리(O4 승인 #8)가 어떤지 대표 확인 전에는 **문구를 쓰지 않는다**. 카드의 「추가 청구」 줄은 확인 전까지 **표시하지 않거나** 「플랜 안내 보기」 링크만 둔다. 가격·할인·결제 유도 문구는 쓰지 않는다.

## 7. 원가 숫자 — 시안에는 원 환산을 쓰지 않는다. 아래는 담당자 참고용

> **모두 코드 주석의 설계 추정이며 실시간 청구액이 아니다. 하나의 숫자로 합치지 않는다. 측정 방식과 대상이 서로 달라 값이 다르다.**

| 숫자 | 무엇의 추정인가 | 위치 [확인] | 실측 여부 |
|---|---|---|---|
| 777원 | 무료 진단 1건(질문 상한 8개) v2 환산 평균(14일 완료 측정 156건 기반 + 보정 가정) | `apps/web/lib/free-audit-budget.ts` 주석 | 일부 가정 포함(웹검색 횟수 등 [확인 필요] 표기됨) |
| 1,000원 | 위 값을 아직 원가에 안 잡힌 호출분을 감안해 올린 보수 평균(코드 상수) | 같은 파일 `FREE_AUDIT_AVG_COST_KRW` | 보수 올림, 실측 아님 |
| 1,400원 | 엔진 세트 `api-search-v1` 일 때의 보수 평균 | 같은 파일 `…_API_SEARCH_KRW` | 시험 데이터 추정, 켠 뒤 재측정 필요 |
| 1,800원 | 관리자 측정 1건(질문 20개×엔진 6곳) | `measure-console.tsx` `COST_KRW` | 8문항 실측 비용에서 환산 |
| 2,800원 | 위의 상한 추정(설계안 기준) | `measure-console.tsx` `COST_KRW_MAX_ESTIMATE` | 설계안 추정 |
| 약 621원 | 영업 발굴 화면 확인 문구에 「운영 실측」으로 적힌 1회 평균 | `ko.json` `app.salesDiscover.measureConfirm` | v1 기록 원가(약 620.6원, `free-audit-budget.ts` 주석)와 같은 숫자로 보임 [추정, 확인 필요] — 「운영 실측」 표기가 지금도 맞는지 사실표 FACT-7 |

- 관리자 화면(`measure-console.tsx`)은 이미 「약 N원」을 쓴다. 이는 **내부 운영자용**이며 고객 화면의 원 환산 방침과 별개다(고객 화면 방침 ☐ 대표 결정).
- 고객 카드에 원 환산을 쓰려면 먼저 ① 정액 플랜과의 관계 ② 원가 노출 방침 ③ 어느 숫자를 쓸지를 대표가 정해야 한다(U 문서 승인표 U-2 c안 보류 사유와 같다).

## 8. 문구 (한국어 + 영어 한 줄) — 모두 ☐ 대표 확인 전 초안

| 칸 | 한국어 | English |
|---|---|---|
| 제목 | 측정할 준비가 됐어요 | Ready to measure |
| 묻는 횟수 | 질문 {n}개 × AI {m}곳 = {n×m}번 묻습니다 | {n} questions × {m} AI engines = {n×m} asks |
| 예상 시간 | (4절 결정 후) | (after decision in section 4) |
| 오늘 남은 횟수 | (5절 규칙 후) | (after rule in section 5) |

영어 문구는 **번역 검증을 거치지 않은 초안**이다(영어 코호트 검증 0).

## 9. 「우리가 못 하는 것」 목록 (시연 ⑥에 쓰는 안, 사실만)

| 못 하는 것 | 근거 |
|---|---|
| 처방이 효과를 만들었다고 말하기 — 1주 관찰로는 인과·지속 효과·트래픽·매출을 말하지 않는다 | O4 3-7 판정선 |
| 못 잰 것을 0으로 세지 않기 때문에, 못 잰 칸이 많으면 비교 불가로 표시 | K0 값 상태 4종, O4 3-3 |
| 한국어 외 언어는 측정이 검증되지 않았다 | K0 `PROOF_LANGUAGES` 주석(현재 검증된 언어는 한국어뿐) |
| 모델 버전은 대부분 기록되지 않는다 | K0 `EngineModelInfo` 주석(Gateway 경로에서만) |
| 대상 페이지가 색인됐는지는 저장·자동 확인하지 않는다(사람이 확인해 적음) | O4 12-1 #15⑤, K0 `IndexCheck` |

| MCP로 측정을 시작하거나 쓰는 일 | O4 4-2 (읽기 전용 모드에서 시작 도구 미등록) |
