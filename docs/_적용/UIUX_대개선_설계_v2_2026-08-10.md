## 1. 🧭 IA — 이 화면이 어느 종류인지부터 정한다

### 1-1. Carbon 2종 프레임워크 (a) — **가장 먼저 결정할 것**
📕 [carbondesignsystem.com/data-visualization/dashboards](https://carbondesignsystem.com/data-visualization/dashboards/) (공식 1차)

| 종류 | 목적 |
|---|---|
| **Presentation Dashboard** | KPI 상태·큰그림 → **다음에 어디를 볼지 안내** |
| **Exploration Dashboard** | 검색·정렬·필터·드릴다운 (열린 분석) |

🔴 **한 화면에 두 의도를 섞는 것이 "문서화된 실패 모드"다.**

**→ Findable 결정**:
| 화면 | 종류 | 근거 |
|---|---|---|
| `/` 대시보드 | **Presentation** | 비개발자 마케터가 "지금 괜찮나"를 본다 |
| 무료진단 결과 | **Presentation** (현재 15섹션 = 혼재) | 1회성 aha 가 목적 |
| `/history`·`/compare` | **Exploration** | 여기서만 필터·정렬 |

### 1-2. 레이아웃 = F 패턴 (a)
가장 중요한 것 **좌상단**, 보조는 좌→우 후 위→아래. (NNG 아이트래킹, Carbon 반복 인용)

### 1-3. 3층 내비 (b) — Linear 선례
**사이드바(구조) + 탭(섹션 내 뷰) + 커맨드 팔레트(액션)**.
Linear 는 Cmd+K 를 사이드바와 **경쟁이 아니라 공존**시킨다.
→ 우리는 사이드바만 있다. 팔레트는 **후순위**(사용자 수가 적어 이득 낮음).

### 1-4. 진행형 공개 (b) — 전 소스에서 가장 반복된 IA 원칙
> *"'모든 게 정상인가'에 답할 것만 보이고 상세는 클릭 뒤로"*

## 2. 🎨 비주얼 디자인 — 색 예산이 핵심

### 2-1. 🔴 Stripe 색 예산 (a) — **이 문서에서 가장 중요한 인용**
📕 [925studios 분해](https://www.925studios.co/blog/stripe-dashboard-design-breakdown)

> *"Stripe reserves color **exclusively for status signaling** rather than decoration."*
> *"**When every data point is coloured, colour loses meaning.**"*

팔레트 = **green(성공) / red(실패) / yellow(대기)** 뿐.

**→ Findable 규약**:
- 색은 **상태에만**. 장식 금지.
- 빨강은 **"주의 필요"에만** — *"이건 빨강 카테고리"* 용도 금지
- 🔴 **점수 하락에 빨강 쓰지 않는다** (GSC 선례 + 토스 "부정 감정 그래픽 금지")

✅ 🔬**실측(2026-08-10): 이미 지켜지고 있다 — 새로 할 일 없음.**
   대시보드 빨강 **1건**(`failed` 배지) · 무료진단 **16건 전부 실제 에러**(제출 실패·crew 실패 등).
   **하락·낮은 점수에 빨강을 쓰는 곳은 0건**(v1 1-3 에서 이미 중립 회색으로 교체).
   ⚠️ 이 항목을 "할 일"로 되살리지 말 것 — **없는 문제를 만드는 것**이다.

### 2-2. 타이포 위계 — 색이 아니라 크기·굵기·간격으로 (a)
| 소스 | 규칙 |
|---|---|
| **Stripe** | **6단계 위계**로 색 없이 우선순위. 주지표=최대+최고굵기 / 보조=중간 / 라벨=가장 얇고 작게 |
| **Linear** | weight **400~510 낮은 대역만** — **굵은 글씨 없음**. 위계는 크기·색·간격에서 |
| **Apple HIG** | 타이포 위계로 구조 전달 |

🔴 **한글 주의**: Linear 의 **자간 -0.022em 은 한글에 적용 금지**(한글은 이미 조밀).
📕 [[reference_korean_ux_writing_toss]]: 한글 **줄높이 1.6~1.7** · `tracking-tight` 금지 ·
`word-break: keep-all` · Pretendard.

### 2-3. 깊이·그리드 (b) — Linear
- **1px 헤어라인 + 인셋 섀도. 드롭섀도 없음**
- 🎯 **모든 것이 4px 그리드** — 패딩·마진·아이콘·텍스트 전부 4의 배수
- 액센트 **단 하나**를 기능적 하이라이트로 절제 사용

### 2-4. 차트 스타일 (a)
| 소스 | 규칙 |
|---|---|
| **Stripe** | **모노크롬 스파크라인**(색상 바 아님), 격자선·커스터마이징 없이 **추세만** |
| **Polaris-viz** | **차트 하나는 질문 하나만** 답한다 · 축 라벨은 **데이터 영역 밖** |
| **Atlassian** | 범주형 **최대 5~6색** · 🔴 상태색은 **비색상 신호와 병기**(아이콘/모양/라벨). **색 단독 금지** |
| **Carbon** | 🎯 **다크모드에선 밝은 색이 큰 값** (라이트모드와 **반대**) |

⚠️ 우리는 다크 테마다 → **Carbon 규칙대로 값 순서를 뒤집어야 한다.**

### 2-5. 화이트스페이스 (a)
Carbon 인용(Human Factors International): **화이트스페이스가 이해도를 약 20% 높인다.**

## 3. 🖱 인터랙션 디자인 — v1 에 없던 축

### 3-1. 드릴다운 = **사이드 패널** (b) — Stripe
> 행 클릭 → **사이드 패널**(전체 페이지 이동 아님) — **리스트 맥락 보존**

**→ Findable 적용**: 엔진 카드·프롬프트 성적표 클릭 시 페이지 이동 대신 패널.

### 3-2. 모션 규약 (a+b)
- 🔴 **토스**: **장식 효과·파티클 애니메이션 금지** · 화면당 큰 그래픽 **1개만** · 아이콘 24~40px
- 🔴 **차트 애니메이션 끔**(`isAnimationActive={false}`) — v1 에서 이미 적용, **유지**
- ⚠️ *"진행형 공개가 인지부하 55% 감소"* = **인용 금지**(1차 출처 추적 실패)

### 3-3. 에러 = 3요소 (a) — Stripe + 토스
| 소스 | 규칙 |
|---|---|
| **Stripe** | 에러는 항상 **무엇이 · 왜 · 다음에 뭘** |
| **토스** | 에러는 **"Navigating error"** — 보고가 아니라 **안내**. 해결 경로를 **앞으로** |

✅ 오늘 이미 적용함 — 측정 실패 화면이 *"0점이 아니라 아직 모른다는 뜻"* + 재측정 CTA.

### 3-4. 맥락 없는 절대값 금지 (a) — Stripe
> 모든 지표는 **이전 기간을 주 숫자 아래 작은 텍스트로 병기**. 기간 비교가 **카드 안에 내장**.

🔬 우리 실측: 히어로 3장에 델타·스파크라인 **있음**(v1 1-6 구현) → ✅ 충족.

### 3-5. 표 밀도 (b)
행 높이 **48~52px**(기본) / **36~40px**(파워유저) · 헤더 고정 · 호버 하이라이트 ·
**숫자 우측정렬, 텍스트 좌측정렬**.

## 4. 🚶 유저플로우 — 우리의 가장 큰 구멍

### 4-1. 🔴 빈 상태 (a) — **정답이 이미 나와 있다**
📕 [Pencil & Paper](https://www.pencilandpaper.io/articles/empty-states)

> 정석 = **헤드라인(왜 비었나) + 짧은 보조문 + 주 CTA 1개**
> **깔끔한 텍스트+버튼이 일러스트만 화려하고 모호한 것을 이긴다**
> 🎯 소스들은 **샘플/스타터 콘텐츠 + 명확한 CTA 1개** 조합을 선호 — **택일 아님**
> 🔴 **설명만 있는 빈 상태가 가장 약하다**

**사례**: **Webflow 첫 실행 = 거대한 "Create new site" CTA 하나, 나머지 딤**

🔬 **우리 현재 빈 상태 실측**(라이브 캡처):
```
"내 브랜드는 AI 답변에 얼마나 등장할까요?"   ← 랜딩 카피 재탕
STEP 1 / STEP 2 / STEP 3                     ← 🔴 설명만
[브랜드 등록하고 측정 시작]
파트너로 신청하기                             ← 🔴 우리 사정
Growth로 업그레이드하면 …                     ← 🔴 판매
```
→ **"설명만 있는 빈 상태"= 가장 약한 유형**이고, 절반이 **우리 사정**이다.

**→ v2 설계**: **샘플 리포트(실제 진단 1건) + 단일 CTA**, 파트너·업그레이드는 **아래로**.
   샘플은 **이미 있는 데이터**로 만든다(새 진단 0원).

### 4-2. 나쁜 점수 프레이밍 (a)
📕 HubSpot Website Grader · PageSpeed Insights

- 평균 **60.9/100 (D-)** 를 **공개** → 🎯 **낮은 점수가 정상임을 공개하는 것이 오히려 신뢰를 만든다**
- 🎯 사용자 반응: *"이걸 어떻게 고치는지 더 알고 싶다"* → **점수만으론 부족, 다음 행동이 반드시 붙어야**
- PageSpeed 패턴: **점수 + "Opportunities"(고칠 것)를 점수 바로 옆에 병치**
- (b) **Gap-to-benchmark**: *"42점"* 보다 **"경쟁사 평균 대비 -18점"**

**→ Findable**: *"AI가 당신을 모릅니다"* ❌ → **"경쟁사 A는 3/10 노출, 귀사는 0/10"** ○
   + **"지금 할 수 있는 것 1가지"** 병치.

### 4-3. 🔴 잠긴 유료 기능 — **지금이 다크패턴 경계선**
🔬 실측: `compare` 114줄 · `alerts` 76줄 · `sources` 100줄 = **전부 `LockedSurface` + "준비 중"**
→ **Growth 결제해도 열리는 화면이 사실상 없다.**

📕 NN/g [Deceptive Patterns](https://www.nngroup.com/articles/deceptive-patterns/) (원문 확인) —
설득이 정당하려면 **①정보가 사실 ②사용자가 선택지를 오해하지 않음 ③교환이 공정**.

🔴 **"준비 중"인 기능을 유료 특전처럼 메뉴에 걸어두는 건 ②·③에 걸린다.**
→ **선택 필요**(§6 결정 필요 항목).

### 4-4. 리텐션 = 유료 축은 "시간·비교·알림" (v1 유지, 재확인)
무료가 **핵심 문제를 다 해결**하면 유료 전환이 죽는다(Docker 선례).
⚠️ 과도한 게이팅은 **최대 30% 경쟁사 이탈**. 전환율 현실 **2~5%**.

## 4.5 🔬 B트랙 — 경쟁사 **실제 화면** 리서치 (2026-08-10 신규)

> ⚠️ **비주얼 축은 근거가 가장 빈약하다** — 색 팔레트·타이포·다크모드는 **12개 도구 전부 확인 실패**.
> 로그인 뒤 화면이 공개되지 않아서다. 아래는 **공식 헬프센터·실사용 리뷰로 확인된 것만**.

### 4.5-1. ⭐ 가장 중요한 발견 — **응답 원문 모달 = 2단 패널** (VERIFIED)
📕 [semrush.com/kb/1596](https://www.semrush.com/kb/1596-visibility-overview-report)

Semrush `View full response` 모달이 **유일하게 완전히 문서화된 구현**이다:
| 위치 | 내용 |
|---|---|
| **왼쪽** | 프롬프트 원문 + `Brands mentioned` + AI 응답 전문(**내 브랜드 하이라이트**) · 미언급 시 **`Your brand not mentioned` 태그** |
| **오른쪽** | 출처 목록(**파비콘**), **`You` / `Other` 두 그룹 분리** |
| 헤더 | LLM 종류 · 데이터베이스 · 최종 업데이트 일자 |

🎯 **결론**: 이 카테고리에서 신뢰는 "점수"가 아니라 **점수를 만든 실제 AI 응답을 즉시 열어보게 하는 것**에서 나온다.
🔬 **우리 상태**: 진실거울이 이미 원문을 보여준다 → **개념은 있다.** 없는 것은
   ①**브랜드 하이라이트** ②**출처를 You/Other 로 분리** ③**미언급 태그**.

### 4.5-2. 🔴 **밀도가 이 카테고리의 1위 실패 요인** (VERIFIED, 3개 도구 교차)
| 도구 | 실사용 평가 |
|---|---|
| **Peec** | *"모든 지표를 다 노출해 **노이즈**"* · *"데이터 토끼굴 — 빠른 답 대신 대시보드를 뒤지게 됨"* |
| **Otterly** | 프롬프트·경쟁사 늘면 *"crowded"* · *"**테이블 차트가 너무 많음**"* · 로딩 지연 |
| **Profound** | *"익히는 데 **몇 주**"* · *"**CSM 없이는 압도적**"* · *"용도를 모르는 버튼이 있는 고급차"* |

🎯 **"모든 지표 노출"은 검증된 오답.** → 우리 무료진단 **15섹션**이 정확히 이 위험군이다.

### 5-1. ⭐ C트랙이 바꾼 것 — **A안의 구체 형태가 정해졌다**
A(빈 상태)를 *"샘플 리포트를 넣는다"* 로만 적었는데, C트랙이 **3가지를 더 확정**해줬다:
1. **자기 소멸**(Metabase) — 사용자가 진단 1건을 저장하면 샘플·안내는 **자동 제거**
2. 🔴 **로딩 중엔 빈 상태를 띄우지 않는다**(Raycast) — 「없음」과 「아직 안 옴」을 분리
3. **온보딩 첫 질문을 분기점으로**(June) — *"측정할 브랜드가 있나요?"*

### 5-2. 🔴 지금 쓸 수 없는 것 (표본 부족)
**"업계 N분위" 벤치마크는 금지.** 우리는 조직 1개·측정 소수라 **표본이 없다.**
표본 없이 분위를 표시하면 **숫자 조작**이고, 오늘 고친 *"측정 0건 손실 단언"* 과 같은 잘못이다.
→ 나쁜 점수는 **방향(개선 중/악화 중)** 과 **기회 언어**로만 프레이밍한다.
