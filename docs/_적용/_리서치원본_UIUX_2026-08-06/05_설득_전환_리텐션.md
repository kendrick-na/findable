## 1. 나쁜 소식을 행동으로 바꾸기

### (a) 증거 기반

**HubSpot Website Grader** 📕 [HubSpot](https://blog.hubspot.com/marketing/does-your-website-make-the-grade) · [Outgrow 케이스스터디](https://outgrow.co/blog/hubspot-website-grader-case-study)
- 점수 자체가 심리 장치: **낮은 점수는 개선 시급함을, 높은 점수는 자랑거리를 만들어 양쪽 다 공유를 유도**
- 🎯 사용자들은 낮은 점수를 보고도 **"이걸 어떻게 고치는지 더 알고 싶다"**는 반응
  → **점수만으로는 부족하고 다음 행동(fix)이 반드시 붙어야 참여가 유지된다**
- 실측 벤치마크: 평균 **60.9/100 (D-)**, 성능 항목은 30점 만점에 **18점**
  → 🎯 **낮은 점수가 정상임을 공개하는 것이 오히려 신뢰를 만든다**

**Google PageSpeed Insights** 📕 [Shopify 벤치마킹](https://www.shopify.com/enterprise/blog/website-benchmarking)
- *"잔혹한 벤치마크"* — 특히 모바일에서 대부분 사이트가 낮게 나옴
- 공통 패턴: **0~100 점수 + 색상 코딩 + "Opportunities"(고칠 것)·"Diagnostics"(진단)를 점수 바로 옆에 병치**
  → **점수만 던지지 않고 항상 우선순위가 매겨진 개선 리스트를 함께 준다**
  (업계 표준으로 광범위 문서화, 이번 세션 직접 재검증은 못함)

**NN/g 설득 vs 기만 프레임워크** 📕 [Deceptive Patterns](https://www.nngroup.com/articles/deceptive-patterns/) (**원문 직접 확인**)
설득이 정당하려면: **정보가 사실에 근거** · **사용자가 선택지를 오해하지 않음** · **교환이 공정**
→ 나쁜 점수를 보여줄 때도 **사실 왜곡 없이, 부정적 정보를 숨기지 않는 것**이 경계선

### (b) 관행
**"Gap-to-benchmark" 프레이밍** — 절대점수(*"42점"*)보다 **"경쟁사 평균 대비 -18점"·"상위 20% 대비 격차"**로 보여주는 것이 UX 벤치마킹 업계(Baymard·Maze) 표준
📕 [Baymard UX Benchmark](https://baymard.com/ux-benchmark/case-studies/gap) · [NN/g Product UX Benchmarks](https://www.nngroup.com/articles/product-ux-benchmarks/)
⚠️ Baymard 방법론 페이지는 **유료 구독 뒤 → 직접 검증 못함**

**Actionability(문제+해결책 동시 제시)가 참여를 높인다** — UX 감사 업계에서 폭넓게 반복되나 **정량 A/B 데이터를 원문에서 못 찾음** → (b)/(c) 경계

### 🎯 Findable 적용
- *"AI가 당신 브랜드를 모릅니다"* → **"경쟁사 A는 ChatGPT 답변에 3/10 노출, 귀사는 0/10"**
  = 절대적 실패가 아니라 **상대적 위치**로 제시
- 점수 화면에 반드시 **"지금 할 수 있는 것 1가지"** 병치

## 2. 계산된 점수의 신뢰도

### (a) 증거 기반
**Moz Domain Authority** 📕 [DA 계산 설명](https://scientificcalculatoronline.io/how-does-moz-calculate-domain-authority/) · [학술 비교 논문](https://www.researchgate.net/publication/372089122_Reliability_of_domain_authority_scores_calculated_by_Moz_Semrush_and_Ahrefs)
- 방법론 **비공개(proprietary)**라는 것 자체가 지속적 비판 지점
- 그럼에도 *"40개 변수를 머신러닝으로 계산"* 정도의 설명 + **"이것은 구글 랭킹 요소가 아니다"**는 명시적 디스클레이머로 오해 관리
- 🎯 학술: Moz/Semrush/Ahrefs 세 도구 **상관계수 0.9 이상**
  → **완전히 다른 방법론이어도 서로 검증 가능한 범위에 들어오면 신뢰도가 올라간다**

**신뢰를 무너뜨리는 것** 📕 [Perfasive - Anatomy of a Trusted Metric](https://perfasive.com/blog/the-anatomy-of-a-trusted-metric)
**"공개 평판과 내부 지표가 어긋날 때"**(내부 지표는 좋은데 외부 평점이 1점대) 신뢰가 무너짐 — 실제 업계 사례 보고

### (b) 관행
NPS: 방법론이 매우 단순(단일 문항)해 널리 채택됐으나, **"업종 평균과 비교해야 의미 있다"**는 벤치마크 필요성이 관행 (이번 세션 원문 재확인 못함)

### (c) 미검증
📕 [Forbes - Closing the Data Confidence Gap](https://www.forbes.com/councils/forbesagencycouncil/2026/04/07/closing-the-data-confidence-gap-5-ways-to-regain-trust-in-your-marketing-metrics/)
**신뢰구간·표본 크기 공개가 소비자용 분석 대시보드 신뢰에 미치는 영향은 실증 데이터 못 찾음.** 일반론(마케팅 분석 신뢰 결핍)은 확인했으나 *"공개하면 신뢰가 오른다"*는 **인과 증거는 아님**

### 🎯 Findable 적용
**"몇 개 프롬프트/몇 번 질의로 이 점수를 냈는지"** 최소한의 방법론 노출(전체 알고리즘 공개 불필요)
+ **"이건 구글 SEO 순위가 아닙니다"** 식 디스클레이머로 오해 예방

🔴 ***"블러 미리보기 자체의 영향을 직접 조사한 연구는 없다"***는 **자기모순적 언급**도 있었음 → **신뢰도 낮음**

### 🔴🎯 Findable 직접 처방 — 이게 이번 리서치의 최대 수확

> 🎯 **"무료가 더 풍부하다"의 진짜 문제는 섹션 개수가 아니라, 무료가 "반복 확인의 이유"까지 다 줘버린 것.**
> **유료가 이겨야 할 축은 "더 많은 정보"가 아니라 "시간이 지나도 이 정보가 유효한가"다.**

| | 무료 | 유료 |
|---|---|---|
| 줘야 할 것 | **1회성 진단** = "지금 이 순간 우리 브랜드가 AI에 얼마나 보이나"(aha) | **시간에 따른 변화 추적 · 경쟁사 비교 · 반복 측정 · 알림** |
| 업계 등가 | Slack 메시징 · Figma 파일 · GitHub 저장소 | Slack **히스토리** · Figma **팀 라이브러리** · GitHub **CI 분** |

→ ⚠️ **따라서 "진실거울을 대시보드로 복사"는 오답이다.** 무료의 aha를 유료로 복사하면 축이 안 바뀐다.

→ **Intercom의 "위험 신호 알림형" 모델이 이 문제에 가장 잘 맞음**(월간 점수가 아니라 **이상 감지 알림**)

## 5. B2B "상사에게 보고할 자료" 문제

### (a) 증거 기반 (부분)
📕 [Close.com - Internal Champion Army](https://www.close.com/blog/internal-champion-army) (**원문 직접 확인**)
챔피언(내부 옹호자) 인에이블먼트 키트는 **"상사에게 그대로 전달할 수 있는 1페이지 임원 요약본"**을 포함해야 하며,
**구매자의 언어·구매자의 지표**로 쓰여야 함. 완전한 키트 = **ROI 계산기(데이터 사전 입력) + 경쟁사 비교표 + 예상 반대의견 대응**
🔴 단 이 페이지 자체는 **구체적 승률 데이터·수치를 제공하지 않았음** → *"챔피언 있으면 승률 4.5배"* 수치는 **원문 재확인 불가 = 사용 금지**

### (b) 관행
📕 [Matik - QBR One-Pager Template](https://www.matik.io/blog/qbr-one-pager-template)
QBR(분기 비즈니스 리뷰) 원페이저: **임원 요약 + 계정 현황 스냅샷** 구조가 SaaS 고객성공 업계 표준

**임원 요약 구조**(약 350~500단어, 1페이지):
**비즈니스 이슈 → 목적 → 근거 → 결론 → 권고 → 요청하는 결정**
🎯 실무 테스트: *"고위 독자가 한 번 읽고 **요청된 결정을 반복하지 못하면** 임원용이 아니다"*

### (c) 확인 못 함
**공유 가능한 리포트가 실제로 B2B 확장/전환에 미치는 정량적 인과 데이터** — 이번 세션 못 찾음. 필요시 별도 리서치

### 🎯 Findable 적용
진단 결과에 *"PDF 내보내기"* 버튼 하나가 아니라 **"대표님께 보내는 요약"** 프레임의 **별도 뷰**:
1. 우리 브랜드 AI 노출 점수 2. 경쟁사 대비 격차 3. **이번 달 안에 할 수 있는 조치 1~2개만** 압축
⚠️ 단 이는 **검증된 인과 데이터가 아니라 QBR 관행에서 유추한 의견**

## 6. 설득적 UX 카피 vs 다크패턴 경계

### (a) 증거 기반 (NN/g 원문 직접 확인)
📕 [NN/g - Deceptive Patterns](https://www.nngroup.com/articles/deceptive-patterns/)

**설득(정당함)**: 제시 정보가 사실에 부합 · 사용자가 선택지를 오해하지 않음 · 가치 교환이 공정할 때 사회적 증거·희소성 등 사용
**기만**: 정보가 조작/불완전 · 사용자가 관련 정보에 쉽게 접근 못함 · **부정적 정보나 대안이 은폐**될 때

🎯 **자가진단 질문**:
- *"사용자가 의도한 것보다 더 많이 쓰거나 공유하게 되는가?"*
- *"정보가 사실에 맞는가?"*
- *"선택지를 오해할 수 있는가?"*
- *"사용자가 서두르거나 압박당하거나 감정적으로 조작당하는가?"*

### 🎯 Findable 적용
경쟁사 비교시 *"경쟁사는 형편없다"*가 아니라 **"현재 관측된 노출 빈도"라는 사실 기반 수치만 제시하고 해석은 사용자에게 맡기면** NN/g 기준상 설득과 기만의 경계 안쪽에 남는다

> 아래 수치는 **그럴듯하지만 원문이 없다. 대외 자료·IR·심사 서류에 절대 쓰지 말 것.**
> (참고: [[feedback_no_fabricated_facts]] — IBK 가짜 실적 사고와 같은 종류의 위험)

| 주장 | 검증 결과 |
|---|---|
| *"NN/g 연구에서 loss-framed 가격 페이지가 gain-framed보다 데모 요청률을 유의미하게 높인다"* | 🔴 **실제 NN/g 원문 없음** |
| *"McKinsey 연구에서 loss-framed 메시지가 전환율 21% 증가"* | 🔴 **실제 McKinsey 원문 없음** |

✅ **손실회피(loss aversion) 자체는 학술적으로 확고**: Kahneman & Tversky 프로스펙트 이론(1979), 프레이밍 실험(1981) — 사람들이 손실을 이득보다 약 2배 크게 느낀다는 것은 실제 연구.
🔴 **단 그것을 "B2B SaaS 전환율 N% 증가"라는 특정 수치와 연결한 출처는 없다.**
