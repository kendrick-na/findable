## ✅ M1 해결 (2026-08-07 세션N-8, 커밋 `79df764`) — 아래 원문은 이력으로 보존

**결정 = A안+B안 병행**(사용자 승인). 인지를 **선행 축**으로 올려 2단 구조 + 종속 축에
**실효 상한** 병기(`27/40` → `27/34`). 점수 계산 무변경(3,840 케이스 회귀 0건).
⚠️ 바 채움·%는 **원 만점 기준 유지** — 실효 상한으로 채우면 인지 30% 브랜드의 감성 바가
가득 차서 "감성 우수"로 보이는 **정반대 오독**이 생긴다.

🔴 **이 작업 중 별건 발견 → 같은 커밋에서 수정**: 화면 점수 ≠ 메일·OG 점수가
**71건 중 58건(82%)**, 최대 32점(Olive 66/34). 화면만 `new Set()` dedup 배열을 채점기에
넘겨 **F11을 되돌리고 있었다**(F11은 geo-score.ts만 고치고 화면 dedup을 못 봄).
판정 근거 = 고유 엔진 방식은 인지도 **만점이 35%**(응답 단위는 4%) → F11이 없애려던
"사실상의 상수" 증상 그 자체. **저장값(응답 단위)이 맞다** → 4경로 전건 일치.
⚠️ `dedupMetrics`는 **개수 표시용으로 남김**("AI 7곳 중 6곳"을 응답 단위로 쓰면 거짓말).

## 🔴 (해결됨 · 원문 보존) M1. 점수의 60%가 "종속 축"인데 화면은 독립처럼 보여준다
**코드 실측**: `packages/audit/geo-score.ts:114·127`
```
sentiment = sentimentRaw × recognitionRate   ← 40점
presence  = presenceRaw  × recognitionRate   ← 20점
```
5축 중 **2축(60/100점)이 인지도에 곱해진다.** 그런데 화면은 5개를 나란히 나열해서
고객은 *"감성을 개선하면 27→40 되겠네"* 로 읽는다. **실제로는 인지도를 올려야 감성이 오른다.**
→ **처방 방향을 반대로 안내한다.** 리서치가 최강 신뢰장치로 꼽은 Semrush식 3요인 분해를
형식만 따라하고 인과를 뒤집은 상태.

**선택지**(사용자 결정 필요):
- A안: 5축을 **2단 구조**로 — `AI가 우리를 아나(인지)`를 선행 축으로 올리고 감성·노출은 종속 표시
- B안: 감성 만점을 인지도로 스케일한 **실효 상한** 병기 (`27 / 40` → `27 / 34 (인지 86% 반영)`)
- C안: 그대로 두고 툴팁으로만 설명
⚠️ 점수 정의 변경은 과거 값과의 비교 가능성에 영향(F11 전례) → 결정 전 영향 범위 확인 필요
