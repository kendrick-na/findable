# 읽기 전용 MCP — 프리뷰 한정 설정 예시와 허용 목록 점검 (2026-10-20)

> 값(토큰·ID)은 이 문서에 적지 않는다. 이름과 쓰는 방법만 적는다. 환경변수 변경·재배포는 대표가 한다.
> 쉬운 말 풀이: **프리뷰** = 운영(진짜 서비스)과 분리된 시험 배포. **허용 목록** = 이 커넥터가 읽어도 되는 브랜드 ID 모음.

## 1. 프리뷰에서만 켜는 환경변수 (모두 프리뷰 환경에만 등록, 운영에는 넣지 않는다)
| 이름 | 용도 | 비고 |
|---|---|---|
| `FINDABLE_MCP_ENABLED` | MCP 서버 전체 스위치 | 프리뷰에서만 켬 |
| `FINDABLE_MCP_READONLY_MODE_ENABLED` | 읽기 전용 모드 | **프리뷰·개발 환경이 아니면(아래 판정) 503 으로 거부**하고 기존 도구로 돌아가지도 않는다 |
| `FINDABLE_MCP_TOKEN_REQUIRED` | 토큰 검사 | 꺼져 있으면 공식 정보 점검 도구는 등록되지 않는다 |
| `FINDABLE_MCP_PREVIEW_TOKEN` | **프리뷰 전용 토큰**(옛 이름 `…READONLY_TOKEN` 은 더 이상 인정하지 않음) | 값은 대표가 직접 입력, 채팅·문서 금지 |
| `FINDABLE_MCP_PREVIEW_TOKEN_EXPIRES_AT` | 토큰 만료 시각. **엄격 형식만**: `2026-10-20T23:59:59Z` 또는 `2026-10-21T08:59:59+09:00` (소수 초·날짜만·공백 불가) | **없거나 형식이 다르거나 지났으면 모두 거부**. 시험 끝나면 변수 삭제 또는 과거 시각 |
| `FINDABLE_MCP_READONLY_BRAND_ALLOWLIST` | 허용 브랜드(쉼표). 항목은 `brandId` 또는 `brandId=기대도메인` (예: `<자사 brandId>=findable.co.kr`) | 비면 아무것도 읽지 않는다. **공식 정보 점검(실제 접속)은 `brandId=기대도메인` 쌍이 있고 DB 의 `Brand.domain` 이 그 도메인과 같을 때만** 한다(2026-10-20 sec/mcp-hardening). `brandId` 만 적으면 요약·분포 조회만 되고 점검은 거부. 형식이 틀린 항목은 그 brandId 를 통째로 뺀다 |

환경 판정(허용 목록 방식, 2026-10-20 보강): **`VERCEL_ENV` 가 정확히 `preview`** 이거나, **`VERCEL_ENV` 가 비어 있고 `NODE_ENV` 가 `development`/`test`** 일 때만 읽기 전용 모드·점검 도구가 켜진다. 그 밖(둘 다 빔·`staging`·오타·대문자 `PREVIEW`·`production`)은 전부 운영으로 보고 거부한다. 허용 목록 brandId 는 영문·숫자·`-`·`_` 만.

**전제와 수용한 위험 (관제탑 결정 2026-10-20, 코덱스 2차 재검토 「조건부 통과」 반영)**
- **배포 전제**: Findable 은 **Vercel 전용 배포**이고 자체 호스팅 운영은 없다. Vercel 은 모든 배포에 `VERCEL_ENV` 를 넣으므로 운영은 `production` 으로 거부된다. `NODE_ENV=development/test` 허용은 `VERCEL_ENV` 가 없는 로컬 개발·시험 전용이다. 자체 호스팅 운영을 새로 만들면 이 판정을 별도 명시적 허용값 방식으로 바꿔야 한다.
- **DNS 재바인딩(검사 때와 접속 때 주소가 바뀌는 공격)은 남아 있다.** 수용 조건: ① 프리뷰 한정 ② 허용 목록에는 **Findable 소유 도메인만**. **운영에서 켜기 전에는 연결 주소 고정(`DNS재바인딩_완화안_20261020.md`)이 필수**다.
- **기대 도메인은 DNS 도메인만** 받는다(의도된 정책). IPv6 리터럴(`[2606:…]`, `2606:…`)은 공개 주소라도 기대 도메인으로 쓸 수 없다. 공용 URL 검사(`assertPublicUrl`)는 공개 IPv6 리터럴을 통과시키지만 MCP 점검 대상은 도메인으로 한정한다.
- **만료 시각**: 앞뒤 공백은 지운다(토큰·허용 목록과 같은 정책). 연도는 2000~9999 만 받는다.

## 2. 허용 목록 규칙
- **Findable 소유 브랜드만** 넣는다(자사 `brandId` 1~2개). 고객 브랜드 ID 금지.
- 공식 정보 점검은 그 브랜드의 등록 도메인(`Brand.domain`)만 읽고, 그 값이 허용 목록에 적은 기대 도메인과 다르면 거부한다(접속 0). 비교 전 대소문자·앞의 `www.`·끝의 점은 같은 것으로 본다.
- 시험이 끝나면 허용 목록 변수와 토큰 변수를 지운다.

## 3. 허용 목록 등록 절차가 외부 입력으로 조작될 수 있는가 (코드 확인 결과)
| 질문 | 확인 결과 |
|---|---|
| 허용 목록은 어디서 오나 | 환경변수 `FINDABLE_MCP_READONLY_BRAND_ALLOWLIST` 하나뿐(`geo-flags.ts`). 요청 입력·DB 값으로 늘어나는 경로 없음 [확인] |
| 허용 목록 브랜드의 도메인은 사용자 입력인가 | **그렇다.** `Brand.domain` 은 고객이 등록하는 값이다(`start-tracking.ts`·`assign.ts` 가 `normalizeDomain`·`isValidDomain` 검증 후 저장, 관리자 `measure.ts` 는 `trim().toLowerCase()` 만). 즉 **허용 목록에 넣은 브랜드의 소유 조직(또는 관리자)이 도메인을 바꾸면 점검 대상이 바뀐다** [확인] |
| 그래서 생기는 위험 | 허용 목록에 고객 브랜드를 넣거나, 자사 브랜드의 도메인이 의도와 다르게 바뀌면 서버가 그 공개 도메인을 읽는다(사설 주소는 계속 차단). 한 번에 읽는 양·횟수는 제한되어 있으나 **허용 목록 브랜드의 도메인이 바뀌지 않았는지 시험 전 확인이 필요**하다 |
| 조치(2026-10-20, 브랜치 sec/mcp-hardening-20261020, 미푸시) | 허용 목록 항목을 「기대 도메인」과 함께 고정(`id=domain`)하고, DB 도메인이 다르면 점검 거부(접속 0). 점검 도구는 쌍 필수, 요약·분포 조회는 `brandId` 만도 허용 |
