# DNS 재바인딩 완화안 (설계·패치 초안만) — 2026-10-20 통합 전담

> **상태: 초안. 코드는 바꾸지 않았다. `official-facts.ts` 수정이 필요하므로 대표 승인 후 적용.**
> 쉬운 말 풀이: **DNS 재바인딩** = 이름(도메인)이 처음 확인할 때는 공개 주소를 가리키다가, 실제로 연결하는 순간 내부 주소(사설망)로 바뀌게 만드는 공격. **핀(고정)** = 확인한 그 IP로만 연결하게 묶는 것.

## 1. 지금 구조의 틈 [확인]

1. `official-facts.ts`의 `safeGet`이 요청마다 `assertPublicUrl(url)`로 주소를 **확인**한다(DNS를 한 번 조회해 사설 주소가 섞였는지 본다).
2. 곧바로 `fetchImpl(url)`이 **다시** 이름을 해석해 연결한다. 확인한 IP와 연결한 IP가 같다는 보장이 없다(그 사이에 DNS 응답이 바뀌면 뚫린다).
3. 이미 해 둔 완화: 등록 도메인(허용 목록 브랜드)만, 토큰 검사 켜짐일 때만 도구 등록, `confinedFetch`가 요청 직전에 한 번 더 확인. **창을 줄일 뿐 닫지 못한다.**

## 2. 해결 방향: 해석한 IP로만 연결 (권장)

한 번만 해석하고, 그 결과가 모두 공개 주소일 때만 **그 IP로 연결**한다. Node 내장 `fetch`는 undici 기반이라 연결 단계의 `lookup`을 바꾼 `Agent`를 `dispatcher`로 넘기면 된다.

```ts
// 초안 (apps/web/lib/mcp/pinned-fetch.ts 신규 제안 — 아직 만들지 않음)
import { Agent } from "undici";            // ⚠️ 의존성 추가 필요 여부 [확인 필요]
import { lookup } from "node:dns/promises";
import { isIP } from "node:net";
import { isPrivateAddress } from "@repo/audit/public-url-security"; // 현재 export 여부 [확인 필요]

export function makePinnedDispatcher(): Agent {
  return new Agent({
    connect: {
      // 연결 순간에 쓰는 DNS 해석을 가로챈다: 한 번 해석 → 전부 공개 주소인지 확인 → 그 IP로만 연결.
      lookup(hostname, options, callback) {
        lookup(hostname, { all: true, verbatim: true })
          .then((records) => {
            if (records.length === 0 || records.some((r) => isPrivateAddress(r.address))) {
              callback(new Error("URL_PRIVATE"), "", 0);
              return;
            }
            const first = records[0];
            callback(null, first.address, first.family);   // all:true 요청이면 배열 형태로 맞춘다 [구현 시 확인]
          })
          .catch(() => callback(new Error("URL_DNS"), "", 0));
      },
    },
  });
}
```

## 3. 필요한 결정·확인

| 항목 | 내용 |
|---|---|
| 의존성 | `undici` 는 워크스페이스 설치본(.pnpm)에 있으나 `apps/web`의 직접 의존성이 아니다. 직접 의존성 추가 = 패키지 설치 → **대표 승인 필요** (Node 내장 `fetch` 의 `dispatcher`는 undici 인스턴스를 요구) |
| 수정 범위 | 방법 A: `official-facts.ts` 수정(위 diff). 방법 B: `geo-tools.ts` 의 `confinedFetch` 안에서 `init.dispatcher` 주입(official-facts.ts 무수정) — 방법 B 권장 |
| 시험 | 모의 DNS(`lookup`)가 첫 호출은 공개 IP, 둘째 호출은 사설 IP를 돌려줄 때 **연결이 첫 IP로만** 가는지(핀 확인), 사설이면 연결 0건 |
| 배포 환경 | Vercel Fluid 환경에서 `Agent`가 요청 간 재사용되지 않게(핀 캐시 오염 방지) 요청마다 만들거나 TTL 0 [확인 필요] |
| 효과 | 확인~연결 사이 재바인딩 차단. **IP 고정 후에도 리다이렉트 대상은 호스트 허용 목록 재검사(이미 적용)** |

## 4. 지금 적용된 안전장치와 한계 (정직 기재)

- 적용됨: 허용 목록 브랜드의 등록 도메인만, 토큰 검사 켜짐일 때만 등록, 리다이렉트마다 호스트 재검사, 요청 직전 `assertPublicUrl` 재확인, 응답 64KB 상한.
- **한계: 확인과 연결 사이의 DNS 변경은 이 초안이 적용되기 전까지 막지 못한다.** 그래서 프리뷰 시험 시간에만 켜고 대표 승인 전에는 켜지 않는다.
