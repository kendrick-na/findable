# DNS 재바인딩 완화안 — 2026-10-20 초안 → 2026-10-21 **구현됨(내장 모듈)**

> **상태: 구현됨(내장 모듈).** 브랜치 `sec/dns-pinning-20261021`. 새 패키지 설치 없음(package.json·락파일 무변경).
> Node 내장 `http`/`https`/`tls`/`net`/`zlib`/`dns` 만 사용. 이전 초안의 `undici` 직접 의존성은 **필요 없어졌다**.
> 쉬운 말 풀이: **DNS 재바인딩** = 이름(도메인)이 처음 확인할 때는 공개 주소를 가리키다가, 실제로 연결하는 순간 내부 주소(사설망)로 바뀌게 만드는 공격. **핀(고정)** = 확인한 그 IP로만 연결하게 묶는 것.

## 1. 예전 구조의 틈 [확인]

1. `official-facts.ts`의 `safeGet`이 요청마다 `assertPublicUrl(url)`로 주소를 **확인**했다(DNS를 한 번 조회해 사설 주소가 섞였는지 본다).
2. 곧바로 `fetch(url)`이 **다시** 이름을 해석해 연결했다. 확인한 IP와 연결한 IP가 같다는 보장이 없었다(그 사이에 DNS 응답이 바뀌면 뚫린다).
3. 그때까지의 완화(허용 목록 브랜드 등록 도메인만, 토큰 검사 켜짐일 때만 등록, `confinedFetch` 재확인)는 **창을 줄일 뿐 닫지 못했다.**

## 2. 구현: 해석한 IP로만 연결 (`apps/web/lib/mcp/pinned-fetch.ts`)

요청 1건(= 리다이렉트 1단계)마다:

| 단계 | 내용 |
|---|---|
| ① 한 번 해석 | `dns.lookup(호스트, {all:true, verbatim:true})` 1회 → 주소가 **하나라도** 사설이면 거부(fail-closed). IP 직접 주소는 DNS 없이 바로 판정 |
| ② 연결 고정 | 통과한 주소 하나(IPv4 우선)를 고르고, 소켓을 직접 만들면서 `lookup` 옵션이 **그 IP만** 돌려주게 한다(연결 단계에서 DNS를 다시 묻지 않음). TLS 는 원래 호스트명으로 SNI·인증서 검증(`servername`, `rejectUnauthorized: true`) |
| ③ 이중 방어 | TCP 연결 직후, 요청 바이트를 보내기 **전에** `socket.remoteAddress` 를 다시 사설 검사 + 고정한 IP와 같은지 확인. 다르면 끊는다 |
| ④ 리다이렉트 | 핀 fetch 는 따라가지 않는다(`redirect: "manual"` 만 받음, 그 외는 거부). `safeGet` 이 기존처럼 수동·3회 상한으로 따라가며 **단계마다** `confinedFetch`(허용 목록·사전 확인) → 핀 fetch(①~③)를 다시 돈다 |
| ⑤ 상한 | 본문 512KB(압축 해제 **후** 기준, 압축 원본도 같은 상한), 전체 시간 5초(연결~헤더~본문 끝까지 하나로 잼), `gzip`/`deflate`/`br` 해제, 모르는 인코딩은 거부(→ 「확인 불가」) |
| ⑥ 연결 | `official-facts.ts` 의 `checkOfficialFacts` 기본 `fetchImpl` = 핀 fetch. `geo-tools.ts` 의 `guardedOfficialFacts` 도 `ctx.fetchImpl ?? pinnedFetch`. **fetchImpl 주입 구조는 그대로**(시험·호출자가 바꿀 수 있음) |

## 3. 한계 (정직 기재)

- **주소 하나만 시도**: 해석 결과 중 IPv4 가 있으면 첫 IPv4, 없으면 첫 주소 하나에만 붙는다. 그 주소가 죽어 있으면 다른 주소로 다시 시도하지 않는다(Happy Eyeballs·대체 시도 없음) → 그 항목은 「확인 불가」로 나온다.
- **IPv6 전용 사이트**: IPv4 가 없으면 IPv6 로 붙는다. 실행 환경(Vercel)에 IPv6 바깥 연결이 없으면 실패할 수 있다 [확인필요: 운영 켜기 전 실측].
- **keep-alive 끔**: 요청마다 새 연결(`connection: close`, 연결 풀 없음). 점검 1회 = 요청 4개 + 리다이렉트라 비용은 작지만, 매번 TLS 연결 비용이 든다.
- **HTTP/1.1 만**: ALPN 을 `http/1.1` 로 고정. HTTP/2 전용 서버는 거의 없지만 있으면 실패할 수 있다.
- **GET/HEAD·본문 없는 요청만**: 이 점검 용도에 맞춰 좁혔다. 다른 용도로 쓰려면 확장 필요.
- **프록시 미지원**: 환경변수 HTTP(S)_PROXY 를 따르지 않는다(직접 연결).
- **③의 순서 보장**: 소켓을 직접 만들고 `connect` 감시를 가장 먼저 걸어 요청 바이트보다 먼저 검사한다(로컬 시험으로 서버가 요청 0건 받음 확인). Node 내부 동작에 기대는 부분이라, Node 메이저 업그레이드 때 시험(`mcp-pinned-fetch.test.ts`)을 다시 돌려야 한다.
- **주입하면 핀이 없다**: 시험 등에서 `fetchImpl` 로 일반 `fetch` 를 넣으면 핀이 빠진다(운영 경로는 주입하지 않음).
- **시험 전용 옵션**: `ca`(자체 인증서 신뢰)·`portOverride`(로컬 포트)·`resolveAll`·`isPrivate` 는 시험용. 운영 기본값(`pinnedFetch`)은 넘기지 않는다.

## 4. 시험 (`apps/web/__tests__/mcp-pinned-fetch.test.ts`, 외부 네트워크 0)

로컬 https 모의 서버(127.0.0.1, 시험 때마다 openssl 로 만든 1일짜리 자체 인증서 — 저장소에 키를 두지 않음)와 모의 DNS.
openssl 이 없는 환경에서는 https 묶음을 건너뛴다.

- 재바인딩 시뮬레이션: 1번째 해석 = 공개, 이후 = 사설 → 이름은 **1번만** 해석되고 연결은 검사한 IP로만, 다음 요청은 연결 전에 거부
- 해석 결과에 사설이 섞이면 연결 0건 / 사설 IP 직접 주소 거부
- 연결 직후 remoteAddress 가 사설이면 요청을 보내기 전에 끊음(서버 요청 0건)
- 자체 인증서 미신뢰 시 거부(인증서 검증 켜짐) / 인증서에 없는 호스트명 거부(servername 검증)
- 본문 512KB 상한 / gzip 64MB 폭탄도 해제 후 512KB / 압축 원본 512KB 초과 시 중단 / 정상 gzip 해제 / 모르는 인코딩 거부 / 시간 제한
- 리다이렉트는 3xx 그대로 반환, 자동 추적·POST 거부
- 공식 사실 점검 전체: 허용 목록 밖(evil.test)으로 리다이렉트 → DNS 조회조차 없이 차단, 사설로 해석되는 허용 호스트(inner.test)로 리다이렉트 → 차단, 정상 경로 통과
- 평문 http 도 같은 핀
- route 통합 시험(`mcp-geo-route-integration.test.ts`): 운영 기본 경로가 핀 fetch 를 거치는지 확인
