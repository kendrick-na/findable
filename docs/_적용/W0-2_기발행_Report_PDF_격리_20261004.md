# W0-2 기발행 Report/PDF 격리 계약

상태: RELEASE `450b9a0` 기반 로컬 후보. 운영 Report.data·Blob·발송 메일은
조회하거나 수정하지 않았고 Preview/배포도 하지 않았다.

## 재현한 노출

- 과거 저장 PDF URL은 현재 웹 고지와 표시 보정이 반영됐는지 확인되지 않아도
  공개 리포트에서 그대로 다운로드됐다.
- 같은 과거 리포트의 운영자 서술은 관찰된 동시 발생을 원인처럼 표현했다.
  예: 공식 사이트 미도달이 다른 출처로 빈칸을 채우는 원인이라는 문장.
- AI 답변과 검색 노출을 분리한 뒷표지 고지는 이미 통과했지만 위 두 노출은
  별개였다. RELEASE 기준 회귀는 **2 RED/2 PASS**였다.

## 로컬 격리 규칙

종료 엔진 또는 2026-09-29 이전 네이버 합성 측정이 든 동결 스냅숏은
`publicationReview`가 없으면 다음처럼 fail-closed한다.

1. 측정 원문·관찰표와 발행본 안내는 계속 보인다.
2. 운영자가 작성한 why/insight/cause/playbook/PoC 서술은 재검수 안내로
   대체한다. 과거 저장 JSON은 덮어쓰지 않는다.
3. 저장 PDF URL은 공개 HTML에서 제거하고 재검수 중임을 알린다.
4. Report.data 안의 `publicationReview`는 고객 공개 JSON이 자기 자신을
   승인하는 값이므로 재공개 권한으로 신뢰하지 않는다. 재공개하려면 별도
   append-only 관리자 writer가 전달한 reviewer·reviewedAt·narrative 승인뿐 아니라 원본
   auditId, importedAt, report version, templateVersion이 모두 현재
   스냅숏과 일치해야 한다.
5. PDF는 위 조건에 더해 검수한 정확한 URL과 SHA-256 기록이 현재 URL 및
   런타임에서 실제 파일로 검증한 digest와 모두 일치해야 한다. URL만 같거나
   digest 문자열만 저장된 경우는 공개하지 않는다. 다른 template 또는 URL의
   검수 기록은 재사용할 수 없다.

후속 공격 테스트에서 자기승인 JSON과 정적 PoC 약속 문구가 각각 RED로
재현됐다. 현재 후보는 신뢰 가능한 별도 review 인자가 없으면 위험 발행본을
항상 격리하고, why/insight/cause/playbook/PoC 배열뿐 아니라 목차·CTA·20일
계획·수정 문구/재측정 약속도 재검수 문구로 바꾼다. 별도 trusted review가
들어오더라도 PDF는 검증된 실제 digest가 없으면 계속 보류한다.

웹 16 files / 95 tests, audit/web typecheck, 변경 핵심 파일 Biome와 diff check가
통과했다. 단, SHA-256 기록은 향후 검수 절차가 계산해 넣어야 하며 현재 요청에서
Blob 내용을 내려받아 실제 해시를 만들거나 운영 JSON을 갱신하지 않았다.

## 아직 완료가 아닌 이유

- 운영 DB의 실제 Report 목록, 고객별 발송 이력, 공개 토큰, Blob 직접 URL을
  대조하지 않았다. 웹 링크를 숨겨도 이미 전달된 Blob URL 자체가 회수되는 것은
  아니다.
- 누가 어떤 근거로 서술과 PDF를 승인할지, 고객 정정 통지와 재발행/폐기 정책이
  확정되지 않았다.
- 별도 `publicationReview`를 append-only로 쓰고 관리자 역할·PDF 실제 해시를 검증하는
  운영 writer가 없다.
- 따라서 이 후보는 **새 공개 노출의 안전 기본값**을 제공할 뿐, 기발행물의
  소급 영향과 고객 정정이 끝났다는 증거가 아니다.

다음 게이트는 W0-0에서 운영 대상이 확인된 뒤 read-only inventory로 영향을
분류하고, 사용자 승인 하에 고객별 `keep / reissue / revoke / notify` 결정을
기록하는 것이다. 운영 DB 쓰기·Blob 삭제·고객 연락은 별도 승인 전 금지한다.
