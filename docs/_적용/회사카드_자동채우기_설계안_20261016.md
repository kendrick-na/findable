## 1. 한 줄 결론
브랜드 이름·도메인 → ①사이트 푸터에서 상호·사업자번호 → ②국세청 상태조회 → ③DART(사업보고서 → 없으면 **감사보고서 원문**)에서 연매출 → ④못 찾은 칸만 입력창 1칸. 출처·사업연도가 붙은 값만 `CompanyFact`에 1사실=1행으로 저장하고, 리포트의 `revenue_opportunity`가 그 확인값을 읽는다. 공식(연매출×7%×(1−정확 노출률))은 그대로.

## 3. 흐름 (제안)
```
브랜드 이름·도메인
 └─① 사이트 푸터 읽기 (신규)  → 상호 · 사업자등록번호 [후보, 출처=홈페이지 푸터 + 읽은 URL]
 └─② 국세청 상태조회 (기존)   → 실재·계속/휴업/폐업 확인. 불일치면 후보 폐기
 └─③ DART 조회
      a. 고유번호(이름·번호 일치) → 기업개황(법인등록번호·설립일)
      b. 사업보고서 주요계정(기존) → 있으면 사용
      c. 없으면 list.json 으로 감사보고서(연결 우선) 접수번호 찾기 → document.xml → 손익계산서 '매출액'(신규)
 └─④ 못 찾은 칸 → 입력창 1칸(연매출 · 출처 · 사업연도) → 저장
 └─⑤ CompanyFact 저장 → 리포트 revenue_opportunity 가 읽음
```

### 3-1. 푸터 읽기 (신규 `sources/site-business-info.ts`)
- 대상: 홈 1쪽 + 푸터가 있는 링크 1~2쪽(이용약관·회사소개). robots 준수, 수집 거부 표시 사이트 제외 — **기존 `contact-email.ts`의 robots·수집거부(`hasCollectionRefusal`)·`htmlToText` 헬퍼를 그대로 재사용**(복사 금지, 이미 그 규칙을 따름).
- 추출: `사업자등록번호` 라벨 뒤 `###-##-#####` 형식, `상호`/`회사명`/`(주)…` 라벨. 테스트 사례(쇼핑몰 푸터, 법상 표시 의무): 넘버즈인 (주)비나우 833-87-01017, 프롬맘 (주)팜스킨 750-86-00716, 프란츠 바이오센서연구소(주) 119-86-72928 [관제탑 실측].
- **검증 규칙**: 사업자번호 체크섬(국세청 10자리 가중합) 통과 + 국세청 조회 성공 + 상호가 DART/푸터에서 일치할 때만 "확인". 한 사이트에 번호가 둘 이상(입점몰·운영사 병기)이면 자동 확정하지 않고 후보 목록으로 입력창에 제시.
- 대표자 이름은 **읽지도 저장하지도 않는다**(개인정보 — 별도 판단 요청 사항).

### 3-2. 감사보고서 매출 파싱 (신규, `opendart.ts` 확장 또는 `opendart-audit.ts`)
- `list.json?corp_code&bgn_de&pblntf_ty=F` 로 감사보고서 목록 → **연결감사보고서 우선**, 없으면 별도. 가장 최근 사업연도.
- `document.xml`(zip, 기존 `unzipFirstEntry`로 해제 확인) → 태그 제거 → 손익계산서 구간의 `매출액` 행: 당기(제N기)·전기 두 숫자 중 **당기만** 사용.
- 주의점(실물 확인): 단위는 보고서마다 원/천원 — 손익계산서 머리의 `(단위: 원|천원|백만원)`을 읽어 환산, 못 읽으면 null. `수익(매출액)` 등 계정명 변형은 허용 목록으로, 그 외는 null(추정 금지). 2024 연결 보고서에는 비교열에 "감사받지 아니한 재무제표" 표기가 있어 **당기 열의 감사의견 여부**를 함께 저장.
- 출력: `{amount, fiscalYear, fsDiv('CFS'|'OFS'), receiptNo, basis:'audit_report'}` — 기존 `DartRevenue`와 같은 모양 + `basis` 추가.
- 비일관 표기(홍보문구 3,250억 vs 3,500억)는 **감사값이 있으면 감사값이 우선**, 홍보문구는 저장하지 않는다.

### 3-3. 입력창 1칸 (대표 승인 필요 — 화면 계획)
- 위치: 영업 회사 카드(`admin/ax-mail/discover/company-card.tsx`)의 "연매출" 행. 자동으로 못 찾았을 때만 [입력] 버튼이 나온다. 자동 값이 있으면 값·출처·연도·접수번호 링크만 표시.
- 입력 칸: 연매출(원 또는 억 — 단위 선택), **출처(필수)**, **사업연도(필수)**. 출처 예: "NICE평가정보 2025". 셋 중 하나라도 비면 저장 불가.
- 저장 시 자동 기록: 입력자(Clerk userId)·입력일. 값 옆에 "직접 입력" 배지.
- **이 화면은 계획 승인 후 구현**(아래 §6 승인 요청).

### 3-4. 저장 (`CompanyFact`, 새 표·마이그레이션 없음)
- 1사실=1행. `field='revenue'`, `value={amount, currency:'KRW', fsDiv, receiptNo, basis}`, `source` = `opendart`(사업보고서/감사보고서) 또는 `input`(수동), `sourceRef`=접수번호 또는 입력 출처 문자열, `asOf`=사업연도. 유니크 키 `[companyId, field, source, asOf]`라 같은 연도 재조회는 멱등.
- 수동 입력은 `value`에 `{source:'NICE평가정보 …', enteredBy, enteredAt}` 포함. **출처 없는 매출은 저장하지 않는다**(서버에서 거부).
- 우선순위(같은 사업연도 충돌 시): DART 감사값 > 수동 입력. 자동 적재는 수동 입력을 덮어쓰지 않는다(`industrySource='manual'` 규칙과 같은 원칙). 다른 연도는 모두 보존, 리포트는 가장 최근 확인값.
- 직원수 등으로 **매출을 추정하지 않는다**(기존 주석 준수).

### 3-5. 리포트 연결 (`revenue_opportunity`)
- 리포트 config를 만들 때 회사 카드의 최신 `revenue` 사실을 `ConfirmedRevenue{annual, source:'DART 감사보고서'|입력 출처, year}`로 변환 → 기존 `aiRoutedRevenue(revenue, accuracy)` 호출 → `config.revenue_opportunity`. 공식·7% 상수·정확 노출률 계산은 **불변**.
- 연결 지점은 `apps/app/lib/client-report/admin.ts`(+`admin/client-reports`) 쪽 config 생성 — 구현 전에 정확한 함수를 한 번 더 확인한다. `apps/web` 렌더(`missedRevenue`)는 수정하지 않는다.
- 값이 없으면 지금처럼 매출 페이지가 통째로 빠진다(변경 없음).

## 5. 테스트 계획
1. **푸터 추출**: 실제 푸터 문구 3종(비나우·팜스킨·바이오센서연구소) 고정 HTML 조각 → 상호·번호 정확 추출. 번호가 둘 이상이면 자동 확정 안 함. 체크섬 틀린 번호는 후보 폐기. robots 금지·수집 거부 표시 사이트는 읽지 않음.
2. **감사보고서 파싱**: 비나우 2025·2024 보고서에서 잘라 낸 손익계산서 조각 고정 → 당기 매출 324,958,207,706 / 266,431,203,386, 연결 우선. 단위 천원·백만원 환산, 단위 없음 → null, 계정명 불일치 → null.
3. **저장 규칙**: 출처 없음·사업연도 없음 거부, 같은 (회사·연도·출처) 멱등, 자동 적재가 수동 입력을 덮어쓰지 않음, 다른 연도 보존.
4. **리포트 연결**: 확인 매출 없음 → `revenue_opportunity` 없음(매출 페이지 빠짐), 있음 → `aiRoutedRevenue` 결과와 동일(공식 회귀: 연매출×7%×(1−정확 노출률)).
5. **실조회 확인(읽기 전용, 구현 후)**: 비나우 1건 DART 실호출로 2025 연결 324,958,207,706 일치, 팜스킨·바이오센서연구소는 null + 입력 경로 안내.
6. `pnpm check`·`apps/app` tsc·전체 vitest·실제 `next build`(env는 로컬 .env 경유, 값 출력 금지).

## 6. 대표 결정·승인이 필요한 것
1. **입력창 화면**(§3-3 위치·칸·문구) — 승인 후 구현.
2. **DART 데이터 재배포**: 저장·내부 활용은 가능해 보이나(금감원 약관 [확인필요]), 감사보고서 원문을 고객 리포트에 그대로 싣는 건 아니다 — 리포트에는 **금액·사업연도·출처 문구만** 쓴다. 이 범위로 충분한지 확인.
3. **대표자 이름**: 이번 설계는 읽지도 저장하지도 않는다. 필요하면 별도 판단.
4. **연결 vs 별도**: 리포트에 어느 쪽을 쓸지 — 제안은 연결 우선(홍보문구 3,250억과도 일치), 연결이 없으면 별도.
5. 새 패키지는 필요 없다(zip 해제는 기존 `unzipFirstEntry`, HTML→텍스트는 기존 헬퍼). 설치 필요가 생기면 먼저 묻는다.

## 7. 구현 순서·일정 제안 (기준선 종료 알림 후)
① 감사보고서 파싱(+테스트) → ② 푸터 읽기(+테스트) → ③ 저장 규칙·서버 액션 → ④ 리포트 연결 → ⑤ 입력창 화면(승인 후) → ⑥ 비나우 실조회 확인 → ⑦ 배포 전 파일 목록 통보. 한 단계씩 커밋·검증.
