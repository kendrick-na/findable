# 영업 시스템 — 회사 카드 DB 설계안 (제안, 미확정)

> 작성 2026-10-06 · 대상 `/admin/ax-mail` 단계 ①② (세그먼트 발굴 → 회사 카드)
> ⚠️ **제안서다. 마이그레이션은 만들지 않았다.** 대표·컨트롤타워 승인 후 별도 작업으로 반영.
> 코드: `apps/app/lib/ax-mail/sources/*` (공공 API 5종 수집기 + `buildCompanyCard`) — DB 없이 동작.

## 1. 한 줄 결론

**회사 1곳 = `Company` 1행, 그 회사에 대한 사실 1개 = `CompanyFact` 1행(출처·가져온 시각·기준일 포함).**
값만 덮어쓰는 구조로 가면 「이 직원수 어디서 났지?」를 답할 수 없다 → 사실마다 출처를 남긴다.

## 2. 이용허락범위 — DB 저장 가능 여부

| 소스 | 문서 | 이용허락범위 (페이지 표기, 2026-10-06 확인) | DB 저장 |
|---|---|---|---|
| 국세청 사업자등록 상태조회 | data.go.kr/data/15081808 | 제한 없음 | 🟢 가능 |
| 금융위 기업기본정보 | data.go.kr/data/15043184 | 제한 없음 | 🟢 가능 |
| 국민연금 가입 사업장 내역 | data.go.kr/data/3046071 | 제한 없음 | 🟢 가능 |
| 식약처 화장품 관련 정보 | data.go.kr/data/15020628 | 제한 없음 | 🟢 가능 |
| OpenDART (금감원) | opendart.fss.or.kr 이용약관 | 별도 라이선스 표기 없음. 약관 제16조: 서비스·프로그램 저작권은 금감원, 공공데이터법 준수 | 🟡 저장·내부 활용은 통상 허용으로 보이나 **[확인필요]** — 재배포(고객에게 원문 그대로 판매) 전 금감원 확인 권장 |

> ⚠️ 「제한 없음」은 공공데이터 **이용 조건** 이야기다. 대표자 **이름**은 개인정보이므로
> 개인정보보호법상 수집 목적(B2B 영업 대상 확인) 범위 안에서만 쓰고, 메일 개인화에 이름을 넣을지는 별도 판단.
> 국민연금 자료는 **3인 이상 법인 / 10인 이상 개인사업장**만 나온다(문서 명시) — 작은 회사가 없다고 「직원 0명」이 아니다.

## 3. 제안 모델 (Prisma 초안)

```prisma
/// 저장된 발굴 필터 — 예: "서울 화장품책임판매업, 국민연금 10~50명, 성장 중"
model Segment {
  id          String    @id @default(uuid())
  name        String
  /// 필터 조건 JSON (source, kind, region, 인원 범위, growth 등) — 화면에서 다시 돌릴 수 있게
  filter      Json
  createdBy   String    // Clerk userId (관리자)
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt
  companies   SegmentCompany[]
}

model SegmentCompany {
  segmentId  String
  companyId  String
  addedAt    DateTime @default(now())
  segment    Segment  @relation(fields: [segmentId], references: [id], onDelete: Cascade)
  company    Company  @relation(fields: [companyId], references: [id], onDelete: Cascade)
  @@id([segmentId, companyId])
}

/// 회사 1곳. 식별자는 사업자번호(10자리) 우선 — 없으면 이름만으로 만들되 matchConfidence 로 구분
model Company {
  id               String   @id @default(uuid())
  businessNumber   String?  @unique   // 10자리 숫자
  corpRegNo        String?            // 법인등록번호 13자리
  dartCorpCode     String?            // OpenDART 고유번호 8자리
  legalName        String             // 표시용 (최신 사실의 사본)
  domain           String?            // 브랜드 사이트 (franzskincare.com)
  /// exact | name_only | none — buildCompanyCard 결과
  matchConfidence  String
  lastEnrichedAt   DateTime?
  createdAt        DateTime @default(now())
  updatedAt        DateTime @updatedAt
  facts            CompanyFact[]
  leads            Lead[]
  segments         SegmentCompany[]
  @@index([legalName])
}

/// 사실 1개 = 출처 1개. 같은 field 에 소스별·시점별 여러 행이 쌓인다(덮어쓰지 않음).
model CompanyFact {
  id          String   @id @default(uuid())
  companyId   String
  /// legalName | representative | foundedOn | employeeCount | address | homepage | industry
  /// | listing | businessStatus | taxType | revenue | pension | cosmeticsLicenses
  field       String
  value       Json     // 매출은 { amount, currency, fiscalYear, fsDiv, receiptNo } 그대로
  /// nts | fsc | nps | mfds | opendart | input(사람이 입력)
  source      String
  sourceRef   String?  // 원천 식별자 (DART 접수번호, NPS seq, 식약처 업체번호 등)
  asOf        String?  // 원천 기준일 (YYYY-MM-DD / YYYY-MM / 사업연도)
  fetchedAt   DateTime // 우리가 가져온 시각
  company     Company  @relation(fields: [companyId], references: [id], onDelete: Cascade)
  @@index([companyId, field, fetchedAt])
}

/// 영업 대상(담당자 연락처 단위). 기존 lib/ax-mail/leads.ts 스냅샷을 옮겨 올 자리.
model Lead {
  id          String   @id @default(uuid())
  companyId   String
  email       String
  contactName String?
  role        String?
  /// prospect | contacted | replied | meeting | won | lost | do_not_contact
  stage       String   @default("prospect")
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  company     Company  @relation(fields: [companyId], references: [id], onDelete: Cascade)
  basis       ContactBasis[]
  @@unique([companyId, email])
}

/// 수신 근거 — KISA 불법스팸 방지 안내서 기준 「먼저 보내도 되는 근거」의 법적 증빙.
/// lib/ax-mail/contact-basis.ts 의 kind 3종과 같다. 수정하지 않고 새 행을 추가(이력 보존).
model ContactBasis {
  id         String   @id @default(uuid())
  leadId     String
  /// business_card | requested | existing_customer
  kind       String
  detail     String   // 명함 받은 장소 / 요청 방법 / 거래 내용
  date       String   // YYYY-MM-DD — 명함 받은 날 / 요청일 / 마지막 거래일
  evidenceUrl String? // 명함 사진·요청 메일 캡처 (Storage) — 분쟁 시 제출용
  recordedBy String   // Clerk userId
  recordedAt DateTime @default(now())
  lead       Lead     @relation(fields: [leadId], references: [id], onDelete: Cascade)
  @@index([leadId, recordedAt])
}
```

## 4. 설계 이유

| 결정 | 이유 |
|---|---|
| 사실을 `CompanyFact` 로 분리 | 대표 규칙 「확인 안 된 사실 금지」. 카드 칸마다 출처·기준일을 화면에 띄울 수 있다 |
| 덮어쓰지 않고 누적 | 국민연금 가입자 추이·대표자 변경 같은 **변화 자체가 영업 신호** |
| `Company.businessNumber` unique | 동명 회사 혼동 방지(실측: 「바이오센서연구소」 검색에 「에스디바이오센서」가 걸림) |
| `ContactBasis` 를 Lead 하위 이력으로 | KISA 기준 증빙은 「언제·어떻게 받았나」가 핵심 → 삭제·수정 대신 추가만 |
| 매출은 DART 만 | 비상장 중소기업은 DART 미등록이 정상 → 칸을 비운다. 직원수로 추정하지 않음 |

## 5. 결정 필요 (대표)

1. 🟡 **OpenDART 데이터 재배포 범위** — 내부 영업용 저장은 진행, 고객 리포트에 원문 수치 노출은 확인 후.
2. 🟡 **대표자 이름 보관 여부** — 공공데이터지만 개인정보. 저장하되 메일 본문 자동 삽입은 끌지 결정.
3. 🟢 마이그레이션 시점 — 현재 리드는 JSON 스냅샷(`lib/ax-mail/data/leads-snapshot.json`). DB 이전은 ③ 단계(발송) 전에.

## 6. 실측 메모 (2026-10-06, Franz = 바이오센서연구소(주))

- 금융위: 같은 법인이 기간별 7행 → 최신 행(기준 2026-06-30) 사용. 홈페이지 칸 비어 있음.
- 국민연금: `seq` 는 사업장 ID 가 아니라 **월별 스냅샷 번호** → 월마다 상세 조회 필요(6개월 = 12회 호출).
- 국민연금 업종명이 「배전반 및 전기 자동제어반 제조업」으로 등록돼 있어 실제 업종과 다를 수 있다 → 업종은 참고용.
- 주소: 금융위(법인 기본정보)는 관악구, 국민연금(2026-04 이후)은 금천구 — 소스마다 기준이 달라 둘 다 보존해야 한다.
- 식약처: 「책임판매업」 전용 오퍼레이션은 없고 업종(INDUTY) 값으로 구분. 업종 필터 파라미터가 없어 전체 3.3만 건을 페이지로 훑어야 한다 → 세그먼트 발굴은 **야간 배치로 전체 적재 후 DB 에서 필터**가 맞다.
- 국세청 상태조회: 첫 호출 503/504 → 같은 날 재시도(11:08 KST) 정상(신규 키 전파 지연으로 추정 [AI가설]).
