# 운영 측정 계기판 (2026-10-05, 컨트롤타워 C21)

> 목적: **추가 유료 호출 없이**, 운영에서 이미 30분마다 도는 워크스페이스 측정(cron `apps/web/app/api/cron/auto-refresh-tracking`, `*/30 * * * *`)을 측정 표본으로 쓰고 배포 전후를 읽기 전용 SQL로 비교한다.
> 실행: Supabase `findable-prod` 커넥터(MCP `execute_sql`) 또는 SQL 편집기. **읽기 전용**. 결과에 고객 식별자(id·도메인·이메일)를 넣지 않는다.

## 1. 배포 경계 이후 측정 건강도

경계 = 배포 시각(UTC). 2026-10-05 RELEASE `8247f2b` 운영 반영 ≈ `2026-10-04 15:05 UTC`.

```sql
select case when "organizationId" is not null or email like 'org:%' then 'org' else 'public' end as kind,
       status,
       count(*) as n,
       round(percentile_cont(0.5) within group (order by extract(epoch from ("completedAt" - "createdAt")))::numeric, 0) as p50_s,
       round(max(extract(epoch from ("completedAt" - "createdAt")))::numeric, 0) as max_s,
       count(*) filter (where checkpoint is not null)         as with_checkpoint,
       count(*) filter (where postprocessing is not null)     as with_postprocessing,
       count(*) filter (where "attemptStartedAt" is not null) as with_attempt
from "AuditJob"
where "createdAt" >= timestamptz '2026-10-04 15:05+00'
group by 1, 2
order by 1, 2;
```

## 2. 실패 사유 분포 (앞 60자만)

```sql
select left(coalesce("errorMessage", '(none)'), 60) as reason, count(*) as n
from "AuditJob"
where status = 'failed' and "createdAt" >= now() - interval '7 days'
group by 1 order by 2 desc;
```

## 3. Tracking 멱등 키 도입 확인

```sql
select count(*) filter (where "trackingRowKey" is not null) as keyed,
       count(*) as total,
       max("createdAt") as latest
from "Tracking"
where "createdAt" >= timestamptz '2026-10-04 15:05+00';
```

## 판정 기준

- 🟢 배포 후 org 측정이 계속 `completed`이고, p50·max가 배포 전과 비슷하거나 나으며, 새 칸(checkpoint/postprocessing/trackingRowKey)이 채워짐.
