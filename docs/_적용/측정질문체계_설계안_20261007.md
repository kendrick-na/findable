# 측정 질문 체계 개선 설계안 (2026-10-07, 승인 대기)

> 상태: **초안 — 대표 승인 전, 코드 반영 없음.** 컨트롤타워 검토 조건(점수 계약 버전 분리·그림자 도입·플랜별 원가·업종 확장성)을 반영했다.
> 표기: [확인사실] 코드·실측·공식 문서 / [AI가설] 제안 / [추정] 계산값 / [확인필요] 미확인

## 1. 지금 구조와 문제 [확인사실]

- 측정 1회 질문 최대 8개(`prompt-limits.ts`) — 브랜드 이름 질문 4개(소개·강점 / 「X와 비슷한 5곳」·경쟁사 비교) + 이름 없는 질문 최대 2개(공식 사이트 문구에서만 생성 → 슬로건뿐인 사이트는 0개).
- **GEO 점수는 브랜드 이름 질문으로만 계산**하고 이름 없는 질문은 분모에서 뺀다(`answer-buckets.ts`, `normalize-stored-metrics.ts`). → 점수가 말하는 것 = 「AI가 우리 이름을 아는가」. 「업종을 물었을 때 추천하나」는 점수에 없다.
- 대표 상품 질문 없음. 실제 검색 수요 반영 없음(검색량 기반 질문 `demand-prompts.ts` 는 플래그 `MEASUREMENT_DEMAND_PROMPTS` 뒤, 꺼짐).
- 점수 5축(감성 40·노출 품질 20·인지 20·점유율 10·경쟁 10)은 HubSpot AEO Grader 공개 배점과 같다.

## 3. 제안 질문 세트 [AI가설]

| 유형 | 개수 | 재료 | 점수 |
|---|---|---|---|
| A. 카테고리 구매 「주름에 좋은 앰플 추천해줘」 | 8 | 네이버 검색광고·구글 키워드 검색량 순 | **핵심 점수**(검색량 가중 언급률) |
| B. 고민 해결·사용법 | 4 | 지식iN 질문 말투 + 검색량 | 핵심 점수 |
| C. 대표 상품(이름 없이 특징으로) | 3 | 공식몰 대표·베스트 상품(성분·가격) | 핵심 점수 |
| D. 비교·대안 「○○ 대신 쓸 만한 곳」 | 2 | 등록 경쟁사 + 검색량 | 경쟁 순위·점유율 |
| E. 브랜드 이해 「X는 어떤 브랜드야」 | 3 | 등록 정보·엔티티 프로필(v3) | **정확도·감성에만** |

- 비브랜드 85% / 브랜드 15%. 말투는 AI에 실제로 묻는 반말 대화체. 시장 설정에 따라 국내 7 : 해외 3 기본.
- **업종 확장성**: 지금 성분·제형 사전은 K-뷰티 전용 → 화장품 외 업종은 A~C 가 비어 기존 사이트 문구 질문으로 돌아간다. 업종 공통 틀(「{키워드} 추천」「{키워드} 비교」「{키워드} 비용」) + 업종별 사전 추가가 필요. 업종 11개 중 우선순위 결정 필요.
- **공식몰을 못 읽을 때**(무신사처럼 해외 IP 차단 등): 대체 경로 = 등록된 대표 상품·카테고리(고객 입력) → 네이버 쇼핑 카테고리 검색량 → 사이트 문구. 어느 것도 없으면 측정은 하되 「이름 없는 질문 0개」를 화면에 명시.

## 4. 점수 계약 (컨트롤타워 조건)

1. 질문 계획에 `questionPlanVersion` 을 두고, **버전이 다른 회차끼리는 추세·직전 대비 비교 자동 차단**(네이버 표본 interleave-v1 방식).
2. `MENTION_VERDICT_VERSION` 은 건드리지 않는다(과거 회차 점수 소실 방지).
3. 헤드라인 점수 = A~D 의 검색량 가중 언급률로 바꿀지는 **대표 결정**. 바꾸면 무명 브랜드 점수가 크게 떨어지고 과거와 이어지지 않음 → 실고객이 적은 지금 바꾸는 편이 덜 아프다.
4. **그림자 도입**: 새 세트를 같이 돌려 기록만, 점수는 기존 세트로 → 며칠 비교 후 전환(v3 판정과 같은 절차).
5. 선행 조건: 느린 엔진 처리(B, 질문×엔진 칸 단위 체크포인트) — 질문 수가 늘면 270초 예산을 확실히 넘기 때문.

### 5-1. 실측 [확인사실] (운영 DB 최근 14일, 완료 측정 156회)
- 1회 평균: 엔진 응답 25.1행 · 질문 4.5개 · **원가 ₩621** → **질문 1개(엔진 6곳)당 약 ₩138**
- 엔진별 호출당: **Claude ₩118.9(웹검색, 엔진 원가의 약 86%)** · naver-briefing ₩12.9 · ChatGPT ₩11.5 · Perplexity ₩6.9 · Gemini ₩0(무료 한도, 지속 여부 [확인필요]) · 네이버·다음 ≈₩0
- 판정기 LLM(v2 + 그림자 v3) 비용은 별도 [확인필요, 소액 추정]
- → **원가를 움직이는 가장 큰 변수는 질문 수보다 Claude 웹검색.** Claude 를 빼면 질문 1개당 약 ₩19.

- **그림자 기간 원가**: 기존 + 새 세트가 겹치므로, 그림자는 **브랜드당 주 1회·일부 브랜드**로 제한한다.

### 5-2-1. 엔진 구성이 다른 회차의 점수 (컨트롤타워 검토 반영)
- ④안은 매일(Claude 제외)과 주간(Claude 포함) 회차의 엔진 구성이 달라 분모가 다르다 → 한 추세선에 놓으면 주간 회차마다 점수가 튄다.
- ⭐ **(나) 채택 권장**: 헤드라인 점수·추세·직전 대비는 **매일 세트(Claude 제외) 기준으로 고정**. 주간 Claude 포함 결과는 「Claude 포함 주간 점검」 카드로 따로 보여 주고 추세선에 넣지 않는다.
- 안전장치: 추세 비교 가드에 **엔진 구성 키**(예: `engineSetKey`)도 추가해, 구성이 다른 회차가 실수로 섞이지 않게 한다(questionPlanVersion 가드와 같은 방식).
- ③안처럼 한 회차 안에서 질문별 엔진 수가 다르면: 점수는 **질문별로 먼저 그 질문에 물은 엔진만으로 평균 → 질문 평균**(질문 가중)으로 계산해, 엔진이 많은 질문이 점수를 더 끌지 않게 한다.

### 5-3. 시간 [추정]
- 질문 1개 ≈ 엔진 병렬 30~40초 → 20문항 약 10~13분 = 270초 실행 3~4번 분량.
- 지금 이어가기 상한(2회)으로는 끝나지 않는다 → **이어가기 상한을 질문 계획 크기로 계산**(필요 실행 수 = ⌈계획 질문 수 × 40초 ÷ 240초⌉, 여유 1회 추가)하고, B(질문×엔진 칸 단위 체크포인트) 위에서 돈다. 매일 8문항은 2~3번, 주 1회 20문항은 4~5번.

### 5-4. 검색량 가중치가 없을 때
- 네이버 검색광고 API 키가 없거나 해당 키워드 검색량이 없으면 **균등 가중**으로 계산하고, 화면 점수 옆에 「검색량 정보 없이 계산」을 표시한다.

## 8. 대표 결정 기록 (2026-10-07)

- ✅ **대표 점수 1개 = 「정확 노출률」**: 이름 없는 질문 답변 중 우리 브랜드가 나오고 설명까지 맞는 비율. 틀린 설명(예: Franz=메신저 앱)은 노출로 세지 않음. 아래에 보조 숫자 「단순 언급률」과 빨간 카드 「AI가 틀리게 설명한 답 N건」(누르면 원문). 점수 2개 안은 철회.
- ✅ **Claude 패키징(경쟁사 관행)**: Growth 이상 주 1회 기본 포함, Starter 는 유료 추가 옵션(월 ₩29,000~39,000, Otterly Lite $29 수준), 어떤 플랜도 Claude 매일 실행 안 함. 근거: 10곳 중 6곳이 Claude 를 추가요금·최상위 전용·고단가로 분리.
