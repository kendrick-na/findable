#### 이메일 보류 규칙 (코덱스 검토 반영)
이메일만으로는 「그 기록이 탈퇴자 본인 것」이라고 단정할 수 없다. 그래서 아래 경우에는 **바꾸지 않고 보류**하고,
로그 `privacy.user_erase.email_held` 에 **사유·건수·id 만** 남긴다(이메일 원문은 남기지 않는다).
| 사유 | 판정 |
|---|---|
| `role_address` | @ 앞부분(+ 뒤 무시)이 역할 주소 목록에 있음: admin·biz·business·contact·cs·help·hello·hr·info·mail·marketing·office·pr·press·sales·service·support·team·webmaster (`ROLE_EMAIL_LOCAL_PARTS`) |
| `shared_with_other_user` | 다른 회원 행이 같은 이메일(대소문자 무시)을 쓰고 있음 |
보류된 건은 운영자가 로그의 id 로 확인한 뒤 수동 처리한다.

### 2-4. 조직 소유권 이전

- 탈퇴자가 `Organization.ownerId` 이고 남은 구성원(`User.organizationId` = 그 조직)이 있으면
  **`User.createdAt`(회원 행 생성 = 가입 시각)이 가장 이른 사람**에게 넘긴다(같으면 id 순).
- **조직마다 별도 트랜잭션**: 한 조직의 이전이 실패해도 회원 삭제와 다른 조직 이전은 유지된다.
- 새 소유자 후보를 **잠근 뒤(조직 연결·해제 웹훅과 같은 잠금) 아직 구성원인지 다시 확인**하고, 소유자가 여전히
  탈퇴자일 때만 바꾼다. 아니면 **바꾸지 않고 보류** → 경고 로그 + 운영 알림 `privacy.owner_transfer.held`
  (사유: `successor_left_during_transfer` · `owner_already_changed` · `transfer_error`).
- Clerk 쪽 조직 관리자 역할은 바꾸지 않는다(우리 DB 의 소유자 칸만). 운영 콘솔 플랜 부여(`grantPlan(org.ownerId)`)가
  새 소유자를 가리키게 된다.
- 남은 구성원이 0명이면 이전하지 않고 `privacy.user_erase.sole_owner_orgs` 로그만 남긴다(⏭ 3-1).

## 3. 다음 단계 ⏭ (스키마 변경 필요 — 이번엔 구현 안 함)

### 3-1. 혼자 쓰던 조직: 「정기결제 해지 → 30일 뒤 삭제」 (대표 확정 방침)
지금은 로그(`privacy.user_erase.sole_owner_orgs`)에 조직 id 만 남긴다.
필요한 것: 조직에 「삭제 예정일」 칸(스키마 변경) → 탈퇴 시 PortOne 예약 결제 취소 확인 후 날짜 기록 →
30일 뒤 cron 이 조직 삭제. 결제 기록(2-3)은 조직과 별도 표라 남는다.
⚠️ 그 전까지는 혼자 쓰던 조직의 **예약 정기결제가 탈퇴 후에도 남아 있을 수 있다** → 로그를 보고 수동 해지 필요.

### 3-2. (3차에서 구현됨) 늦은 웹훅을 막는 탈퇴 표식 표 ✅
`DeletedClerkUser{clerkId, deletedAt}` — 탈퇴 트랜잭션 **첫 단계**에서 기록. 가입·수정·조직 연결은 같은 사용자
잠금(`pg_advisory_xact_lock(hashtext('clerk-user:<id>'))`) 안에서 표식을 확인한 뒤에만 쓴다 → 확인과 쓰기 사이에
탈퇴가 끼어들 수 없다. 표가 없거나 조회가 실패하면 500(fail-closed). 표식은 개인정보가 없어 계속 보관한다.

## 4. 남은 일·대표 조치

### 4-1. 법정 보관 기간 끝난 결제 기록 자동 파기
세 표 모두 2026-10-05 마이그레이션으로 생겨 2031-10 전에는 대상이 없다.

### 4-2. PostHog 에 이미 들어간 개인정보 (대표 조치)
이번 수정은 **앞으로** 보내지 않게 할 뿐, 과거에 보낸 값은 PostHog 에 남아 있다.
- PostHog → People → 속성 `email`·`firstName`·`lastName`·`phoneNumber`·`avatar` 삭제(탈퇴자는 사람 자체 삭제).
- PostHog 프로젝트 설정 → **「Discard client IP data」 켜기**(브라우저 이벤트의 IP — 코드로는 못 끔).

### 4-3. 처리방침 문구
IP 보관 기간을 「목적 달성 시」 → **「3개월」** 로 고쳐야 코드와 맞는다(문구 담당 세션에 전달).

### 4-4. 보류된 이메일 수동 처리
`privacy.user_erase.email_held` 로그가 나오면 운영자가 id 로 확인해 처리한다.

### 4-5. PostHog `User Deleted` 이벤트 중복 (영향 낮음 — 그대로 둠)
Clerk 가 탈퇴 웹훅을 다시 보내면 DB 삭제는 멱등이라 문제없지만, PostHog `User Deleted` 이벤트는
한 번 더 기록될 수 있다. 탈퇴 수 집계 시 distinct_id 기준으로 세면 된다.

|---|---|---|---|
| `apps/web/app/api/audit/route.ts` → `AuditJob.ipAddress` | DB | 무기한이었음 | ✅ 3개월 뒤 자동 비움 (`/api/cron/purge-expired-ip`, 매일 01:30 KST) |
| `apps/app/.../auto-refresh-tracking` → `AuditJob.ipAddress = "auto-refresh"` | DB | 표식일 뿐 IP 아님 | 같은 cron 이 함께 비움(하루 한도는 당일 것만 봐서 영향 없음) |
| `apps/web/app/[locale]/contact/actions/contact.tsx` | Upstash 요청 제한 키 | 1일 창 후 자동 만료 | 그대로 |
| `apps/web/app/api/newsletter/subscribe/route.ts` | Upstash 요청 제한 키 | 1시간 창 후 자동 만료 | 그대로 |
| `apps/web/lib/mcp/audit-bridge.ts` | DB(`ipAddress: null`) | 저장 안 함 | — |

**IP 정리 작업 방식**
- 3개월 = 달력 기준, **월말 넘침 없음**: 5-31 → 2-28(윤년 2-29), 8-31 → 5-31, 12-31 → 9-30. 시각은 그대로(UTC).
- **경계 정책: `createdAt < 기준 시각` 만 비운다. 기준 시각과 정확히 같은 행은 남기고 다음 날 실행이 비운다**
  (즉 보관 기간은 「3개월 + 최대 하루」).
- 오래된 것부터 **1,000건씩**, 한 번 실행에 **최대 45초**(함수 제한 60초 안). 배치마다 남은 예산을 확인하고(2초 미만이면
  새 배치 안 함), 배치 1회는 min(남은 예산, 15초)를 넘으면 그 배치만 되돌려진다. 다 못 끝내면 `done:false` 로 끝내고
  다음 날 실행이 이어서 한다. 행은 지우지 않고 IP 칸만 비운다.
- **동시 실행 방지**: 배치마다 별도 트랜잭션에서 `pg_try_advisory_xact_lock(hashtext('cron:purge-expired-ip'))` 를
  시도하고, 다른 실행이 쥐고 있으면 기다리지 않고 비켜선다(`lockBusy:true`). 비우는 조건을 쓰기 때도 다시 걸어
  건수가 실제로 비운 수와 같다.

## 6. 운영자 확인 절차 — 웹훅 실패·보류

| 로그/알림 이름 | 뜻 | 할 일 |
|---|---|---|
| `webhook.auth.failed` (로그 + Sentry 알림) | Clerk 웹훅을 500 으로 돌려보냄. 남는 값: `eventId`(Svix 메시지 id)·`eventType`·`status`만 | ① 같은 시각의 원인 로그 확인(`privacy.user_erase.failed`·`webhook.user.tombstone_lookup_failed`·`webhook.user.clerk_lookup_failed`) ② Clerk 대시보드 → Webhooks → 해당 엔드포인트 → Message Attempts 에서 `eventId` 로 검색해 재시도 성공 여부 확인 ③ 재시도가 모두 실패했으면 원인 해결 후 같은 화면에서 **Resend**(삭제·적재는 멱등이라 다시 보내도 안전) |
| `privacy.owner_transfer.held` (로그 + Sentry 알림) | 소유권 이전 보류, `ownerId` 그대로 | 운영 콘솔에서 그 조직 구성원을 확인해 소유자를 직접 정한다 |
| `privacy.user_erase.email_held` | 역할 주소·공유 이메일이라 무료 진단·리드 이메일 보류 | id 로 확인해 본인 것만 수동 처리 |

| `privacy.ip_purge.done` 의 `done:false` | IP 정리가 시간 예산·잠금 때문에 덜 끝남 | 조치 불필요(다음 날 이어서). 며칠 연속 `done:false` 면 확인 |
