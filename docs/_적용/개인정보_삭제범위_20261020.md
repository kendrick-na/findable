## 3. 대표 결정 필요 🟡 (구현하지 않음)

### 3-1. 혼자 쓰던 조직 — 탈퇴자가 소유자이고 남은 구성원이 0명
지금은 **로그(`privacy.user_erase.sole_owner_orgs`)에 조직 id 만 남기고 아무것도 지우지 않는다.**

| 안 | 내용 | 장점 | 위험 |
|---|---|---|---|
| A. 즉시 삭제 | 조직 → 브랜드·측정·리포트 연쇄 삭제 | 방침과 가장 가까움 | ⚠️ **예약된 정기결제가 PortOne 에 남아 있으면 탈퇴 후에도 청구될 수 있음** — 결제 취소를 먼저 해야 함. 되돌릴 수 없음 |
| ⭐ B. 30일 유예 후 삭제 | 정기결제 해지 확인 → 30일 뒤 cron 이 삭제 | 실수 탈퇴 복구 가능, 결제 정리 시간 확보 | 「삭제 예정일」 칸이 필요 → **스키마 변경 필요** |
| C. 남기고 이름만 지움 | 조직명을 "탈퇴한 조직"으로 교체 | 가장 안전 | 브랜드(사업자번호 등) 데이터가 계속 남음 |

> 결제 기록(2-3)은 어느 안이든 **조직과 별도 표**라 남는다(관계를 일부러 안 걸어 둠).

### 3-2. 뉴스레터 구독 이메일
회원 가입과 별개 동의다. 탈퇴 시 함께 지울지(제안: **구독 해지 상태로 바꾸고 이메일 삭제**) 결정 필요.

### 3-3. 검색 성과 연결(GSC·GA4)의 Google 권한 토큰
탈퇴자가 연결했더라도 조직이 쓰는 연결이다. 조직에 다른 구성원이 있으면 유지가 맞아 보이나,
토큰 자체는 **탈퇴자의 Google 계정 권한**이다. 결정 필요(제안: 조직에 남은 사람이 있으면 유지 + 재연결 안내).

### 3-4. 조직 소유자(`ownerId`)가 탈퇴한 경우
다른 구성원이 있어도 `ownerId` 는 탈퇴자 id 로 남는다. 운영 콘솔의 플랜 부여(`grantPlan(org.ownerId)`)가
없는 사용자를 가리키게 된다. 제안: 남은 구성원 중 가장 오래된 사람으로 옮기기(코드만으로 가능, 결정 후 구현).

## 4. 남은 일 (이번 범위 밖)

### 4-1. 법정 보관 기간 끝난 결제 기록 자동 파기
5년 지난 `PaymentRefund`·`RefundRequest`·`RenewalNotice` 정리 cron. 세 표 모두 2026-10-05 마이그레이션으로 생겨
2031-10 전에는 대상이 없다.

### 4-2. PostHog 에 이미 들어간 개인정보 (대표 조치)
이번 수정은 **앞으로** 보내지 않게 할 뿐, 과거에 보낸 이메일·이름·전화번호·사진 주소는 PostHog 에 남아 있다.
- PostHog 화면 → People → 각 사용자 → 속성 `email`·`firstName`·`lastName`·`phoneNumber`·`avatar` 삭제
  (또는 탈퇴자는 사람 자체 삭제).
- PostHog 프로젝트 설정 → **「Discard client IP data」 켜기** — 브라우저 이벤트에 IP 가 붙는 것을 막는다(코드로는 못 끔).

### 4-3. 탈퇴 후 늦게 도착한 `user.created`/`user.updated` 가 회원 행을 되살리는 경우
Clerk 웹훅은 순서를 보장하지 않는다. 막으려면 「삭제된 id 목록」 표가 필요 → **스키마 변경 필요**라 보류.

### 4-4. 처리방침 문구
IP 보관 기간을 「목적 달성 시」 → **「3개월」** 로 고쳐야 코드와 맞는다(문구 담당 세션에 전달).
