# 질문 생성기 품질 수정 계획 (2026-10-14 · 계획만, 구현·푸시 없음)

> 대표 방침: "우리 시스템이 이상한 질문을 만들면 알고리즘을 고친다."
> 범위 제한(관제탑 지시): 기본 질문 폴백 `defaultConsumerQuestions`, 비교키 `+q:default-v2`, 판정, 엔진 설정, 측정 실행 로직은 **건드리지 않는다.** 바꾸는 곳은 "질문 제안 경로"(`/welcome` 질문 단계·질문 마법사·영업 제안)뿐이다.

## 1. 원인 (코드 확인)

| 증상 | 원인 | 위치 |
|---|---|---|
| ①"지메인이나 클로드…" 엔진명 오표기 | AI 엔진 이름을 검사하는 코드가 없다. 프롬프트도 엔진명 언급을 막지 않는다. | `prompt-suggestions.ts` 프롬프트, `question-plan.ts` `checkQuestion` |
| ②"센드버드·인터콤" 무관 서비스명 | 경쟁사 입력이 없으면 프롬프트가 "일반형"만 요구하는데, 코드는 **LLM이 끌어온 고유명사를 검사하지 않는다.** 이름 검사는 "우리 이름이 이름 없는 질문에 들어갔나"(`containsAnyName`)뿐이다. | `checkQuestion` |
| ③"Findable은 어디서 사는 거야?" | 프롬프트가 "소비자가 반말로" + 브랜드 질문 예시에 `'{브랜드} 어디서 사?'`를 **고정 예시로 박아 놨다.** 업종 B2B SaaS여도 같은 틀을 쓴다. 업종은 분야 이름(`industryLabel`)만 넘기고 질문 틀은 업종과 무관하다. | `brandUnderstanding` 스키마 설명, 프롬프트 첫 문단 |
| 뷰티: "번호 매긴 스킨케어"(넘버즈인) | 브랜드 이름 뜻을 풀어 쓴 질문. 이름 문자열이 안 들어가서 이름 검사를 통과한다. 대표 상품 유형만 "사이트 문구 근거"를 요구한다. | `hasSiteEvidence`는 representative 한정 |
| 뷰티: "서울대 연구진 제품 있다고 했는데" | 전제를 깐 문장을 막는 규칙이 없다. | `checkQuestion` |

## 2. 수정안 (전부 질문 제안 경로 안, 추가 AI 호출 0)

### 2-1. AI 엔진명 고정 사전 + 검증
- 새 순수 파일 `packages/ai/lib/engine-names.ts`: 표준 표기(ChatGPT·Claude·Gemini·Perplexity·네이버·다음·HyperCLOVA 등)와 한글 표기(챗GPT·클로드·제미나이·퍼플렉시티), **알려진 오타**(지메인·지매니·제미니 등) 표.
- 검사: 질문에서 사전·오타 표·자모 단위 편집거리 1 이내 근접어를 찾는다.
- 처리 권고안: **질문에서 엔진명이 나오면 버린다.** AI에게 "AI 모델에서…"라고 묻는 질문은 측정 의미가 없고, 소비자도 그렇게 묻지 않는다. 대안은 "표준 표기로 치환"이고, 선택은 승인 사항이다.
- 프롬프트 제약에도 "질문에 AI 서비스·모델 이름을 쓰지 마"를 추가한다.

### 2-2. 입력에 없는 고유명사 삽입 차단
- **허용 목록 방식:** 질문 속 고유명사 후보가 [우리 이름·별칭·등록 경쟁사·사이트 문구·업종 라벨·일반어 목록·엔진 사전] 어디에도 없으면 버린다(`unknown_proper_noun`).
- 후보 탐지(한계 있음, 아래 7절): ① 영문 대문자 단어·3자 이상 영문 중 약어(AI·SaaS·B2B·CRM·API 등)가 아닌 것. ② 한글은 "X(이)나/(이)랑/와 Y 같은·처럼" 목록 패턴의 X·Y.
- **대안 유형 구조 변경:** 등록 경쟁사가 **없으면** 대안 질문은 LLM이 쓰지 않고 코드의 고정 문형("이 분야 다른 선택지는 뭐가 있어?" 등 업종 분기 문형)을 쓴다. 경쟁사가 있으면 그 이름만 쓰고, 다른 고유명사가 섞이면 버린다. ②번 사고의 주 경로를 구조로 막는다.
- **근거 표기 필드:** 스키마의 질문마다 `basis`(site·industry·competitor·brand)를 같은 호출에서 받는다. 근거가 없거나 대표 상품 유형인데 site가 아니면 버린다. 추가 호출은 없다.

### 2-3. 업종별 질문 틀 분기 (업종 enum 전체)
`question-plan.ts`에 `INDUSTRY_FRAME` 표를 추가해 프롬프트(질문 틀·페르소나)와 후처리(금지 패턴)가 같은 표를 쓴다.

| 업종 | 질문 관점 | 브랜드 직접 질문 예 | 금지 패턴 예 |
|---|---|---|---|
| beauty·fashion·food·retail | 구매·후기·성분/소재·가격대·구매처 | 후기·어디서 사 | (제한 없음) |
| b2b_saas | 도입·비교·가격·연동·보안·후기, 도입 담당자 | "{브랜드}는 어떤 서비스야?", 가격, 연동, 평판 | 어디서 사·구매처·배송 |
| manufacturing | 납품·인증·소재·견적·거래처 | 어떤 부품 만들어?, 인증 있어? | 후기 어때(소비자형)·배송 |
| finance | 가입·수수료·금리·안전성·후기 | 수수료, 안전해? | 어디서 사 |
| healthcare | 진료·예약·비용·후기·위치 | 어떤 진료 해?, 예약 | 어디서 사 |
| education | 수강·커리큘럼·비용·후기·수료 | 커리큘럼, 수강 후기 | 어디서 사 |
| content_ip | 어디서 보나·구독·장르 | 어디서 볼 수 있어? | (구매처 허용) |
| other·미선택 | 구매 전제 없이 일반 질문 | 어떤 곳이야? | 어디서 사 |

- 이 표는 제안 경로 전용이다. `defaultConsumerQuestions`와 `industryLabel`은 그대로 둔다.

### 2-4. 전제·이름 풀이 차단
- 전제 문장: "~라고/다고 했는데·했던데·들었는데·라던데" 같은 패턴은 버린다(`presupposition`).
- 브랜드 이름 풀이: 규칙만으로는 완전 차단이 불가능하다. 프롬프트에 "브랜드 이름 뜻을 풀어 질문하지 마(예: 넘버즈인→번호)"를 명시하고, 2-2의 `basis` 필드와 허용 목록으로 대부분 걸러낸다. 새어 나가는 몫은 사람이 승인하는 단계(기본 미선택)가 마지막 방어선이다.

### 2-5. 질문 수 부족 시 폴백
- 지금: 유효 질문 4개 미만이거나 `confident=false`면 기본 질문 폴백(그대로 유지).
- 추가: 새 가드로 더 많이 버려지므로 유형별 초과 요청(`OVERSHOOT`)을 2→3으로 올린다.
- 20개 미만이어도 지어내서 채우지 않고 "직접 추가" 안내로 둔다.
- 재생성 재시도(추가 AI 호출 1회)는 선택 사항이며 승인이 필요하다.

## 3. 재현·가드 테스트 계획
- 사례 6개 전부를 "나쁜 생성물을 흉내 낸 입력 → 가드가 버린다/치환한다"로 `question-plan.test.ts`에 추가: 지메인(엔진 오타), 센드버드·인터콤, B2B에 "어디서 사", 넘버즈인 번호 풀이, 서울대 전제, 일반 정상 질문은 통과.
- `generateObject`를 모킹한 `prompt-suggestions` 통합 테스트: 나쁜 출력이 섞인 응답 → 최종 후보에 없고, 정상 질문은 남는다.
- 업종 enum 전체 표 테스트: 모든 enum 값에 틀이 있는지(빠지면 실패).
- 거짓 양성 테스트: 정상 질문 20개가 안 잘리는지.
- 기존 테스트(ai 347개)와 `defaultConsumerQuestions` 불변을 확인하는 고정 테스트.

## 4. 금지 조건 준수
- 변경 파일: `question-plan.ts`(가드·업종 틀 추가만), `prompt-suggestions.ts`(프롬프트·스키마·가드 호출), 새 `engine-names.ts`, 테스트.
- 건드리지 않음: `defaultConsumerQuestions`, `+q:default-v2`, `search-sampling-version.ts`, 러너·판정·엔진 설정, 기존 저장 질문.
- 이미 저장된 Findable 자사 질문은 그대로이므로, 재생성·재승인하면 질문 세트 지문이 바뀌어 "새 기준선"이 자동으로 잡힌다(G3).

## 5. 일정·리스크
- 구현 약 1일(가드·사전·업종 표·테스트), 영업 3곳 측정과 무관해 동결 기간에도 배포 가능(질문 제안 경로만 변경).
