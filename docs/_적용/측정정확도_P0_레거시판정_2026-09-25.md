# 측정 정확도 P0 — 레거시 엔티티 판정 격리

## 재현

- 운영 `GET /api/audit/e395f16c-c4cc-4bab-a0b0-b16bc2f1a3f9`는 `completed`, `sov=23`, `verifiedCount=22`, `unverifiedCount=0`을 반환했다.
- 같은 결과에서 ChatGPT는 `㈜테크디디` 클라우드/SI 회사를 설명하면서 `confirmed`, Gemini는 노우버스의 TechDD를 설명하면서 `different_entity`, Perplexity는 `techdd.co.uk`를 설명하면서 `confirmed`였다.
- 저장 응답에는 원문 발췌와 `mentionQuality`가 있었지만, 읽기 경로의 `withRecomputedAuditMetrics`는 원문 재판정 없이 저장된 boolean만 재집계했다.

## 원인

엔티티 판정 규칙이 변경되어도 `AuditJob.result`에는 판정 계약 버전이 없었다. 따라서 과거의 잘못된 `confirmed`/`different_entity` 값이 현재 리포트·PDF 상태·처방·이력 집계의 입력으로 계속 사용됐다. 또한 집계기는 `unverified`를 분모에서만 제외하고 분자(`enginesWithMention`)에는 남길 수 있었다.

## 이번 수정

- 신규 측정 결과에 `mentionVerdictVersion=2`를 저장한다.
- 버전이 없는 과거 결과는 원문/발췌를 보존한 채 `revalidation_required`로 격리한다.
- 격리 회차는 모든 성공 응답을 `unverified`로 취급하고 점수·인용 도메인·순위·처방을 확정하지 않는다. 공개 API에서는 PDF도 오래된 것으로 표시되어 제공하지 않는다.
- `aggregateAudit`가 `unverified` 행을 언급 분자에서도 제외하도록 보강했다.
- 회귀 테스트는 레거시 TechDD 형태의 오판정이 `sov=0`, `unverifiedCount>0`, 빈 처방으로 내려가는지와 분자/분모 집계를 검증한다.

## 미해결 / 다음 단계

현재 변경은 운영 데이터 삭제·덮어쓰기 없이 안전하게 보류시키는 단계다. 레거시 원문을 새 판정기로 재검증해 별도 파생 결과를 생성하는 백필은 API 요청마다 LLM을 호출하지 않도록 관리자 실행 경로와 비용·재시도·감사 로그를 설계한 뒤 진행해야 한다. 그 전까지 과거 회차는 확정 점수나 유입 추정으로 사용할 수 없다.

운영에서 확인한 공개 리포트 페이지는 HTTP 200이었다. 반면 직접 GET한 `/chat`·`/lead`는 405(POST 전용), `/pdf`는 404였다. 실제 클릭 플로우는 배포된 클라이언트의 POST/다운로드 요청을 브라우저에서 추가 확인해야 하며, 이번 코드 변경에서는 고객 연락이나 운영 데이터 변경을 수행하지 않았다.

## 최신 main 통합 및 재검증 (23:30 KST)

- `origin/main`을 fetch해 `8ed8163` 확인 후 격리 브랜치에 merge했다. 원래 작업의 가입/초대/고객 플로우 수정은 보존했다. 운영 push/배포는 수행하지 않았다.
- mixed official/namesake 목록 전체를 즉시 다른 엔티티로 판정하던 규칙을 수정했다. 반대로 목록에 우연히 들어온 공식 URL만으로 동명 업체를 승인하지 않도록 본문의 공식 주체 단서도 요구한다. 근거 부족은 `unknown_brand` 확정값 대신 `unverified`다.
- `tldts`의 public/private suffix 처리를 사용해 본사/하위도메인을 비교한다. `co.uk`, `github.io`, 타 입주자 도메인 및 `official.com.evil.test`는 공식 소유 범위가 아니다. 이는 의미 판정을 보조하는 단서이며 도메인만으로 최종 엔티티를 승인하지 않는다.
- Claude는 답변 text.citations만 사용한다. Perplexity는 citations URL만 채택하고 search_results는 해당 URL의 제목을 보완하는 용도로만 사용한다. 검색 후보를 인용으로 승격하지 않는다.
- 신규 측정은 전체 rawResponse, 원래 문자열 일치 결과, 질문/언어를 함께 저장한다. 재판정 시 판정 이후 false를 재사용해 올바른 응답을 다시 검사하지 못하는 문제를 막았다.
- `proposeAuditRevalidation`과 `scripts/propose-audit-revalidation.ts`는 저장 스냅샷을 입력받는 읽기 전용 도구다. 원자료 해시와 행별 제안만 생성하며 DB import·업데이트·점수·게시용 버전 필드가 없다. `reviewRequired=true`이며 잘린 발췌·없는 원문은 unverified다.
- 잠정 projection의 응답 badge/순위도 함께 제거한다. DB의 원래 응답은 유지한다. 재정규화는 멱등이며 잠정 PDF는 항상 오래된 결과로 취급한다.

### 실제 저장 응답 재판정 (외부 판정 모델 호출, DB 쓰기 없음)

동일한 운영 API 스냅샷을 두 번 재생했다. 첫 실행에서 공식 URL이 검색 목록 끝에 끼어 있는 Perplexity 오탐이 재현돼 추가 실패 테스트를 만든 뒤 수정했다. 두 번째 실행 결과:

| 원래 index | 엔진 | 이전 판정 | 제안 판정 |
|---|---|---|---|
| 0 | ChatGPT | confirmed | unverified |
| 2 | Perplexity | confirmed | unverified |
| 3 | Gemini | different_entity | confirmed |
| 16 | Perplexity | confirmed | unverified |

23행(별도 브리핑 포함) 제안은 confirmed 3, unverified 7, unknown_brand 6, absent 3, different_entity 4. 이 숫자는 **점수/등장률로 게시하지 않았다**. 저장된 출처 목록에는 실제 인용 번호의 원래 순서·검색 후보 여부가 없고 일부 응답은 잘려 있어, 완전한 소급 복원을 보장할 수 없다. 전체 원문 및 출처-주장 연결을 검증하기 전까지 해당 회차는 잠정 유지가 맞다.
