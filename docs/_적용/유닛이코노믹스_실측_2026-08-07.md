# 유닛 이코노믹스 실측 — 진단 1건에 얼마·얼마나 걸리나 (2026-08-07 세션N-10)

> 투두리스트 #41 *"HyperCLOVA(네이버 AI) 호출당 원가·레이턴시 실측"* 의 답.
> ⚠️ **재실측 불필요** — 프로덕션 `AuditJob.result.cost` 에 이미 쌓여 있던 값을 집계한 것이다
> (새 측정 0건·추가 과금 0원). 값이 바뀌는 건 단가표를 고치거나 엔진 구성을 바꿀 때뿐.

## 0. 한 줄 결론

**진단 1건 = 평균 87원 · 중앙값 89원 · 3분 30초.**
원가는 **문제가 아니다**(Starter 99,000원 기준 원가율 0.09%). 진짜 리스크는 **시간**이다.

## 1. 원가 (실측 n=19, 0원 아닌 완료 job)

| 지표 | 값 |
|---|---|
| 평균 | **86.8원** |
| 중앙값 | **88.7원** |
| 최소 ~ 최대 | 42.2원 ~ 133.8원 |
| 프롬프트 4개 기준 | **84.2원** (n=18) |
| 프롬프트 5개 기준 | 133.8원 (n=1) |

### 엔진별 기여 — **claude·chatgpt 두 개가 92%**

| 엔진 | 1회 평균 | 비중 |
|---|---|---|
| **claude** | 8.59원 | **50.5%** |
| **chatgpt** | 7.09원 | **41.7%** |
| naver | 0.57원 | 3.3% |
| perplexity | 0.48원 | 2.8% |
| **hyperclova** | **0.30원** | **1.7%** |
| gemini · daum | 0원 | 0% (무료 티어) |

🔬 **투두 질문("HyperCLOVA 원가")의 답은 "거의 0"이다.** 건당 **0.30원**으로 전체의 1.7%.
원가를 줄이려면 손댈 곳은 한국 엔진이 아니라 **claude·chatgpt(합 92%)** 다.
→ 한국 엔진은 **원가 부담 없이 유지**할 수 있다(= 차별점을 싸게 지킨다).

### 마진 (Starter 99,000원/월 기준)

| 월 측정 횟수 | 원가 | 원가율 |
|---|---|---|
| 1회 | 87원 | 0.09% |

⚠️ 단 이 계산에 **crew(4에이전트) 원가는 빠져 있다** — 별도 확인 필요.

## 2. 레이턴시 — 🔴 **여기가 진짜 리스크**

| 지표 | 값 |
|---|---|
| p50 | **181초** (3분) |
| p75 | 233초 |
| p90 | **239초** |
| 최대 | **298초** |

### 🔴 함수 상한과 **2초 차이**

```
실측 최대   298초
함수 상한   300초  ← apps/web/vercel.json · route.ts maxDuration
             ↑ 여유 2초
```

`p90=239초`이고 최대가 **298초**다. 상한 300초를 넘기면 함수가 죽고
job 이 `processing` 으로 굳는다(stuck). **이미 한 건이 2초 차로 살아남았다.**

- 프롬프트가 4→5개로 늘어난 job 이 곧바로 최댓값(298초·133.8원)을 찍었다
  → **프롬프트 수를 늘리면 상한에 먼저 부딪힌다.** 게이팅 레버(프롬프트 5/30/150…)를
  풀 때 원가가 아니라 **시간이 먼저 터진다**.
- 완화책이 이미 있음: stuck 스윕 cron(15분 초과 정리)이 돌고 있어 **영구 굳음은 방지**된다.
  다만 그 고객의 진단은 실패한다.

### 권고 (미착수 — 판단 필요)

1. **함수 상한 300 → 600초 상향** 검토. Vercel 기본 상한이 300s 라 플랜 확인 필요.
2. 또는 **엔진 병렬도 상향**(현재도 `Promise.allSettled` 병렬이나 총 28~35 호출).
3. 또는 프롬프트 증가 시 **분할 실행**(배치를 나눠 여러 함수 호출로).

⚠️ 어느 쪽도 **지금 당장은 급하지 않다** — 실측 24건 중 240초 초과가 1건뿐이다.
다만 **프롬프트 수를 늘리는 순간 급해진다**는 걸 기록해 둔다.

## 3. 데이터 한계 (해석 시 주의)

- 원가가 기록된 job = **24건 / 완료 71건**. 나머지는 `cost` 계기 도입 전 측정분이다.
- 그중 0원 아닌 건 **19건**. 표본이 작다.
- 단가표(`packages/ai/lib/engines/cost.ts`)는 **2026-07 기준 추정**이다.
  ⚠️ **실제 청구서로 보정하지 않았다** — claude·chatgpt 가 92%를 차지하므로
  이 둘의 단가가 틀리면 전체가 틀린다. 청구서 확인 시 `TOKEN_PRICES` 만 고치면 된다.
- 🔬 **자기정정**: 처음에 *"`basis` 가 전부 `free` 인데 `krw` 는 0이 아니다(표기 불일치)"* 라고
  적었으나 **내 집계 스크립트의 버그**였다(엔진별 마지막 행의 basis 만 읽음).
  실제 분포는 정상이다 — 예: claude `{token:77, free:20}`. `free` 20건은
  **stub·에러 호출**(실호출 안 해 0원)이고, 과금분은 전부 `token` 으로 찍힌다.
  `cost.ts` 도 `krw` 를 계산하면 반드시 `basis:"token"` 을 함께 반환한다(코드 확인).
