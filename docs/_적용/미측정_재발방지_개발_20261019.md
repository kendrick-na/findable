## 2. 구조적 보장(불변식)

| 불변식 | 구현 | 시험 |
|---|---|---|
| ① 시작 전 질문 ≥ 8 이고 이름 질문 ≥ 2, 아니면 사유 코드가 붙은 측정 불가 | `checkQuestionInvariant`·러너 `requireQuestionInvariant`(+플래그 `MEASUREMENT_INVARIANT_ENABLED`, 고객 측정은 opt-in 안 함)·스크립트 기본 적용(`--allow-short` 로만 우회) | 질문 0~20 × 이름 0~q 전 구간, 러너 3조합(꺼짐·opt-in 없음·켜짐) |
| ② 어떤 실패에도 사유 코드 존재 | `ensureReasonCodes`(비면 `unclassified`)·`classifyFailureMessage`·`unmeasurableMessage` | 사이트 결과 8종 × 질문 수 × 엔진 전멸 전 조합에서 코드 비지 않음, 모든 코드에 라벨·행동 안내 |
| ③ 「확신 없음」이어도 통과 질문은 사용, 모든 시도 빈손이면 다음 단계로 | 재시도(첫 시도 빈손) → 후보 합치기(기존) → 단계적 채움(업종·분야 기본 질문) → 한 줄 소개 입력(`mergeSiteNote`) → 그래도 0이면 `zero_questions` 로 정직하게 종료 | 무작위 흔들림 120회·15곳 × 3변형 |
| 이름 질문 항상 ≥ 2 | `withBrandGuarantee`(어느 경로로 끝나도 적용, 질문이 하나도 없는 결과는 그대로) | 흔들림 120회에서 질문이 있으면 이름 질문 ≥ 2 |
| robots 우회 금지 | 금지 경로 미요청 · `SITE_ROBOTS_FIRST_ENABLED` 시 홈 미요청 | 요청 경로 기록 시험 4건 |
| 오류는 미노출로 세지 않음 | 재시도 후에도 못 재면 오류 칸으로 남음 | 429 동시 8칸·총 예산 소진 시험 |

## 6. 한계
- 과거 1차 타임아웃·429 의 엔진은 복구 불가(기록 없음). 앞으로는 남는다.
- 이름 변형이 실제 폐기 원인과 맞는지는 1번 검증 전까지 **추정**이다(표기 유형별 통과 여부 자체는 확정). 어느 경우든 이름 질문은 보증으로 항상 ≥ 2.
- 이미지 안의 글(I-05형)은 읽지 못한다 — 정직한 측정 불가 + 한 줄 소개 대체.
- 고객 측정 경로는 질문을 DB 에서 읽어 사이트 읽기 결과 코드가 러너로 안 넘어간다(질문 수 기반 코드만 남음). 화면·문구 변경은 하지 않았고, 필요하면 계획만 보고한다.
