## 3. 켜는 순서(제안 — 각 단계 Preview 확인 후)
1. `MEASUREMENT_GAP_LOG_ENABLED` — 기록 전용, 점수·질문 불변. 가장 먼저(이후 단계의 효과를 같은 표로 본다)
2. `QUESTION_GENERATION_LOG_ENABLED` — 기록 전용
3. `QUESTION_OTHER_FALLBACK_ENABLED` → `QUESTION_BRAND_GUARANTEE_ENABLED` → `QUESTION_BRAND_VARIANT_ENABLED` → `QUESTION_SOFT_CONFIDENCE_ENABLED`(영향 가장 넓음·생성 호출이 최대 1회 늘 수 있음, 마지막)
- 켜기 전 16곳 A/B(외부 비용 약 ₩2,800 추정)는 대표 승인 후. 되돌리기는 환경값 삭제+재배포.

## 4. 한계·남은 결정
- 사이트 읽기 결과 코드는 `readSiteProfileWithOutcome` 를 부르는 쪽(측정 스크립트·질문 제안 서버 액션)이 `gapInput.siteOutcome` 으로 러너에 넘겨야 결과에 남는다. 현재 제품 경로(고객 측정)는 질문을 DB 에서 읽어 사이트 읽기 결과를 러너에 넘기지 않으므로 **질문 수 기반 코드만** 남는다(사이트 코드는 동기측정 스크립트 경로에서 효과).
- 이름 변형이 실제 `brand_missing` 원인(이름 표기 어긋남)과 맞는지는 **추정**이다(진단 문서도 추정). 15곳 A/B 에서 확인한다.
- 이름 변형은 번역·음역(한글↔영문)을 하지 않는다. 그 경우는 고정 문형 보장이 받는다.
- 화면(UI)·고객 노출 문구 변경 없음.
