# Findable 회원가입·온보딩 최신 플로우

## 원칙

- 회원가입 화면은 계정 인증만 맡는다. 브랜드명·도메인·업종을 한꺼번에 묻지 않는다.
- 워크스페이스 이름은 내부 회사/팀 이름이고, 공개 브랜드명과 분리한다.
- 브랜드 설정은 도메인부터 시작하고 브랜드명은 자동 제안 후 사용자가 확인한다.
- 측정 성공 여부와 온보딩 완료 여부를 분리한다. 측정 실패·한도 초과가 재가입 루프를 만들면 안 된다.
- 각 중간 단계의 입력과 진행 위치를 저장해 다음 로그인에서 이어서 진행한다.

## 기본 여정

1. `/sign-up` — 이메일·비밀번호 또는 Google/Kakao/Naver로 계정 생성
2. `/welcome` — 활성 워크스페이스가 없으면 회사/팀 이름으로 워크스페이스 생성
3. 브랜드 1단계 — 도메인 입력 → 브랜드명 자동 제안 → 이름 확인 → 측정 시작
4. 브랜드 2단계 — 타깃 시장 자동 추정 확인
5. 브랜드 3단계 — 한글·영문 별칭 확인(선택)
6. 브랜드 4단계 — 경쟁사 자동 제안 확인(선택)
7. 브랜드 5단계 — 설정 요약 및 완료 → 대시보드

## 경우별 분기

| 경우 | 진입 후 처리 |
|---|---|
| 완전 신규 사용자 | 계정 생성 → 워크스페이스 생성 → 브랜드 설정 1단계 |
| 무료 진단 후 가입 | 무료 진단 이메일의 최근 완료 도메인을 1단계에 자동 입력 |
| 초대받은 사용자, 기존 설정 완료 조직 | 해당 조직 대시보드로 이동 |
| 초대받은 사용자, 아직 빈 조직 | 조직을 새로 만들지 않고 해당 조직의 브랜드 설정을 함께 진행 |
| 중간에 이탈한 사용자 | 저장된 `onboardingStep`부터 재개 |
| 측정 시작 성공 | 설정을 끝내는 동안 백그라운드 측정, 완료 후 대시보드 |
| 24시간 한도 초과 | 브랜드 설정은 계속 저장, 완료 후 기존 결과 안내 |
| 측정 시작 실패 | 브랜드 설정은 계속 저장, 완료 후 대시보드에서 재시도 안내 |
| 온보딩은 완료했지만 측정 데이터 없음 | `onboardingCompletedAt` 기준으로 재온보딩하지 않음 |
| 기존 고객(Tracking 보유) | 새 온보딩 필드가 없어도 기존 측정 이력으로 즉시 통과 |
| 새 워크스페이스로 전환 | 그 워크스페이스의 독립적인 온보딩 상태에 따라 분기 |

## 입력 책임

| 화면 | 필수 입력 | 선택 입력 |
|---|---|---|
| Clerk 회원가입 | 계정 인증 정보 | 소셜 로그인 제공사 선택 |
| 워크스페이스 생성 | 회사/팀 이름 | 없음 |
| 브랜드 1단계 | 도메인, 확인된 브랜드명 | 없음 |
| 브랜드 2단계 | 자동 추정값 확인 | 타깃 시장 수정 |
| 브랜드 3단계 | 없음 | 별칭·영문 표기 |
| 브랜드 4단계 | 없음 | 경쟁사 추가·삭제 |
| 퍼블리싱 설정 | 없음 | 뉴스레터, 고객 전용 도메인 |

고객 전용 블로그 도메인은 회원가입 관문이 아니다. 먼저 기본 `findable.co.kr` 주소에서 발행할 수 있고, 실제 운영 도메인이 준비됐을 때 `인사이트 → 퍼블리싱 설정`에서 연결한다.
