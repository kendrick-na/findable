## 0. 질문과 결론 (30초)

사용자 질문(2026-07-31): *"로그인 없이 무료 진단은 몇 개까지 제한? 어떻게 작동?
IP 제한 가능한가? 아니면 더 좋은 방식 있는지 서치해. **원가가 너무 비싸잖아.**"*

**결론: IP 레이트리밋은 원가 방어책이 아니다.** 어뷰저는 1,000~10,000배 싸게 우회하고,
정작 우리 B2B 고객(회사 NAT)이 막힌다. 진짜 답은 **도메인 단위 캐시 + 전역 지출 상한 + 건당 원가 절감**
— 셋 다 로그인이 필요 없다.

**레버리지 순서**: ①도메인 캐시 → ②전역 일일 상한 → ③건당 원가 절감 → ④봇 차단(BotID/Turnstile) → ⑤IP는 보조 신호로만

## 1. 우리 현황 (실측 — 코드 기준)

| 항목 | 실측값 | 위치 |
|---|---|---|
| 무료 진단 1건 호출 수 | **7 엔진 × 4 프롬프트 = 28 LLM 호출** | `runner.ts` D-058 주석 |
| 건당 원가 | **약 150~300원** (~$0.12–0.20) | `packages/ai/lib/engines/cost.ts` |

### 원가 구조 (cost.ts 실측)
- **과금 엔진**: chatgpt($2.5/$10 per 1M), claude($3/$15), perplexity($1/$1), hyperclova($0.4/$1.2), naver(hyperclova 준용)
- **무료 엔진**: gemini(무료티어 1,500/일), daum(스크랩), chatgpt-web(웹UI 미과금)
- **browser 과금**: naver-briefing = Browserbase $0.1/분
- 환율 `USD_TO_KRW = 1380`
- ⚠️ 단가는 2026-07 추정 → **실제 청구서로 보정 필요**(cost.ts 주석)

### 🔴 리서치 중 발견된 우리 레포 결함 4건 (중요)
1. **비싼 엔드포인트에 Arcjet 보호가 0.** `api/audit/route.ts` 헤더 주석은
   *"어뷰즈 방지는 v1.0.5에서 BotID + rate limit 강화"* 라고 적혀 있는데 **그게 안 들어왔다.**
   `packages/security`가 `secure()`(shield+detectBot)를 export 하는데 `/api/audit`은 호출하지 않음.
2. **`ipAddress`는 이미 저장 중인데 아무도 읽지 않는다.** (스키마 주석: "어뷰즈 방지 (rate limit)")
   → IP 로직 추가에 **마이그레이션 불필요**.
3. **도메인 캐시가 없다.** `checkUsageGate`는 email+domain 으로 **차단만** 하고,
   있는 `result` JSON 을 **재사용하지 않는다.** → 최대 레버리지 지점.
4. **`@repo/rate-limit`(Upstash)은 설치됐으나 프로덕션 미작동.**
   `vercel env ls` 실측: `UPSTASH_REDIS_REST_URL`·`ARCJET_KEY` **둘 다 없음.**
   → 이걸 쓰는 **문의 폼(`contact.tsx`)도 지금 무방비**.

## 2. IP 레이트리밋 — 주 방어선으로는 부적합 **[확인]**

### 양방향으로 실패한다

**① 실고객을 막는다**
- **RFC 6269 §13.1** (IETF, 대규모 주소공유 문제) 원문:
  > *"In the presence of widespread large-scale address sharing, penalty box solutions to service abuse simply will not work."*
  — 우리가 검토한 "penalty box"를 이름까지 똑같이 지목한다.
- **Cloudflare (2025-10)** 실측: *"CGNAT IPs are subject to rate limiting **three times more often** than non-CGNAT IPs"*
  — 그런데 봇 비율은 통계적으로 동일(4.8% vs 4.7%). **3배는 순수 오차단.**
- **Microsoft NAT 가이드**: 회사 IP 1개 뒤에 **~6,000 대**.
  → 6,000명 회사에서 첫 사람이 하루 할당량을 태우면 나머지 5,999명은 벽을 보고 조용히 떠난다.
  ⚠️ **우리 ICP가 정확히 회사 NAT 뒤의 인하우스 마케팅팀이다.**

**② 어뷰저는 거의 안 막힌다**
- 주거용 프록시 시세: **IPRoyal "from $1.75/GB"**(64M+ 풀), Bright Data 400M+ IP,
  회색시장 바닥 **$0.29/GB**(Lumen Black Lotus Labs).
- **IPv6는 공짜 우회**: 전체 주소로 제한하면 일반 가정 /56 회선이 **2^64 버킷**을 낸다.
  (Cloudflare 하한 /64, Let's Encrypt /48)
- **Vercel WAF 문서**: *"Rate limit counters are tracked on a **per-region basis**"*
  → 분산 호출자는 리전 수만큼 한도를 곱한다.
- **Arcjet 문서 자체 경고**: IP는 *"can be shared by many users or changed by an attacker."*

**[추정]** 비용 비대칭 ~1,000–10,000배 (요청당 50KB 가정한 자체 산술 → 인용 통계 아님).
**[확인필요]** "IP 제한이 어뷰징 N% 차단" 류의 권위 있는 수치는 **찾지 못했다.**
Imperva 21% 주거프록시 비중은 *면역 트래픽의 하한*이고 2차출처(Thales)로만 확인.

## 3. 경쟁사 실태 — **아무도 우리가 검토한 방식을 안 쓴다** **[확인]**

| 도구 | 로그인 | 이메일 | 무료 한도 | 전달 |
|---|---|---|---|---|
| **Semrush** AI Search Visibility | ❌ | ❌ | **"three times per day… without registering"** | 즉시 |
| **Ahrefs** AI Visibility Checker | ❌ | ❌ | "No signup, no credit card, **no limit**" | 즉시 |
| **Geoptie** | ❌ | ❌ | "No signup required" | 즉시 |
| **HubSpot** AEO Grader | ❌ 계정불필요 | 전체리포트만 | "free, **one-time** check", 3엔진 | 즉시+리포트게이트 |
| **Profound** 무료리포트 | ❌ | ✅ **이메일=전달수단** | 미공개 | **이메일 비동기** |
| Peec / Otterly / Scrunch | ✅ | — | **무료 없음** — 7일 트라이얼 | 대시보드 |

**핵심 3가지**
1. **최대 경쟁사 2곳(Semrush·Ahrefs)은 아무것도 요구하지 않는다.** Semrush는 상장사인데
   익명 레이트리밋 모델을 그대로 쓴다.
2. **로그인 벽이 있는 곳은 무료 체커가 아예 없다** — 엔터프라이즈 세일즈(다른 전략).
3. **"결과 보려면 이메일 인증" 방식을 쓰는 투자받은 경쟁사는 0곳.**
   → 우리가 그걸 하면 업계 유일이 된다(좋은 의미가 아님).

**[추정]** 도메인 캐시를 공개적으로 문서화한 경쟁사는 없음. 가장 가까운 건 Semrush
*"updates key AI visibility data daily"* → 무료 체커가 라이브 호출이 아니라 캐시를 읽는다는 강한 암시.

## 4. 이메일 인증 — 가장 나쁜 선택 **[확인]**

- **GetResponse (n=27.6억 통)**: single opt-in **1.28%** vs double opt-in **0.33%**
  → 인증은 **이미 동의한 사람의 ~75%를 잃는다.**
- 낙관적 실무 범위(50~70% 확인)로 봐도 **리드의 30~50%가 리포트를 못 본다.**
- **원가를 못 막는다** — 일회용 메일함도 인증 링크를 잘 클릭한다.
- 일회용 메일 비중은 생각보다 작다: **ZeroBounce(110억+ 주소, 2025) 기준 1% 훨씬 미만.**
- **Apple Hide My Email**: 2026-06부터 전용 `@private.icloud.com` 으로 이동
  → **도메인 룰 1개로 차단 가능**(인증보다 싸고 효과적).

**⚠️ 폴클로어 주의 (검증 실패)**
- "폼 4→3 필드 = +50% 전환"은 **HubSpot 원문에 없다**(40,000페이지 상관관계 연구, 수치 미공개).
- Unbounce 자체 데이터는 **U자 곡선** — *"ten form fields actually saw greater conversion rates than three."*
  → **필드 수 통계 위에 설계하지 말 것.**
- 돈을 더 벌게 한 증거가 있는 게이트는 **신용카드**뿐(ChartMogul n=200: 가입 −22%, 유료고객 ~3배)
  — 단 이건 유료전환 결정이고 무료도구 결정이 아니다.

## 5. 원가를 구조적으로 낮추는 패턴 — **여기가 진짜 답** **[확인]**

### (a) 대상(도메인) 기준 캐시 — 가장 강한 선례 ⭐
- **Mozilla HTTP Observatory** 문서 원문:
  > *"the HTTP Observatory will return a **cached** site result if the site has been scanned anytime in the previous **24 hours**"*
  > + 하한: *"a site can not be scanned at a frequency greater than every **three minutes**."*
- **SSL Labs**: 호출자가 신선도를 선택(`fromCache`, `maxAge` 시간 단위),
  결과는 *"stay in the cache for as long as there's sufficient room."*

**핵심 통찰: 우리 원가는 요청 수가 아니라 서로 다른 도메인 수에 비례한다.**
→ 도메인 캐시를 켜면 **이메일 우회 공격이 경제적으로 무의미해진다.**
  (이메일 50개로 같은 도메인을 물어도 원가는 1회분)
→ **CGNAT 문제도 동시에 해결** — 캐시 공유는 버그가 아니라 기능이다.

### (b) 엔진 수를 게이팅(갱신주기는 게이팅 X)
- **Profound 사다리**: Starter $99 = **ChatGPT만** / Growth $399 = **3엔진** / Enterprise = 최대 9엔진
- **Otterly**: 엔진 낱개 판매(Claude +$29~439/월)
- ⚠️ **반대 발견**: **갱신주기를 게이팅하는 경쟁사는 없다** — 전원 입문요금제부터 daily 광고.
  → **갱신주기 게이팅은 경쟁 열위**가 된다.
  (⚠️ 우리는 `autoRefreshHours` 로 free=null/starter=168h/growth=24h 게이팅 중 → **재검토 필요**)

### (c) 무료엔 값싼 모델
- **Anthropic**: *"Free includes Haiku and Sonnet; Pro and Max adds Opus, Fable."*
- **HubSpot 무료 grader는 "GPT-5.4 mini"** 사용 — 의도적으로 mini 티어.
- **스택 가능한 API 레버(전부 1차 문서 확인)**:
  - Anthropic **prompt caching = 읽기 0.1배(90% 할인)**
  - Anthropic **Message Batches = 50% 할인**
  - OpenAI **Batch = "50% cost discount"**, 24시간 내 완료

### (d) 비동기 이메일 전달
- **Prismic** 무료 GEO 감사: ChatGPT·Claude·Gemini에 *"**40 times each**"* (~120 호출 — 우리의 4배)
  + *"**Your report arrives via email**."*
- 비동기가 **batch 50% 할인을 가능하게 하는 전제**다.

### (e) 점진적 결과
- **Ahrefs**: 무료는 *"top **20** backlinks"*, 무료계정은 1,000개 → **50배 사다리**.
  가입이 벌이 아니라 **보상**이 되는 구조.

## 6. 봇·어뷰징 도구 현황 **[확인]**

| 도구 | 가격 | 우리 적합성 |
|---|---|---|
| **Vercel BotID** Basic | **전 플랜 무료** | ⭐ 최적. Deep Analysis=**$1/1000 호출**($0.001 → 건당 원가의 **0.5~0.8%**) |
| **Cloudflare Turnstile** | 무료(위젯20·호스트10) **"Unlimited challenges"** | ⭐ **Cloudflare 경유 불필요** — Vercel에서 작동 |
| **Arcjet** | ⚠️ **무료플랜 사라진 듯**. Individual $25/월~, "free 15 day trial" | 설치돼 있으나 키 없음 |
| **Upstash 무료 deny list** | rate-limit 패키지에 포함 | `enableProtection: true` + ipsum 30개 리스트 일일갱신 |
| **Vercel WAF** | 전 플랜 rate-limit 룰(Hobby 1룰) | 차단 트래픽은 **과금 안 됨** |

- **BotID 문서가 우리 케이스를 이름으로 지목**: *"**Expensive resources**: Prevent bots from consuming expensive infrastructure."*
- ⚠️ **BotID 함정**: 클라이언트에 등록 안 하면 `checkBotId()` 실패 / dev에선 항상 `isBot:false` /
  **프로덕션에서 curl·직접 접근을 막는다** → 정상 프로그램 호출자도 깨진다.
- ⚠️ **Arcjet 위험**: rate limit은 클라우드 호출 필요(*"Client state must be tracked across requests"*) +
  **기본이 fail-open** → 트라이얼 만료 시 **설치된 SDK가 조용히 무력화**될 수 있다.
- ⚠️ Arcjet 문서: *"Avoid passing personal information such as an email address as a custom characteristic."*
  → 이메일을 레이트리밋 키로 쓰지 말 것.
- ⚠️ Upstash 기본 `timeout` 도 **fail-open** → 비싼 라우트엔 명시 설정 필수.
- **[확인필요]** Turnstile "1M siteverify/월" 상한은 **Cloudflare 가격표에 없다** → 폴클로어로 취급.

## 7. 권고안 (레버리지 순)

1. **도메인 단위 캐시** (Observatory 방식: 24h + 3분 하한).
   원가를 요청당 → 도메인당으로 전환. **이메일 우회를 무력화.** 마이그레이션 불필요(`result` JSON 이미 있음).
2. **전역 일일 지출 상한** — 어뷰저가 로테이션으로 우회할 수 없는 **유일한** 통제.
   (경고 사례: Recipe Ninja — 한 유저가 같은 레시피 12,000회, **$700 청구**)
3. **건당 원가 절감**: 무료는 엔진 수 축소(Profound 사다리) + mini 모델(HubSpot 선택) +
   prompt caching(90%) + batch(50%) 스택.
4. **Vercel BotID**(무료/0.5~0.8% 오버헤드) 또는 **무료 Turnstile** 로 자동화 차단.
5. **IP는 보조 신호로만** — 절대 신원으로 쓰지 말고, IPv6는 절대 /128 단위로 세지 말 것.

**L-1 재프레이밍(리서치 최종형)**:
> **가치를 *보는* 데 로그인을 요구하지 말고, *비싼 엔진을 소모하는* 데 요구하라.**
> 익명에게는 캐시·프리뷰 결과를 주고(SEO 논거 유지), **재측정·추적·이력**이라는
> 두 번째 상호작용을 게이팅한다 — 이미 가치를 본 뒤라 전환 저항이 낮다.
