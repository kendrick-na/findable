# 안정성 플래그 켜기 순서 + 알려진 한계 (2026-10-18)

## 알려진 한계 (입장 관리 켠 뒤에만 해당)

### 위험 1 — 이어가기 예약이 순번을 뒤로 민다
- 현상: 슬롯 예약(`reserveSlot`)이 `attemptStartedAt`을 현재 시각으로 덮어쓴다. 이어가기 대기는 `attemptStartedAt` 오름차순으로 뽑으므로, 예약됐다가 TTL(90초) 안에 시작하지 못해 풀린 건은 줄 맨 뒤로 간다.
- 영향: 경합이 잦을 때 일부 이어가기가 한 번 정도 더 늦게 처리될 수 있다. 이어가기 시간창(2시간) 안에서는 보통 흡수된다. 유실·중복은 없다(리스 토큰 펜싱 그대로).
- 대응: 코드 변경 없음. 켠 뒤 「이어가기 대기 평균 대기 시간」을 관찰해 시간창 만료(저장된 답으로 잠정 마감)가 늘면, 예약 때 `attemptStartedAt`을 덮지 않고 별도 표식만 쓰는 방식으로 바꾼다(작은 수정, 시험 먼저).

### 위험 2 — 일꾼이 자리 없음이면 바로 끝낸다(no_room 조기 반환)
- 현상: 일꾼 1회(cron 1회)는 후보 1건만 골라 `reserveSlot`을 시도하고, 실패하면 다른 후보를 보지 않고 `no_room`으로 끝난다.
- 영향: 시작 경로와 일꾼이 같은 자리를 두고 자주 경합하면 그 분의 처리량이 줄고 다음 분으로 넘어간다. 일꾼이 매분 도는 한 대기 건은 최대 1분 단위로 지연될 뿐 유실되지 않는다.
- 대응: 코드 변경 없음(실제로 자리가 가득 찬 경우 다른 후보도 어차피 못 들어가므로 손해는 고객별 상한으로 막힌 후보를 건너뛰는 경우에 한정). 켠 뒤 `no_room` 비율이 높으면 「실패 시 다음 후보 1회 재시도」를 추가한다.

## 꺼짐 보장
- 입장 관리·일 상한 플래그가 꺼져 있으면 `start-gate`가 DB/플랜 조회를 하지 않고, `$transaction`·잠금·예약·점유 수 조회가 한 번도 호출되지 않는다(`audit-queue-start.test.ts` 「꺼짐 동일성」·「입장 관리만 꺼진 경우」가 직접 단언).
