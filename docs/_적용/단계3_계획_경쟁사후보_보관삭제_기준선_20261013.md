## 1. 경쟁사 후보 사후 제안 (원칙 2)
- **무엇**: 측정 결과에서 우리와 **같이 자주 언급된 브랜드**를 경쟁사 후보로 보여 준다(Peec: 2회 이상 · Scrunch Signals 방식).
- **재료**: 저장된 AI 답변을 다시 읽는 기존 코드 `extractCompetitorLandscape`(`packages/audit/competitor-extract.ts`) — 원가 0, 새 AI 호출 없음.
- **규칙**: 후보는 **기본 미선택**, 사람이 누른 것만 `Brand.competitors`에 저장(`updateBrandProfile`, 기존 정규화 재사용). 자동 저장 금지(Otterly 오분류 사고 반면교사). 이미 등록·'없음' 선택한 브랜드는 후보에서 제외하거나 '없음' 해제 안내.
- **화면**: 브랜드 카드/프로필 편집기 옆 「이런 브랜드가 함께 언급됐어요 (최근 N회 중 M회)」 + [추가] 버튼. 새 화면을 만들지 않고 프로필 편집기에 한 블록 추가.
- **테스트**: 2회 미만 제외, 우리 이름·별칭 제외, 이미 등록한 경쟁사 제외, 저장은 사람이 누른 항목만.

## 2. '비교 기준 없음' 표시 (원칙 2)
- 경쟁사 상태가 `unset`/`none`이면 경쟁 점유율·순위 지표를 **비우고** 「비교 기준 없음」을 표시한다(0으로 그리지 않는다).
- 판정은 이미 있는 `competitorSettingOf`(setup-readiness) 한 곳. 대시보드·리포트가 같은 값을 쓰는지 [확인 필요: 경쟁 지표가 그려지는 모든 위치 목록은 구현 전에 조사].
- 문구는 사전(ko·en) 추가 — 대표 승인 대상.

## 3. 질문 보관/삭제 (원칙 3)
- **원칙**: 변경 = 삭제가 아니라 **보관 + 새 질문**(이력 유지). 삭제는 이력 소실을 경고. 수정은 '새 질문으로 저장'.
- **현재**: `Prompt`에 보관 필드가 없다. 삭제·수정 액션(`delete-prompt.ts`, `edit-prompt.ts`)이 이미 있고, 측정 이력(`Tracking`)은 `promptId`에 묶여 있다.
- **결정 필요(대표)**:
  | 안 | 운영 DB 변경 | 판단 |
  |---|---|---|
  | A. `Prompt.archivedAt DateTime?` 컬럼 추가 | 필요(마이그레이션 파일은 개발이 작성, 적용은 대표) | ⭐ 추천 — 의미가 분명하고 이력·할당량 계산을 명확히 구분 |
  | B. `isAutoGenerated=false`로 돌려 '보관' 흉내 | 불필요 | 기본 질문(시스템) 구분과 뜻이 섞여 혼란 |
- 보관된 질문은 러너 선택·질문 세트 지문·플랜 상한(남은 칸) 계산에서 빠지고, 시계열 선은 남는다.
- 삭제 화면: 「삭제하면 이 질문의 측정 이력도 사라져요. 보관하면 이력은 남아요」 + 기본 버튼은 보관.

## 4. 기준선 표시 + 변경 이력 (원칙 4)
- **표시**: 질문 세트가 바뀌어 직전 대비·추세가 막힌 회차에 「질문이 바뀌어 비교할 수 없어요. 여기서부터 새 기준선이에요」. 막힘 판정은 이미 있는 비교키(`+qs:`, `+q:`)와 `searchSamplingChangeLabel`·`comparisonBlockedReason` 재사용.
- **변경 이력 로그**: 질문 추가·보관·삭제·수정을 시각·행위자와 함께 남긴다. 저장 위치 [확인 필요: 기존 `Annotation` 모델을 쓸 수 있는지 / 새 테이블이 필요한지 조사 후 결정]. 새 테이블이 필요하면 마이그레이션이므로 대표 결정 사안.
- **경고**: 질문을 바꾸기 직전에 「이 변경으로 지금까지 점수와 비교할 수 없게 돼요」 안내(확인 후 진행).
