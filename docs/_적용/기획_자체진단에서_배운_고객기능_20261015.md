# 기획 — 자체 진단에서 배운 고객사 기능 (2026-10-15)

> 상태: **기획안(미승인)**. 코드·화면은 이 문서 승인 전에 만들지 않는다. 측정 로직·질문 생성 코드는 영업 베이스라인 동결 중이라 **동결 해제 후** 착수한다.
> 표기: [관찰] 오늘 직접 확인 / [가설] / [확인필요]. 실적·고객 수·수상 같은 새 사실은 쓰지 않는다.

## 1. 왜 이 기획인가 (한 줄)

**GEO 서비스인 Findable도 자기 문제를 처음엔 못 잡았다.** 고객사는 우리보다 훨씬 더 같은 함정에 빠지고, 그때 우리 제품은 "0%입니다"라고만 말해 줄 위험이 있다. 이번에 직접 겪은 사각지대를 제품 기능으로 바꾼다.

## 2. 우리가 겪은 사각지대 → 고객 상황 매핑

| # | 우리 사례 [관찰] | 고객사에서 일어날 일 | 지금 제품 상태 |
|---|---|---|---|
| A | 측정이 ChatGPT를 **웹검색 없이** 돌려 "안 나온다"로 보임(출처 0/113). 같은 질문을 화면에서 하면 추천됨 | 신규 브랜드 고객이 진단 결과 "ChatGPT 0%"를 보고 **오진·불신·환불** | 결과에 측정 조건 구분 없음 |
| B | "이름 있는 질문"만 측정, "이름 없이 추천해줘" 질문 17개는 결과 0건 | 인지도는 있는데 추천 후보엔 없는 상황을 못 봄 | 질문 체계는 있으나 결과 해석에서 분리 부족 [확인필요] |
| C | 이름 충돌: 영문 "Findable" 단독어에서 동명 서비스에 밀림, 한글 "파인더블"은 호텔·동명 회사·동명 GEO 업체 | **흔한 단어형 상호**, 동명 업체가 있는 고객 | 이름 충돌을 진단하는 기능 없음 |
| D | 구글이 중요 페이지 29개를 "크롤링됨-색인 안 함"으로 보류 | **신규 도메인** 고객 다수 | Search Console 연결은 있으나 색인 상태 진단은 없음 |
| E | 테스트 발행처·옛 이름("OAuth Verification")·`app.` 서브도메인이 외부에 노출 | 스테이징·테스트·로그인 서브도메인이 색인되는 고객 | 사이트 점검 18개 항목은 **홈 한 페이지** 기준 |
| F | 사이트맵 안의 테스트 주소, 영어 링크가 국가별 307, 한/영 짝(hreflang) 깨짐, 글 안 404 링크 | **다국어 사이트** 고객 | 사이트 전역 위생 점검 없음 |
| G | 브랜드 이름을 바꾼 뒤 **질문 문구·발행처 이름은 옛 이름 그대로** | 상호 변경·리브랜딩 고객 | **제품 자체 결함**(이름 변경 전파 없음) |
| H | 엔진별로 결과가 갈림: ChatGPT(개인화 계정)는 추천, 구글 AI 모드는 미인지 | 한 엔진 결과로 전체를 판단 | 엔진별 결과는 있음, 해석 가이드는 약함 |
| I | 외부 출처(언론·위키·Medium·LinkedIn)가 이미 있는데 우리 스스로도 못 봄 | "출처가 없다"고 오해 | 출처 빈틈 분석(경쟁사 비교)은 있음 |

## 3. 핵심 신규 플로우 — "0% 진단서" (F0, 가장 중요)

**문제**: 진단 결과가 낮을 때 고객은 "서비스가 안 좋은가 / 내가 망했나"를 모른다. 우리도 오진했다.

```
진단 완료 → 결과가 낮음(예: 언급률 하위 구간 / 일부 엔진 0%)
   ↓ 자동으로 "왜 낮은가" 4단계 분해 카드
   ① 측정 조건: 웹검색 사용 여부 · 이름 포함/미포함 질문 분리 · 엔진별 · 반복 횟수 · (개인화 없음 표시)
   ② 이름 충돌: 이름 단독 / 이름+분야 / 이름+도메인 질의 결과의 동명 비율
   ③ 색인·접근: 검색 도구 색인 상태, noindex·robots, 사이트맵 위생
   ④ 외부 출처: AI가 대신 인용하는 출처 vs 우리를 언급하는 출처
   ↓ 가장 큰 병목 1개를 "먼저 할 일"로 제시 → 처방 → 재측정 일정
```
- 효과: 낮은 점수를 **원인이 있는 문제**로 바꾼다. 환불·불신 방어, 컨설팅 연결, 재측정 유도.
- 이번 사례가 템플릿이다(우리 사이트 = 첫 번째 사례, 우리 숫자는 공개 전 대표 승인).

## 4. 기능 목록

| ID | 기능 | 해결하는 사각지대 | 핵심 동작 | 기존 자산 활용 | 우선순위 |
|---|---|---|---|---|---|
| **F1** | **측정 신뢰도 표기·분리 리포트** | A·B·H | 결과마다 "웹검색 사용/미사용", "이름 포함/미포함", "엔진", "반복 N회", "측정일" 배지. 이름 있는/없는 질문 점수를 **합치지 않고** 분리 표시. 웹검색 켠 ChatGPT 측정 옵션(비용 별도: 코드 주석상 웹검색 호출 1,000회당 약 10달러) | 질문 계획 v2, `cost.ts` 비용 구조 | **P0** (동결 해제 후) |
| **F2** | **이름 진단(Brand Identity Check)** | C·I | 이름 단독/+분야/+도메인/한글·영문 표기별 검색·AI 응답에서 동명 후보 탐지 → "충돌 위험 상/중/하" + 처방(첫 화면 라벨 문장, Organization 구조화 데이터, sameAs, 표기 통일 문장). 검색 수집은 **공식 검색 API만** [확인필요: 약관] | `entityVariants`, 공식 사이트 정체 확인(`official-site-identity`) | **P0** |
| **F3** | **색인 건강 점검(Index Health)** | D | Search Console 연결로 "크롤링됨-미색인 / 발견됨-미색인" URL 목록 가져와 **원인 분류**(잡주소·테스트·중복·얇음·신규 신뢰). 같은 주제 글끼리 겹침(카니발라이제이션) 표시. 처방 우선순위 + 재요청 안내 | `SearchPerformanceConnection`(구글 연결), `SearchPerformanceDaily` | **P1** |
| **F4** | **사이트 위생 스캐너(Site Readiness v2)** | E·F | 홈 1페이지 → **사이트맵 전체 순회**: 상태코드(200/301/404), noindex 누수, 서브도메인·테스트 주소 노출, 내부 링크 307/404, hreflang 쌍 대상 검증, JSON-LD 검증(@id·sameAs 도달성·화면 일치), apex/www/http 정규 체인, robots 패턴 오탐(예: 언어별 경로 누락), 사이트맵 lastmod 유효성 | 현재 18개 점검(`https·robots·aiBots·sitemap·canonical·jsonLd·llmsTxt …`), PageSpeed 패널 | **P1** |
| **F5** | **브랜드 변경 전파 가드** | G | 브랜드 이름·표기 변경 시: 저장된 질문 문구·발행처 이름·구조화 데이터 설명에 **옛 이름이 남았는지 스캔** → "n개 갱신" 제안/자동 갱신. 변경 직후 재측정 권유 | 브랜드·질문·발행처 모델 | **P0** (제품 버그 방지, 코드 작음) |
| **F6** | **발행 플랫폼 가드레일** | E·F | ① 확인 안 된 발행처 비노출 기본(**이번에 구현**) ② 발행 전 **주제 중복 경고**(기존 글과 유사도) ③ ko/en 번역 쌍을 **글 단위로 연결**(슬러그가 달라도 hreflang 자동) ④ 발행 전 링크 검사(404·접두사 없는 링크) ⑤ 확인 안 된 수치·수상 문구 경고 | `ContentQualityCheck`, `ContentRevision`, 발행 Job | **P1** |
| **F7** | **엔진별 상태판·플레이북** | H | 한 브랜드의 ChatGPT·구글 AI 모드·Perplexity·네이버 AI 브리핑 상태 매트릭스 + 엔진별 처방(예: 해당 서비스 검색 크롤러 허용 확인, 네이버 서치어드바이저·RSS 제출) | 엔진별 측정, `aiBots` 점검, 실행 플레이북 | P2 |
| **F8** | **외부 출처 지도(Source Map)** | I | AI가 인용하는 출처 + 우리 브랜드를 언급하는 제3자 출처(언론·위키·디렉터리·계정)를 한 지도에 표시. "이미 있는 것/없는 것" 구분 | 출처 빈틈 분석(`AnswerBrand`), 질문·출처 유형 분류 | P2 |
| **F9** | **Findable on Findable (자기 점검)** | 전체 | 우리 사이트를 위 기능으로 **매주 자동 점검**해 결과를 사례·문서로 축적. 내부 품질 게이트 + 영업 근거 | 일일 헬스체크 스케줄 | P1 (F4와 동시) |

## 6. 제약·위험

| 항목 | 내용 |
|---|---|
| 베이스라인 동결 | F1·F5는 측정·질문 코드를 건드리므로 **동결 해제 전 착수 금지** |
| 비용 | 웹검색 켠 측정은 호출당 비용이 큼(코드 주석 기준 1,000회당 약 10달러). 플랜별 허용 횟수 정책 필요 |
| 약관·법 | 검색결과 수집은 **공식 API만**. 구글·네이버 화면 긁기 금지 [확인필요: 각 약관]. 사이트 순회는 robots.txt 준수, 호출 속도 제한 |
| 개인정보 | Search Console·GA4 연동 데이터는 고객 조직 단위로 격리(기존 원칙). 토큰은 암호화 저장(기존 구조) |
| 오진 위험 | 진단서가 "원인"을 단정하면 이번 우리 실수의 반복이다 → **관찰/가설을 화면에 구분 표기**(이번 문서와 같은 규칙) |
| 사실 규칙 | 우리 사례를 영업에 쓸 때 수치·성과는 **대표 확인본만** |

## 7. 성공 지표 (제안)
- 낮은 진단 결과 후 **재측정까지 이어진 비율**
- "0%" 결과에 대한 문의·환불 요청 건수 감소
- 진단서에서 제시한 "먼저 할 일" 실행률
- 이름 충돌·색인 보류를 사전에 잡아낸 건수

## 8. 결정 4가지 — 대표 위임으로 Claude가 정한 안 (2026-10-15)

대표님이 "다 직접 하라"고 위임하셨다. 아래는 **제 판단과 근거**이며, 바꾸고 싶으면 언제든 뒤집을 수 있다.

| # | 쟁점 | 결정 | 근거 |
|---|---|---|---|
| 1 | F0 "0% 진단서"를 1순위로 | **예** | 우리가 낮은 측정값을 원인 분해 없이 믿어 오진했다. 고객은 더 크게 겪는다. 환불·불신을 막는 가장 싼 방어이자 컨설팅 연결 지점 |
| 2 | 웹검색 켠 측정 비용 | **웹검색 측정을 기본으로 하되 플랜별 월 횟수 상한 + 초과분은 옵션** (구체 횟수는 원가 계산 후 확정 [확인필요]) | 웹검색이 꺼진 ChatGPT 측정은 신규 브랜드를 구조적으로 낮게 본다. 끄고 파는 것이 더 위험. 비용은 코드 주석 기준 1,000회당 약 10달러라 상한이 필요 |
| 3 | 우리 사이트 사례 외부 공개 | **지금은 보류, 내부 사용만.** 2~4주 추적 후 "개선 전·후" 자료가 생기면 대표 확인본으로 공개 | 아직 개선 결과가 없고, 약점 수치를 먼저 공개하는 것은 영업·심사에 불리. 사실 규칙상 대표 확인 전 외부 공개 금지 |
| 4 | 이름 진단에서 검색 수집 | **공식 검색 API만 사용** | 화면 긁기는 약관 위험. 범위가 좁아지는 대신 안전 |

### 같은 날 확인된 숫자 문제 (F0·F9와 연결)
홈 공개 카운터의 "진단 완료 424"는 **대표님 본인·팀·QA 계정의 진단 322건(76%)을 포함**했다. 외부(무료 진단 64 + 타 조직 38)는 **102건·33개 도메인**. 카운터에서 팀·테스트 조직을 제외하고 "추적 브랜드"를 "진단한 도메인"으로 정정했다(커밋 `cd8ad9b4`, 푸시 대기). 같은 원칙(외부 제출에서 부풀려 읽히는 숫자 금지)을 제품 전체의 공개 숫자 규칙으로 삼는다.
