## 3. ③ 브랜드 등록 — 재설계

### 3-a. 지금 / 바뀔 것

| | 지금 | 바뀔 것 |
|---|---|---|
| 필수 입력 | 브랜드명 + 도메인 **2개** | **도메인 1개** |
| 등록 버튼 문구 | `브랜드 등록` | **`등록하고 측정 시작`** |
| 등록 후 | 🔴 아무 일 없음 → 측정 버튼을 또 찾아야 함 | **바로 측정 시작 → ④ 로 이동** |
| 브랜드명을 비우면 | 🔴 `"브랜드 이름을 입력해 주세요"` 로 거부 | 도메인에서 **자동 추론** |

### 3-b. 🔴 반드시 같이 처리할 것 (교차검증 조건)

**⑴ 측정 결과를 화면에 전달한다.**
지금 `assignBrandOwner` 는 `{ok:true} | {error}` 만 돌려준다. 측정이 한도에 걸려도 담을 자리가 없어
**"등록했어요" 만 뜨고 측정은 안 되는 조용한 실패**가 난다.
→ 반환을 `{ok, measurement: "started"|"rate_limited"|"failed", message?}` 로 넓히고 **토스트에 반영**한다.

| 측정 결과 | 사용자에게 보일 것 |
|---|---|
| `started` | *"측정을 시작했어요. 1~3분 걸려요."* → ④ 로 이동 |
| `rate_limited` | *"오늘은 이미 측정했어요. 내일 다시 측정할 수 있어요."* + 이전 결과 링크 |
| `failed` | *"측정을 시작하지 못했어요."* + 다시 시도 버튼 |

**⑵ 거짓이 되는 문구 6곳을 같은 커밋에서 고친다.**
- `assign-brand-form.tsx` — *"이제 **측정 시작을 눌러**…"*
- `brand/page.tsx` ×3 — *"아직 측정 전 — 측정 시작을 누르면…"* 등
- `dashboard-empty-state.tsx` — 3단계 설명
- 대시보드 CTA `측정 시작` → `/brand` 링크

⚠️ 코드 주석에 *"바로 측정을 시작할 수 있어요"* 를 **거짓이라 지웠다**는 기록이 있다.
이번 변경으로 그 문장이 **다시 참**이 된다 — 되살릴 때 그 주석도 갱신한다.

**⑶ 문구를 하드코딩한 테스트를 구조 검사로 바꾼다.**
`empty-state.test.tsx` 가 `"측정 시작하기"` 를 하드코딩해 검사한다 → 자동측정 후 이 문구는 거짓인데
**테스트는 통과한다**(가드가 거짓말을 지킨다). 문구가 아니라 **계약**을 검사하도록 고친다.

### 3-c. ⛔ 하지 않을 것

- 🔴 **확인 단계 화면 신설** — v1 의 §3-b. 언어 축이 무효라 **정직하게 만들 수 없다**.
  타깃시장도 측정 후 바꾸면 **분모가 갈려** 추세 그래프가 두 기준을 한 선으로 그린다.
- 🔴 **국가 드롭다운** — 우리 축은 국가가 아니라 엔진 지역이다.
- 🔴 **`resolveBrandIdentity` 를 등록 폼에서 호출** — LLM 호출이라 제출이 느려진다.
  **러너가 이미 부른다**(`runner.ts:230`) → 폼은 도메인만 저장하면 된다.

## 4. ④ 대기 화면 — 신설 ⭐

### 4-a. Profound 실측 (영상)

| 항목 | 측정값 |
|---|---|
| 배경 | 거의 검정 (RGB 15,15,17) |
| 내용 | **화면 정중앙**, 전체 높이의 **7%** 만 사용 |
| 구성 | 로고 + 도메인 **두 줄뿐** |
| 지속 | **약 2분 20초** |
| 진행 표시 | 🔴 **없음** |

⭐ 대표님이 *"토스 같다"* 고 한 이유 = **한 화면에 한 가지 · 압도적 여백**.

### 4-b. 🔴 그대로 베끼면 안 되는 이유

2분 20초 동안 **얼마나 남았는지 안 알려준다.** 멈춘 건지 도는 건지 알 수 없다.
닐슨 10 "시스템 상태 가시성" 위반이다(10초 넘는 작업은 진행 상황을 보여야 한다).

### 4-c. 우리 안 — 여백은 가져오고, 진행은 우리가 더 잘한다

```
              [ Findable ]

              indigochild.kr

        ChatGPT에게 물어보는 중…
        ●●●○○○○   3 / 7곳

        보통 2~3분 걸려요
```

- **여백·중앙 정렬·한 가지만** = Profound 에서 가져온다
- **엔진 진행 표시** = 우리가 이긴다. 7곳을 순서대로 도니 *"지금 몇 번째"* 를 정직하게 보여줄 수 있다
- **소요 시간 안내** = 불안을 없앤다

⚠️ **선행 확인 필요**: 러너가 진행 상황을 실시간으로 알려주는 구조인지, 끝나야 아는지.
실시간이 아니면 **단계 표시 대신 소요 시간 안내만** 넣는다(가짜 진행률은 만들지 않는다).

## 9. 🔴 이 설계로도 안 고쳐지는 것

1. **첫 결과까지 2~3분** — 7엔진 실시간이라 즉시 불가. Profound 도 24~48h 다.
2. **"왜 돈 내나"** — 이 설계는 온보딩·화면을 고칠 뿐이다. 답은 **알림 메일 스위치**(크론 완성·기본 꺼짐)에 있고 별건이다.
3. **죽은 컬럼 3개**(`competitors`·`entityVariants`·`language`) — 쓰는 것보다 **읽는 곳을 먼저** 만들어야 한다.
   ⚠️ 쓰기만 하고 안 읽으면 *"죽은 걸 못 죽은 것처럼 보이게"* 만들 뿐이다.
