# 공유 이미지(og:image) 점검 — 카톡 링크에 next-forge 그림이 뜨는 이유 (2026-10-16)

> 읽기 전용 점검. 코드·파일 수정 없음(새 이미지 승인 후). 표기: [관찰]=직접 확인

## 1. 결론
- **원인**: 사이트 기본 공유 이미지 `apps/web/public/opengraph-image.png`가 **next-forge 템플릿 그림**("Production-grade Turborepo template for Next.js apps")이다. 라이브 파일도 바이트·해시까지 같다 [관찰].
- **이미 한 번 고쳤다가 되돌아갔다**: 9/6 커밋 `4340d9aa`("replace template social preview image")가 Findable 브랜드 그림(「AI가 우리 브랜드를 먼저 답하게.」, 432KB)으로 교체했지만, **9/8 병합 `dc41bba0`("merge main for production release")과 PR #11 병합 `dcfcf2d7`(feature/login-branding)이 옛 템플릿 파일(58KB)로 되돌렸다** [관찰: 두 병합 커밋에서 파일 크기 432,263 → 58,106]. 9/6 교체본은 git 기록에 남아 있다(`git show 4340d9aa:apps/web/public/opengraph-image.png`).
- 영향: **글 대표 이미지가 없는 모든 페이지**(홈 `/`·`/ko`·`/en`, 요금제, 용어집, 인사이트 목록, 문의 등)가 카톡·페이스북·슬랙 공유 시 템플릿 그림. 글 대표 이미지가 있는 글(예: `what-is-geo-seo-vs-geo`)은 자기 이미지.

## 2. 이미지가 쓰이는 곳 [관찰]
| 위치 | 내용 |
|---|---|
| `packages/seo/metadata.ts` | 기본값: `image ?? ${siteOrigin}/opengraph-image.png`. og:image·twitter:image 둘 다 이 값. 페이지가 `image`를 넘기면(글 대표 이미지) 그 값이 이김 |
| `apps/web/public/opengraph-image.svg` | 9/6에 같이 추가된 Findable 브랜드 SVG 원본(1200×630). **어디서도 참조되지 않음**(메타는 PNG만 씀) |
| `app/[locale]/` 안 | 메타데이터 이미지 파일 없음(과거 빌드 오류로 `public/`으로 옮김) |
| `next-forge` 문자열 | 코드 주석뿐(sitemap·layout·contact-form·metadata). 사용자에게 보이는 곳 없음 |
| 파비콘·앱 아이콘 | `favicon.ico`·`icon.svg`·`apple-icon.png` 별도, 이번 문제와 무관 |

## 3. 페이지별 현황 [관찰]
| 페이지 | og:image | twitter:card | 선언 크기 |
|---|---|---|---|
| `/`·`/ko`·`/en`·`/ko|en/pricing`·`/ko/glossary`·`/ko/insights`·`/ko/contact` | `/opengraph-image.png`(템플릿) | summary_large_image | 1200×630 |
| 글(대표 이미지 있는 글) | `/images/insights/<글 이미지>` | summary_large_image | **1200×630으로 선언**(실제 이미지는 1672×941) |
| 소개 글 한/영 | 기본 그림(DB 연결 후 페이지 캐시 갱신 대기, 17:41 KST쯤 바뀔 예정) | summary_large_image | 1200×630 |
- 카드 종류는 전부 `summary_large_image`로 정상. 기본 이미지는 1200×630 PNG라 비율 정상.
- 낮은 우선순위 발견: 글 이미지의 선언 크기(1200×630)가 실제(16:9)와 다름. 카톡·페이스북은 실제 이미지를 읽어 대체로 문제없으나 정확히 하려면 메타 코드에서 실제 크기를 쓰도록 고칠 수 있음.

## 4. 교체 방식 제안 (의견)
| 방식 | 장점 | 단점 |
|---|---|---|
| A. 같은 파일명(`opengraph-image.png`) 덮어쓰기 | 코드 변경 없음 | 카톡·페이스북이 옛 그림을 **주소 기준으로 오래 캐시**, 공유 디버거로 페이지마다 재수집해야 함. 응답 헤더는 `max-age=0, must-revalidate`라 서버 쪽 문제는 없음 |
| B. 새 파일명(예: `og-default-v2.png`) + 메타 기본값 변경 | 주소가 바뀌어 **재수집 시 확실히 새 그림**, 되돌릴 때 이전 파일이 남아 비교 쉬움 | `packages/seo/metadata.ts` 한 줄 수정 필요 |
- **권장: B(새 파일명, 쿼리 없는 안정 주소) + 옛 `opengraph-image.png`도 같은 새 그림으로 덮어쓰기.** 새 주소로 재수집을 유도하고, 혹시 옛 주소를 아직 참조하는 곳에도 템플릿이 남지 않게 한다.
- 파일명에 버전을 붙이는 이유: 카카오·페이스북은 이미지 **주소**로 캐시한다. 쿼리(`?v=2`)는 일부 크롤러가 무시할 수 있어 파일명 변경이 더 확실하다 [추정].
- 이미지가 바뀐 뒤에도 **이미 공유된 카톡 방의 옛 미리보기는 그대로**일 수 있다(재전송 시 새로 수집). 카카오 디버거(developers.kakao.com 링크 미리보기 도구)·페이스북 공유 디버거에서 주요 주소(홈 `/ko`·`/`·요금제·소개 글)를 재수집하는 안내가 필요하다.
- 이미지 요건(대표 요청): 1200×630 PNG, 중앙 Findable 로고. 참고로 9/6 교체본은 좌측 정렬 「F.」 + 문구 구성이라 **카톡 정사각 크롭 시 잘릴 수 있음** → 로고를 가운데에 두는 대표 요청 구성이 안전하다.

## 5. 진행 순서 (제안, 승인 후)
1. IR덱 세션이 만든 시안(`Findable_공유이미지_20261016/og-findable-1200x630.png`)을 대표가 승인.
2. 이 세션: 파일을 `apps/web/public/og-default-v2.png`로 두고 + `opengraph-image.png` 덮어쓰기, `packages/seo/metadata.ts` 기본값을 새 주소로, 테스트·배포(대표 푸시).
3. 배포 후 한/영 홈·주요 페이지 og:image 확인, 대표에게 카카오·페이스북 디버거 재수집 안내.
