# 설계안 — G1 「내 브랜드 정보」(팩트시트) 1차 (2026-10-16)

> 상태: **착수 승인됨**(대표 "계속 착수해" ×3). 화면은 파일럿 스위치 뒤에 두고, 대표 테스트 후 전체 공개.
> 근거 문서: 경쟁사_기능분석_및_고객기능_세부기획 §12(②), 기획_고객_GEO_SEO_실효과_극대화 G1.

## 1. 한 문장
고객이 **확인된 사실만** 한 번 적으면, 그 사실이 AI가 읽기 좋은 형태(회사 정보 코드·`llms.txt` 문안)로 **미리보기**로 나오고, 사이트에 적힌 내용과 다른 곳을 알려 준다.

## 2. 이 화면을 안 만들면 고객이 못 하는 것
"내 브랜드가 무엇인지"를 AI에게 **일관되게** 알릴 기준을 한 곳에 못 둔다(지금은 사이트마다·프로필마다 표현이 다름).

## 3. 위치 (새 탭 없음)
- 기존 `/brand` 화면 안의 **「내 브랜드 정보」 카드 1장**(기존 프로필 편집기 아래).
- 이미 있는 값(브랜드명·표기 변형·정식 상호·사업자번호·업종)은 **다시 묻지 않고 그대로 보여 준다**(단일 원천).

## 4. 입력 항목 (8개 이하 — 기본 6, 접힘 2)
| # | 항목 | 필수 | 증빙 유형(고르기) | 비고 |
|---|---|---|---|---|
| 1 | 한 줄 소개 (60자 이내) | ✅ | 사이트·사업자등록증·직접 확인 중 택1 | "우리는 무엇을 하는 곳인가" |
| 2 | 운영 주체 (개인사업자/법인 등) | ✅ | 〃 | 정식 상호는 기존 값 재사용 |
| 3 | 제공 범위 (무엇을·누구에게) | ✅ | 〃 | 문장 1~2개 |
| 4 | 공식 프로필 주소 (최대 5) | 선택 | 주소 자체가 증빙 | LinkedIn·네이버 블로그 등 |
| 5 | 설립 연도 | 선택 | 〃 | 모르면 비움 |
| 6 | 같은 이름 다른 곳과 구분 문구 | 선택 | 직접 확인 | 동명 충돌 처방용 |

- 각 항목 옆 **「확인함」 체크**가 없으면 미리보기에 **반영하지 않는다**(승인된 사실만 하류로).
- **빈칸은 비워 둔다.** 없는 인력·실적·수상은 어떤 경우에도 자동으로 채우지 않는다.

## 5. 미리보기(결과) 2개 — 만들기만, 사이트에 자동 반영 안 함
1. **회사 정보 코드(JSON-LD `Organization`)** — 복사 버튼. 확인함 항목만 포함.
2. **`llms.txt` 문안** — 복사 버튼.
- 고객이 직접 붙여넣어 쓴다(자동 게시는 2차, 승인 후).

## 6. 불일치 감지 (1차는 단순하게)
- 고객 도메인 홈페이지를 한 번 읽어 **정식 상호·사업자번호·한 줄 소개**가 팩트시트와 같은지 비교 → "사이트에 적힌 상호가 다릅니다" 같은 **사실 문장 1~3개**만.
- 기준 임계값·점수 없음(새 숫자를 만들지 않는다).
- 사이트를 못 읽으면 "확인하지 못했어요"로 표시(추정 금지).

## 7. 저장 (DB)
- 새 테이블 `BrandFactSheet` 1개, **추가만**(기존 테이블 불변). 앱은 `AnswerBrand`와 같이 raw SQL로 읽고 쓰며, **테이블이 없으면 카드가 "준비 중"**이 되고 다른 기능은 영향 없음.
- 운영 DB 반영은 Supabase MCP 한 트랜잭션 + `_prisma_migrations` 행(관례). **반영 전에 관제탑·개발 세션에 알린다.**
- 측정 로직·Brand 행·질문·경쟁사·도메인은 건드리지 않는다(기준선 보호).

## 8. 8층 표 (ui-ux-quality)
| 층 | 할 것 | 🔴 안 할 것 |
|---|---|---|
| ①IA | `/brand` 안 카드 1장, 새 탭 없음 | 새 메뉴·새 화면 |
| ②플로우 | 입력 → 확인함 → 미리보기 → 복사 | 자동 게시, 가입 강요 |
| ③레이아웃 | 기본 3칸 먼저, 나머지 접기 | 한 화면에 입력 10개+ |
| ④인터랙션 | 저장 시 즉시 미리보기 갱신 | 모달 중첩 |
| ⑤비주얼 | 기존 카드 스타일 재사용 | 새 색·새 컴포넌트 |
| ⑥카피 | 쉬운 말, 사전(ko/en) 사용 | 한글 하드코딩, 용어 설명 없는 영어 |
| ⑦상태정직성 | 빈/로딩/오류/부분실패 4상태, 못 읽으면 "확인 못 함" | 추정으로 채움 |
| ⑧기본기 | 라벨 있는 입력, 키보드 이동 | placeholder만 있는 입력 |

## 9. 안 고쳐지는 것 3개
1. 사이트에 실제 반영(자동 게시)은 안 된다 — 복사해서 붙이는 방식.
2. 동명 충돌의 **측정 쪽** 해결(이름 검색 API)은 기준선 이후.
3. n=1 사건에서 나온 기능이라 **고객이 실제로 쓰는지는 미검증**(5~10곳 테스트 필요).

## 10. 구현 순서
1. 테이블 SQL(미적용) + 읽기/쓰기 모듈 + 단위 테스트
2. 저장 서버액션(org 스코프 검증) + 입력 카드(파일럿 스위치 뒤)
3. 미리보기 2개(순수 함수 + 테스트)
4. 불일치 감지(사이트 읽기 — 3단계 이후 별도 승인 없이 진행하되 측정 경로와 무관)
5. 검증(check·tsc·vitest·build) → 관제탑 사전 통지 → 운영 SQL 반영 → 배포
