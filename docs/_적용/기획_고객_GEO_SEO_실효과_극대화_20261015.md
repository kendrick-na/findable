# 기획 — 고객의 GEO·SEO 실제 효과를 만드는 기능 (2026-10-15)

> 상태: **기획안(미승인)**. 앞 문서 `기획_자체진단에서_배운_고객기능`(F0~F9, "문제를 정확히 보여주기")의 다음 층이다.
> 이 문서는 "**고치고, 반영하고, 효과를 증명하기**"를 다룬다. 측정 코드를 건드리는 항목은 영업 베이스라인 동결 해제 후 착수.
> 표기: [관찰] 오늘 직접 확인 / [가설] / [확인필요]. 어떤 기능도 **노출 보장**을 약속하지 않는다.

## 1. 한 줄 결론

**진단만 파는 서비스는 "이렇게 고치세요"에서 끝난다. 효과는 ① 실제로 적용되고 ② 그것이 읽히고 ③ 변화가 증명될 때 생긴다.** 현재 Findable은 측정·분석·추천은 강하고, 적용·유지·증명이 약하다. 그 세 곳을 채우는 것이 "본분 극대화"다.

## 2. 효과가 만들어지는 길 — 그리고 우리가 어디서 막히는지

고객 브랜드가 AI·검색에 나오려면 다섯 단계를 지나야 한다. 이번 자체 점검에서 우리 사이트는 **단계마다 구멍이 있었다**.

| 단계 | 질문 | 이번에 본 우리 사례 [관찰] | 지금 제품의 지원 |
|---|---|---|---|
| ① 접근·색인 | 읽힐 수 있나 | 구글이 중요 페이지 29개를 "크롤링됨-색인 안 함"으로 보류, 테스트·앱 주소 노출 | 홈 1페이지 점검 18개, 구글 연결 있음 |
| ② 이해 | 정체·설명이 맞나 | 동명 서비스에 밀림, AI가 옛 이름을 "구글 인증 대행"으로 오해 | 표기 변형 추적, 정체 확인 일부 |
| ③ 선택 | 질문에 답이 되고 인용되나 | 구글 AI 모드는 우리를 모르고 추천 질문에서 제외 | 질문·인용 측정, 경쟁사 빈틈 분석 |
| ④ 확산 | 제3자가 우리를 말하나 | 기사·위키·Medium은 있으나 우리가 몰랐음 | 출처 빈틈(경쟁사 비교) |
| ⑤ 증명 | 효과가 났다고 말할 수 있나 | 측정 설계 오류로 "안 나온다"를 잘못 믿음 | 효과영수증 설계 문서 |

## 3. 신규 기능 제안 (G1~G11)

### A. 적용 — "처방"을 "완료"로 바꾼다

| ID | 기능 | 무엇을 | 왜 효과가 나나(근거) | 기존 자산 |
|---|---|---|---|---|
| **G1** | **브랜드 팩트시트 허브** | 고객이 **확인된 사실만** 한 번 입력(정식명·표기 변형·한 줄 설명·운영 주체·분야·도메인·공식 프로필·제공 범위). 각 항목에 증빙 유형과 "확인함" 표시 필수. 이 한 곳에서 자동 생성·동기화: Organization JSON-LD, llms.txt, 공식 사실 문서(우리 `/ai-instructions` 같은 것), 메타 설명 후보, 프로필 소개문, 보도자료 기본문. 사이트마다 다르게 쓴 곳을 찾는 **불일치 감지** | AI는 "누구이고 무엇인가"가 여러 곳에서 같을 때 안정적으로 설명한다 [가설]. 우리도 한 문장을 모든 곳에 맞추는 작업을 했다 | `official-site-identity`, 구조화 데이터 생성, llms.txt 생성 |
| **G2** | **적용 경로 3종** | (a) 복사·붙여넣기 조각 (b) Findable이 호스팅하는 팩트시트·글 페이지(고객 도메인 연결, 이미 발행 플랫폼 있음) (c) 연동: 카페24·스마트스토어·WordPress(개발 중) / Next.js는 코드 변경 제안(PR). **적용 후 자동 재검사로 "읽히는지" 확인** | 고객 대부분은 개발자가 없다. 처방이 실행되지 않으면 효과가 0이다 | 발행 플랫폼, 사용자 정의 도메인, IndexNow |
| **G3** | **질문-페이지 맵 + 답변 우선 콘텐츠** | 측정된 질문 중 고객이 빠진 질문 → "한 질문 한 페이지" 브리프 → 팩트시트 기반 초안 → 품질 게이트(확인 안 된 수치·수상 차단) → 발행. **같은 주제 중복 경고**, 한/영 글 **쌍 연결**(슬러그 달라도 hreflang), 내부 링크 제안 | 우리가 겪은 "같은 주제 2개 중 하나 탈락", "한/영 쌍 깨짐"을 제품이 막는다 [관찰] | 질문 계획 v2, `ContentQualityCheck`, 발행 Job |
| **G4** | **도달 경로 등록 마법사** | 구글 서치 콘솔 · 네이버 서치어드바이저 · 빙 웹마스터(ChatGPT 검색이 빙 색인을 쓰는지는 [확인필요]) · IndexNow를 **한 화면에서 단계별 등록**: 인증 메타 삽입, 사이트맵·RSS 제출, 상태 확인. 고객이 "등록 안 해서" 못 나오는 경우를 제거 | 우리도 서치어드바이저 인증은 돼 있었으나 구글 색인은 보류됨 — 등록은 시작일 뿐 | 구글 연결, IndexNow 구성 |

### B. 유지 — 한 번 고친 것이 깨지지 않게 한다

| ID | 기능 | 무엇을 | 근거 |
|---|---|---|---|
| **G8** | **사이트 가드(상시 감시 + 배포 전 검사)** | 매주 사이트 전체 순회(앞 문서 F4)로 **회귀 경보**: noindex 누수, 사이트맵 깨짐, robots 변경, hreflang 깨짐, 이름 변경 후 옛 이름 잔존. 선택 기능으로 **배포 전 검사 API/GitHub Action**(위반 시 경고·차단) | 우리가 겪은 테스트 발행처 누출·hreflang 깨짐·영어 링크 307은 모두 **배포 후에야** 발견됐다 [관찰] |

### C. 이해·선택 — 정확하게, 그리고 인용되게

| ID | 기능 | 무엇을 | 근거 |
|---|---|---|---|
| **G6** | **오해 교정 워크플로** | AI 답변이 팩트시트와 **다르게** 설명하면 감지 → 원인 추적(인용된 출처·우리 페이지·동명 대상) → 출처에서 고치는 처방(내 페이지 수정 / 제3자 페이지 정정 요청 문안) → 재측정으로 교정 확인 | 우리 사례: ChatGPT·Claude가 "Findable OAuth Verification"을 구글 인증 대행으로 설명 [관찰]. 원인은 우리가 흘린 옛 이름이었다 |
| **G9** | **엔진별 도달 진단** | 엔진마다 ① 해당 크롤러가 가져갈 수 있나(robots·방화벽·**서버 로그의 방문 기록**) ② 그 엔진이 쓰는 색인에 있나 ③ 답변이 어떤가. 로그 연동(Vercel·Cloudflare 등)으로 AI 크롤러 방문을 **증거로** 확인 | Codex 지적: 200 응답만으로는 도달 증명이 안 된다. 인용 주소와 방문 기록이 맞으면 강한 증거 |
| **G10** | **한국 특화(네이버·동명 처방)** | 네이버 AI 브리핑이 인용하는 출처(블로그·카페·지식iN 비중) 기반 처방, 서치어드바이저·RSS 운영, **한글·영문 동명 충돌** 처방(분야·도메인 결합 문구, 표기 연결) | 우리 사례: 네이버 AI 브리핑은 우리를 출처로 썼고, 구글 AI 모드는 몰랐다. 한글 "파인더블"은 호텔·동명 회사·동명 GEO 업체에 가려졌다 [관찰] |

| ID | 기능 | 무엇을 | 근거·주의 |
|---|---|---|---|
| **G5** | **외부 출처 확보 엔진** | 카테고리별 AI가 많이 인용하는 외부 도메인 → 확보 과제 목록(우선순위) → **사실만 쓴 템플릿**(보도자료·디렉터리 등록·리뷰 요청·브랜드 블로그 운영 가이드) → 완료 증빙 수집 → 재측정. 위키·위키데이터는 **독립 제3자 출처가 충족될 때만** 자격 점검(자기 편집 금지 안내) | 신규 브랜드의 최대 레버는 제3자 언급일 가능성이 크다 [가설: 우리 사례는 일부만 확인]. **협찬·광고 표기 의무 등 법 준수 문구 필수** [확인필요: 표시광고법 가이드] |

### E. 증명 — 효과를 말할 수 있게 한다

| ID | 기능 | 무엇을 | 근거 |
|---|---|---|---|
| **G7** | **실험 설계·귀속(증명 엔진)** | 처방을 **실험**으로 취급: 처리 질문군 vs 대조 질문군, 반복 횟수·엔진·웹검색 여부 고정, 사전 기준선 기록, **불확실성 구간과 함께** 변화 표시. "효과영수증"으로 발행. 대조 없이 인과를 단정하지 않는다 | 우리 오진의 원인이 정확히 "조건이 다른 숫자를 비교"한 것이었다 [관찰]. AI 답변은 변동이 커서 단발 비교는 무의미 |

## 4. "Findable on Findable" — 우리가 첫 실험 대상 (G7의 선행 사례)

우리 사이트에 G1·G3·G4·G5·G8을 먼저 적용하고 **기준선 대비 변화를 기록**한다. 이것이 제품 검증이자 영업 자료다. 공개는 대표 확인 후(보류 결정).

| 지표 | 기준선 (2026-10-15 관찰) | 재측정 |
|---|---|---|
| 구글 색인 / 미색인 | 27 / 48 (크롤링됨-미색인 29) | +2, +4, +8주 |
| 구글 90일 클릭·노출 | 14 · 364 (평균 순위 33.4) | 동일 |
| 구글 AI 모드: "파인더블이 뭐야?" | 호텔·동명 회사로 답변, 우리 미인지 | 동일 질문 |
| 구글 AI 모드: 추천 질문 2종 | 우리 없음 | 동일 질문 |
| 네이버 `Findable GEO`·`파인더블 GEO` | AI 브리핑이 우리 /insights 인용, 기사·위키 노출 | 동일 |

| ChatGPT(개인화 계정) | 이름·추천 질문 모두 우리 포함 — **개인화 가능, 일반화 불가** | 개인화 없는 환경 확인 필요 |

※ 이 표는 **관찰값**이다. 변화가 생겨도 우리 조치 때문인지는 대조 없이 단정하지 않는다.

## 6. 설계 원칙 (이번에 배운 것을 제품 규칙으로)

1. **보장 금지**: "노출됩니다/순위 오릅니다" 문구 금지. 화면에 [관찰]/[가설] 등급을 표시한다.
2. **사실만**: 고객이 확인한 사실만 생성·게시에 쓴다. 증빙 없는 수치·수상·고객 표기는 게시 전 차단.
3. **한 번에 한 병목**: 처방은 우선순위 한 개 + 이유 + 확인 방법.
4. **적용은 검증까지가 한 세트**: 적용 직후 재검사로 "읽히는지" 확인.
5. **비교는 같은 조건끼리**: 웹검색 여부·질문 유형·엔진·반복 횟수가 다르면 합치지 않는다.
6. **외부 제출 숫자는 부풀리지 않는다**: 팀·테스트 계정은 공개 수치에서 제외(홈 카운터 사례).

## 7. 제약·위험

| 항목 | 내용 |
|---|---|
| 베이스라인 동결 | G6·G7은 측정·질문 코드와 맞닿음 → 동결 해제 후 |
| 비용 | 웹검색 측정은 호출당 비용(코드 주석 기준 1,000회당 약 10달러). 플랜별 상한 |
| 약관·법 | 검색 수집은 공식 API만. 사이트 순회는 robots 준수·속도 제한. 외부 출처 확보(G5)는 표시광고·협찬 표기 준수 [확인필요] |
| 오남용 | G5가 스팸·가짜 리뷰 도구가 되지 않게 **사실 템플릿·증빙 필수**, 대량 자동 발송 없음 |
| 기대 관리 | AI 노출은 변동이 크다. G7 없이 "효과 있음"을 말하지 않는다 |

## 8. 대표님 확인이 필요한 것 (이 문서 한정)
