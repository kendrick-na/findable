## 3. 🅰️ 1단계 — "4곳처럼" (경쟁사 수준 도달)

### 3-a. 공통 자산 신설 — **지표 사전** ⭐ 가장 먼저

지금 지표 설명이 컴포넌트마다 흩어져 있다(`hint` 문자열). 이걸 **하나의 사전**으로 올린다.

```ts
// packages/audit/metric-dictionary.ts (신설)
export interface MetricMeta {
  label: string;        // "우리를 아는 AI"
  question: string;     // "AI가 우리를 아나?"      ← 카드 라벨(질문형)
  description: string;  // "AI 답변에서 우리 브랜드를 언급한 엔진 수"  ← 항상 표시
  format: "percent" | "count" | "rank" | "score";
  direction: "higher" | "lower";  // 🔴 Scrunch 방식
  denominator?: string; // "AI 7곳 중"             ← 🔴 분모
}
```

🔴 **읽는 코드가 없는 필드를 만들지 않는다**(v2 교훈) → **화면에서 실제로 읽는 4곳**을 같은 커밋에 연결:
무료진단 결과 · 대시보드 히어로 3장 · `/compare` · `/sources`.

## 5. 🔴 이 설계로도 안 고쳐지는 것

1. **첫 결과까지 1~3분** — 7엔진 실시간이라 구조적. Profound도 3분20초, Otterly 4분.
2. **실고객 검증** — UI를 고쳐도 지불의사는 시뮬로 안 나온다(r≈0.20). 유저 0명이 최대 병목.
3. **반복 개선** — 스킬 명시: *"잘 만든 제품은 수십 번 갈아엎은 결과. 1회로는 안 된다."*
4. **취향의 마지막 10%** — 색·모션·톤은 사람이 만든다. 도구는 바닥만 올린다.

## 6. 착수 순서 (승인 후)

| # | 묶음 | 위험 | 규모 |
|:--:|---|:--:|:--:|
| **1** | **정렬·타이포 기본기** (좌측선 8→2 · 근사불일치 10→0 · keep-all 10곳 · 입력 라벨) | 낮음 | M |
| **2** | **지표 사전 + 3단 표시 + 분모 명시** (읽는 곳 4군데 같은 커밋) | 중간 | M |
| **3** | 🆕 **대시보드 탭 7개 재편** — 있는 데이터를 꺼낸다(AI별·출처·평가 신설) | 중간 | **L** |
| **4** | **순위 충격 공개 + 모바일 처방 상단화** (무료진단 결과) | 중간 | M |

| **6** | **로그인 PC 소셜 프루프** | 낮음 | S |
| — | 2단계(한국 축 1급 · 진실거울 강화 · 지역·페르소나 스키마) | — | 별도 승인 |

⚠️ **2번이 3번보다 먼저인 이유**: 탭 7개를 만들면 지표가 **7화면으로 퍼진다.**
지표 사전을 먼저 만들지 않으면 **같은 지표를 7곳에서 각자 설명**하게 되고,
그건 이 저장소가 이미 세 번 겪은 사고다(N-14 분모 부재 → N-28 `7/6곳·117%` → 오늘 `95% vs 7곳`).

⚠️ **1번을 먼저 하는 이유**: 스킬 4층 모델 — *"①②를 안 고치고 ③④만 손대면 고쳤는데도 별로다가 반복된다."*
그런데 우리는 반대다. ①(뭘 넣나)·②(얼마나)는 v2에서 이미 정리했고, **남은 게 ③④(배치·보기)**다.
🔴 그리고 ③④가 정확히 **align.mjs 가 잡은 그 항목들**이다 — 지금까지 **재는 도구가 없어서** 못 고쳤다.
