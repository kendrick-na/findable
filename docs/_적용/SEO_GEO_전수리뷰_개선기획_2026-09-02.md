## 2. ✅ 합격 — 리서치 요건을 이미 충족한 것

| 리서치 근거 | 현황(실측) |
|---|---|
| 1차 §1-2·1-3 (sitemap/robots는 로케일 밖 표준 파일) | `app/robots.ts`·`app/sitemap.ts`가 `app/` 루트. 미들웨어 matcher가 `xml`·`txt` 제외. `/robots.txt` 200 · `/sitemap.xml` 200 |
| 1차 §1-7 (hreflang은 canonical과 일치·자기참조) | 사이트맵 47 URL에 `xhtml:link` 90개, ko↔en 상호참조 + `x-default`. 대부분 페이지 head에도 3종 hreflang |
| 1차 §1-4 (JSON-LD는 서버 렌더 + `<` 이스케이프) | `packages/seo/json-ld.tsx`가 `<` 등 이스케이프. 홈 = SoftwareApplication·Organization·WebSite / 글 = Article+BreadcrumbList / 인사이트 = CollectionPage+ItemList / 용어집 = DefinedTerm+DefinedTermSet·FAQPage |
| 2차 §A-3 (네이버 IndexNow 지원) | IndexNow 키 파일 `/7810a16b-….txt` 200. 제출 코드 존재(`apps/app/app/actions/search-performance/manage.ts`) |
| 2차 §C (구글 뉴스 사이트맵: 최근 2일) | `/news-sitemap.xml` 200, `news:` 네임스페이스·2일 창 필터 구현 |
| 1차 §1-8 (네이버 서치어드바이저 등록·RSS 제출) | 네이버 인증 meta 존재. `/rss.xml`·`/feed.xml` 200 |
| 1차 §4-2 (GSC 등록) | **DNS TXT로 소유확인 완료** (`google-site-verification=joa4bWX…`) — HTML meta가 없어 "미등록"으로 오판하기 쉬움 |
| 2차 §A-1 (llms.txt는 효과 없음에 가까움) | `/llms.txt`는 두되 **핵심 전략에 넣지 않음** + 미출시 기능 광고 금지 가드 테스트까지 있음 → 리서치 결론과 정확히 일치 |

| 1차 §2-3 (답변 우선 구조) | 글 첫 문단이 결론 문장으로 시작, 목차·발행일·수정일 노출 |

## 3. 🔴 P0 — 라이브 SEO·GEO 자산이 git에 없다

라이브에서 200을 주는데 **커밋된 어떤 브랜치에도 소스가 없는** 파일:

| 라이브 URL | 실제 소스 위치 | 없어지면 |
|---|---|---|
| `/news-sitemap.xml` | `stash@{0}^3` 미추적 | robots.txt가 이미 이 주소를 광고 중 → **404 광고** |
| `/ai-instructions` | `stash@{0}^3` 미추적 | sitemap.ts가 이미 등재 중 → **404 등재** |
| `/rss.xml`, `/feed.xml` | `stash@{0}^3` 미추적 | 네이버 서치어드바이저 RSS 제출 주소가 죽음 |
| `public/7810a16b-….txt` | `stash@{0}^3` 미추적 | IndexNow 키 검증 실패 |
| `app/[locale]/components/site-header.tsx`, `insights/loading.tsx` | `stash@{0}^3` 미추적 | 글·인사이트 헤더 소멸 |

동시에 **커밋된 HEAD가 라이브보다 후퇴**해 있다:

| 항목 | 라이브(=stash) | HEAD(커밋본) | 배포 시 결과 |
|---|---|---|---|
| hreflang·sitemap 로케일 | `ko`+`en`, x-default=en | **`ko` 단독** | EN 23페이지가 사이트맵·hreflang에서 사라짐 |
| `UNPREFIXED_LOCALE` | 무접두사 사용 금지 | `en`(무접두사) | 지오 리다이렉트되는 URL을 정본으로 신고 |
| robots `host` | `www.findable.co.kr` | `https://www.findable.co.kr` | robots.txt 문법 위반(호스트명만 허용) |
| 글 페이지 렌더링 | ISR+`generateStaticParams`+구슬러그 호환 | **`force-dynamic`** | 프리렌더 소멸 → 크롤 시 매번 DB, 구슬러그 404 |
| `max-image-preview:large` | 있음 | 없음 | 구글 Discover 큰 카드 자격 상실(3차 §A) |

> 리스크 등급 🔴🔴 — 스태시는 `git stash drop` 한 번, 저장소 정리 한 번으로 **영구 소실**된다(과거 Aora v3 소실과 같은 구조). 게다가 HEAD를 그대로 배포하면 위 5개 URL이 동시에 404가 된다.

**조치**: 새 브랜치에서 `stash@{0}` 적용 → 미추적 6개 파일 `git add` 강제 → HEAD 후퇴 항목 정리 → 커밋. 배포 전 `_백업/`에 현행 파일 사본.

## 4. 🔴 P1 — 페이지별 결함 (전수 실측)

### 4-1. canonical·hreflang이 아예 없는 페이지 (6개)

`/ko|/en` × `/case/a-brand` · `/legal/privacy` · `/legal/terms`

- `createMetadata`를 안 쓰고 페이지에서 직접 메타를 만든다 → canonical·hreflang·og:url 전부 없음
- og:image도 파일 컨벤션 자동 태그(`?opengraph-image…` 쿼리형)로 새어 나감
- 법적고지 meta description = **4~16자**(`이용약관` 4자) → 사실상 없음
- 근거: 1차 §1-7 — "hreflang URL은 반드시 canonical이어야 하고 자기참조 태그도 항상 포함"

### 4-2. canonical이 다른 언어를 가리킨다 (2개)

| 페이지 | canonical | hreflang | 문제 |
|---|---|---|---|
| `/en/report/k-beauty-geo-2026q2` | `/ko/report/…` | en 자기참조 | 신호 충돌 |
| `/en/research/k-geo-bench-v0_1` | `/ko/research/…` | en 자기참조 | 신호 충돌 |

hreflang은 "en이 정본"이라 말하고 canonical은 "ko가 정본"이라 말한다. 1차 §1-7 기준 구글은 이런 클러스터를 **통째로 무시**할 수 있다. K-GEO Bench·K-뷰티 리포트는 우리 최고 자산이라 손실이 크다.

### 4-3. 제목 접미사가 두 번 붙는다 (17 페이지)

`AI 검색 가시성 측정 방법 | Findable | Findable`, `What is GEO? | Findable | Findable` …

- 원인: `seoTitle`/사전 문구에 이미 `| Findable`이 들어 있는데 `createMetadata`가 `${title} | Findable`을 또 붙인다
- 영향: SERP·AI 답변 인용 표기에 그대로 노출. 용어집 5×2, EN 글 6, KO 글 2 등 **17페이지**
- 조치: `createMetadata`에서 접미사 중복 제거(끝이 `| Findable`이면 붙이지 않음) + 가드 테스트

### 4-4. 그 외 페이지 결함

| 페이지 | 결함 | 근거 |
|---|---|---|
| `/ko/contact`·`/en/contact` | **H1 없음** | 1차 §3-1(H1=검색 의도), 자사 점검항목 "대표 H1 추가" |
| `/pricing` | 제목 14자(`요금제 | Findable`), JSON-LD **0개**(Offer·Product 없음), H2 1개 | 1차 §1-4 지원 타입에 Product/Offer 포함 |
| `/p/findable`(퍼블리셔 홈) | JSON-LD **0개**(Blog·CollectionPage 없음) | 인사이트 허브인데 엔티티 미선언 |
| 홈 `/ko`·`/en` | FAQ 섹션은 있는데 **FAQPage 스키마 없음**(용어집엔 있음) | 2차 §A-1: 구글 리치결과는 2026-05-07 폐지 → **SEO 목적 없음**, AI 파싱용 저비용 위생조치로만 |
| `/ko/audit` | 본문 720자, H2 0개 | 동선에서 뺀 페이지라 우선순위는 낮음 |

### 4-5. 매 요청 SSR인 페이지 14개 (프리렌더 없음)

`/insights`(ko·en) · `/glossary`(ko·en) · `/legal/*` · `/p/findable` · `/research/*` · `/ko/audit`

- TTFB 0.26~0.62s. **인사이트 허브가 SSR** = 크롤러가 가장 자주 오는 목록 페이지에서 비용을 낸다
- 1차 §1-6: 목록·문서 페이지는 SSG/ISR이 정석

### 4-6. 홈 HTML 223KB / 본문 4,899자

텍스트 대비 마크업·JS 비율이 극단적으로 높다(≈2%). 1차 §1-5 기준 LCP·INP 위험. `/ko/pricing` 97KB·`/ko/insights` 96KB도 동일 경향.

## 8. 개선 기획 (우선순위·작업단위)

### P0 — 오늘 (기존 자산 보존)
1. **stash 회수·커밋** — `stash@{0}` 적용 → 미추적 6개 파일 커밋 → HEAD 후퇴 5항목 정리(hreflang ko+en 복원, robots `host` 호스트명, 글 페이지 ISR, `max-image-preview:large`)
2. 배포 전 `_백업/`에 현행 `robots.ts`·`sitemap.ts`·`metadata.ts` 사본
3. 검증: `/news-sitemap.xml`·`/ai-instructions`·`/rss.xml`·키파일 4주소 200 재확인 + 사이트맵 URL 47개 유지

### P1 — 1일 (메타 신호 정합)
4. `createMetadata` 접미사 중복 제거 + 가드 테스트(17페이지)
5. `/case/a-brand`·`/legal/*`를 `createMetadata`로 이관(canonical·hreflang·og) + description 60~155자 작성

| noindex·robots 차단 | 공개 페이지에 없음 |

## 🔴 실측으로 찾은 결함 (오늘 수정)

**`lastmod` 가 요청마다 바뀌었다.** 3초 간격 두 번 요청에 `04:41:39` → `04:41:42`.
정적 30개 URL(15경로×2언어)이 매번 "방금 수정됨"으로 신고되고 있었다.
구글은 부정확한 `lastmod` 를 **무시**한다 → ① 변경 신호 무력화 ② 안 바뀐 페이지에 크롤 예산 낭비.
→ 경로별 실제 수정일(각 페이지 파일의 마지막 커밋일)로 교체. 로컬 검증: 두 번 요청해도 동일.

## 원인 3층 — 무엇이 얼마나 기여하나

**1층 · 나이와 규모 (가장 큰 요인, 즉시 못 고침)**
도메인 등록 **2026-04-16 = 4.5개월** · 공개 페이지 **22개**(한국어 글 7 + 정적 15) · 백링크 사실상 없음.
2차 리서치 §D(Ahrefs 실측): 신규 페이지의 **1년 내 top10 진입 1.74~6.11%**,
구글 1위 페이지 **평균 나이 5년**, top10의 **72.9%가 3년 이상**.
→ 지금 안 잡히는 것은 **정상 범위**다. 이걸 버그로 오진하면 엉뚱한 곳에 시간을 쓴다.

**2층 · 신호가 흔들렸다 (고칠 수 있음 — 오늘 고쳤고 **미배포**)**
- 거짓 `lastmod`(위)
- EN 23페이지가 8/17~9/1 사이 사이트맵·hreflang 에서 **빠졌다가 복귀** → 색인 신호 단절
- 제목 접미사 중복 17p · canonical 없음 6p · EN canonical 이 KO 를 가리킴 2p
- 한글 슬러그 → ASCII 슬러그 **URL 이동 이력**(`LEGACY_SLUG_ALIASES` 가 증거) — 4차 리서치 §C: 마이그레이션은 회복에 시간이 든다
⚠️ **배포 전에는 검색에 아무 변화가 없다.**

**3층 · 네이버는 구조가 다르다**
2차 리서치 §B-4-4: 네이버 AI 브리핑 인용 출처 비중 = **네이버 블로그 158건 > 외부 웹사이트 45건**,
네이버 공식 발표로 **UGC 비중 70%**. 즉 자체 홈페이지로 네이버 상위 노출은 **원래 어렵다**.
네이버 축은 "웹사이트 SEO"가 아니라 **서치어드바이저 등록 → RSS·사이트맵 제출 → 수집 요청**이 먼저다.

## 내가 확인할 수 없는 것 (👤 만 가능)

색인 **상태**는 GSC·서치어드바이저에서만 정확히 보인다. 판별법(📕 `reference_gsc_not_indexed_diagnosis`):

| GSC 표시 | 뜻 | 처방 |
|---|---|---|
| 발견됨 – 현재 색인되지 않음 | 링크(내부·외부) 부족 | 내부링크 강화 + 외부 언급 |
| 크롤링됨 – 현재 색인되지 않음 | 본문 가치·중복 판단 | 콘텐츠 보강(P2 레버) |
| 최종 크롤 날짜 비어있음/1970-01-01 | **한 번도 안 왔다** | 사이트맵 재제출 + URL 검사 요청 |

## 다음 액션 우선순위

1. **배포** — 안 하면 오늘 수정분 효과 0 (카카오페이 승인 후 권장)
2. GSC 색인 상태 확인 → 위 표로 사유 판별
3. 네이버 서치어드바이저에 **RSS 제출**(`/rss.xml` — 최근에야 생겼다) + 사이트맵 재제출 + 수집 요청
4. 자체 발행 IndexNow 통지 연결(네이버 실시간) — 미구현
5. 내부 링크 강화(현재 홈→글 3개뿐) + P2 콘텐츠 레버
