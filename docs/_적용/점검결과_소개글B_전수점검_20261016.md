## 1. 🔴 모바일에서 화면이 옆으로 밀림 [관찰]
- **증상**: 휴대폰 폭(375px)에서 페이지 폭이 443px로 늘어나 **좌우 스크롤**이 생김(한/영 글 모두).
- **원인**: 본문 「공식 정보」의 LinkedIn 주소(`https://www.linkedin.com/company/findableglobal/`, 391px)가 한 덩어리라 줄이 안 바뀜. 사이트의 글 링크 스타일(`apps/web/components/content/markdown-article.tsx`)에 줄바꿈 허용이 없음.
- **고치는 법(권장)**: 링크 스타일에 `break-words`(긴 단어 줄바꿈) 한 줄 추가. 이 소개 글뿐 아니라 앞으로 긴 주소를 넣는 모든 글에 효과. 본문은 안 바뀌므로 재승인 불필요.
- 대안: 본문에서 주소 대신 "LinkedIn" 글자에 링크를 거는 방법 — 글 내용이 바뀌어 대표 재승인 필요.

## 2. 🔴 대표 이미지 없음 [관찰 · 관제탑 확인과 일치]
- 다른 글은 `og:image`·`twitter:image`·구조화 데이터 `image`에 글 전용 이미지(예: `/images/insights/geo-seo-vs-geo-map.webp`)가 있음. 새 글은 세 곳 모두 **사이트 기본 그림**(`/opengraph-image.png`)이고 구조화 데이터에는 `image` 자체가 없음, 본문 위 이미지도 없음.
- **영향**: 카카오·슬랙·SNS 공유 카드가 밋밋함. **구글 디스커버는 큰 이미지가 조건**이라 지금은 대상 아님 [Discover 조건: 큰 이미지 허용 설정(`max-image-preview:large`)은 이미 켜져 있음 — 이미지가 빠진 상태].
- **진행**: 관제탑이 만든 요청서(`docs/_적용/이미지요청_소개글B_Codex_20261016.md`)대로 대표가 Codex로 생성 → **시안 대표 승인 전 연결 금지**. 연결 시 글의 `coverImageUrl`·대체 텍스트를 DB로 넣는 작업이 필요(그때 대상·복원 SQL을 먼저 통지).

## 3. 🟡 글 날짜가 하루 어긋남 [관찰]
- **증상**: 소개 글(한국 시간 10/16 02:03 공개)에 **「2026. 10. 15.」** 표시. 영어판은 `10/15/2026`.
- **원인**: 날짜를 화면에 쓰는 코드 5곳이 `toLocaleDateString(언어)`만 쓰고 **시간대를 지정하지 않음** → 서버(UTC) 기준 날짜가 나옴. 한국 시간 0시~9시에 올린 글은 전날로 보임.
  - 위치: `apps/web/app/[locale]/p/[publisherSlug]/[postSlug]/page.tsx`(2곳), `.../p/[publisherSlug]/page.tsx`, `insights/page.tsx`(2곳).
- **영향 글(6개, DB로 확인)**: 소개 글 ko/en(10/15 → 정답 10/16), `ai-brand-recommendation-comparison-ko/en`(9/8 → 정답 9/9), `google-discover-blog-visibility-ko/en`(9/7 → 정답 9/8).
- **영향 없는 것**: 구조화 데이터·메타의 `datePublished`(ISO, UTC 표기)는 정상.
- **고치는 법**: 5곳에 `timeZone: "Asia/Seoul"` 지정. 코드만 고치면 영향 글의 표시 날짜도 같이 바로잡힘(DB 변경 없음).

## 4. 🟡 새 글로 들어오는 링크가 부족 [관찰]
- 새 글로 가는 링크가 있는 곳: **홈의 최신 글 카드**, 인사이트 목록(맨 위), 발행처 목록, `llms.txt`, RSS(한/영 모두).
- **없는 곳**: `/ai-instructions`(공식 사실 문서), 용어집(GEO 등), 다른 글 본문, 요금제·문의 페이지.
- **영향**: 이름 구분(동명 서비스 혼동)에는 "공식 사실 문서가 이 글을 가리키는" 연결이 도움이 될 수 있음 [추정].
- **제안**: `/ai-instructions`에 "소개 글" 링크 한 줄. 문구·코드 변경이라 **대표 승인 필요**. 용어집·다른 글은 지금은 손대지 않음.

## 5. 🟢 Medium 링크가 로봇에는 403 [관찰]
- 인용한 Medium 주소(`https://medium.com/@findableglobal`)는 자동 접속(curl)에 **403**. Medium이 로봇을 막는 것으로 보이며 사람이 브라우저로 여는 것은 [확인필요 — 대표 브라우저에서 한 번 열어 확인].
- LinkedIn은 200, 나머지 인용 주소(`findable.co.kr`, `/ai-instructions`, 용어집 한/영)는 모두 200(주소 없는 `findable.co.kr`은 `www`로 308 이동).
- 조치: 홈 구조화 데이터 `sameAs`에도 이미 있어 **유지 권장**.

### C 초안 문구 (승인 전 미반영)
대상: `apps/web/app/ai-instructions/route.ts` 의 `## 공개 자료` 목록에 한 줄 추가.

```
- [Findable(파인더블)이 무엇인가요?](${origin}/ko/p/findable/what-is-findable): 서비스 소개 글 (English: [What is Findable (파인더블)?](${origin}/en/p/findable/what-is-findable))
```
- 이유: 공식 사실 문서가 소개 글을 가리키면 "같은 이름의 다른 서비스"와 구분하는 신호가 늘어난다 [추정].
- 새 사실 없음. 이미 공개된 두 글의 제목과 주소만 사용.
- 캐시: 이 문서는 응답을 최대 1일(`s-maxage=86400`) 캐시하므로 배포 후 반영에 시간이 걸릴 수 있음.

### A 배포 후 확인 계획
1. 375px 폭에서 두 글의 가로 넘침 해소(`scrollWidth` = 375).
2. 영향 글 6개의 표시 날짜가 한국 시간 기준(소개 글 10/16, ai-brand-recommendation 9/9, google-discover 9/8)으로 바뀌었는지, 인사이트 목록·발행처 목록의 날짜도 확인.
