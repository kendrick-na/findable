## 3. 제안 ① — 언어 자동 감지 계획 (승인 전 미구현)

### 3-1. 지금 상태 `[확인사실]`
- 앱은 `NEXT_LOCALE` 쿠키만 읽고, 없으면 한국어(`apps/app/lib/i18n.ts`).
- 🔴 **발견**: `lib/i18n.ts` 주석은 "이 쿠키는 `apps/web` 이 이미 심는 것"이라 하지만,
  웹이 쓰는 라이브러리(`next-international` 1.3.1)가 심는 쿠키 이름은 **`Next-Locale`** 이다.
  쿠키 이름은 대소문자를 구분하므로 **웹에서 고른 언어가 앱으로 넘어오지 않는다.**
  (웹 도메인과 앱 도메인이 쿠키를 공유하는지도 `[확인필요]` — 도메인 지정 없는 쿠키는 원래 공유 안 됨)
- 웹사이트는 **IP 국가**(한국 IP=한국어, 그 외=영어)로 언어를 정한다(`packages/internationalization/proxy.ts`).

### 3-2. 제안하는 순서 (위가 우선)

1. **사용자가 직접 고른 언어** — 계정에 저장(Clerk 사용자 정보 `unsafeMetadata`/`publicMetadata` 또는 DB 사용자 행)
   - **사용자 단위**(조직 단위 아님): 같은 회사 안에서도 한국 직원·외국 직원이 다른 언어를 쓸 수 있게.
2. **쿠키 `NEXT_LOCALE`** — 지금 토글이 하는 일. 로그인 전·저장 실패 시의 기억 장치.
3. **첫 방문 시 브라우저 언어(Accept-Language)** — `en` 이 `ko` 보다 앞이면 영어, 아니면 한국어. 결과를 쿠키에 한 번 저장.
4. 아무것도 없으면 **한국어**(현재 기본값 유지).

| 선택지 | 장점 | 단점 |
|---|---|---|
| ⭐ 브라우저 언어(제안) | 사용자 기기 설정을 따름, 해외 거주 한국인도 기기가 한국어면 한국어 | 브라우저 언어를 바꿔 놓은 일부 한국 사용자가 영어로 뜰 수 있음 → 토글로 해결 |
| IP 국가(웹 방식) | 웹과 일관 | **해외 출장 중인 한국 고객이 갑자기 영어 화면**을 봄. 로그인 후 앱엔 부적합 `[AI가설]` |

- ⚠️ 이 감지는 **핵심 화면 번역이 끝난 뒤** 켜야 한다. 지금 켜면 영어 브라우저 사용자에게 "사이드바만 영어"인 화면이 뜬다.
- 변경 범위(예상): `apps/app/proxy.ts`(감지), `lib/i18n.ts`(우선순위), `app/locale/route.ts`(계정 저장 추가). 라우트 URL 변경 없음.

## 4. 제안 ② — 새 한국어 하드코딩 막는 장치(가드레일)

**제안: "늘어나면 실패" 방식의 테스트 1개** (이 저장소가 이미 쓰는 `__tests__/*.test.ts` 가드 방식과 같음)

- 왜 lint(biome) 규칙이 아니라 테스트인가
