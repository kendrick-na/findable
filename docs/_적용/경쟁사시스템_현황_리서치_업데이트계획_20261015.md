# 경쟁사(경쟁 브랜드) 시스템 — 현황 · 경쟁 도구 리서치 · 업데이트 계획 (2026-10-15)

> 용어: 여기서 "경쟁사"는 고객 브랜드의 **경쟁 브랜드**(예: Findable 의 Profound·Peec AI)다. "경쟁 도구"는 Findable 과 경쟁하는 AI 가시성 서비스다.
> 사실 표기: 코드·실측으로 확인한 것은 사실, 경쟁 도구 정보는 공개 자료(링크)로 확인된 것만. 못 찾은 것은 "확인 필요".

## 1. 경쟁 도구는 어떻게 하나 (리서치)
| 항목 | 확인된 사실 | 출처 |
|---|---|---|
| 도메인을 넣으면 자동 제안? | Ahrefs(웹사이트 분석 후 연관 경쟁 브랜드 제안, 수동 입력 가능), Semrush(도메인 기준 자동 식별), Scrunch(도메인+실제 응답 데이터), Rankscale(함께 나온 브랜드 자동 감지). **제안의 생성 원리(사이트를 읽는지, 모델인지)는 문서에 없음** | [Ahrefs](https://help.ahrefs.com/en/articles/11064852-what-is-brand-radar-and-how-to-use-it), [Semrush](https://www.semrush.com/kb/1493-ai-visibility-toolkit), [Scrunch](https://scrunch.com/blog/2025-12-suggested-competitors-auto-detect-competitive-brands-ai-search/), [Rankscale](https://rankscale.ai/features/ai-competitor-analysis) |
| 승인 방식 | 사용자가 확인·추가(Peec: 체크/거절 X/편집, Scrunch: 추가 또는 무시). 미리 선택해 두는 도구는 확인되지 않음 | [Peec](https://docs.peec.ai/identifying-your-competitors) |
| 첫 측정 후 답변에서 발굴 | Peec: 내 브랜드와 함께 나온 브랜드를 **2회 이상**일 때만 제안(횟수 표시). Scrunch: 잡음 필터 후 제안, 추가하면 과거 데이터에 소급 계산 | 위와 같음 |
| 경쟁사 입력 항목 | Peec: 표시명·추적명·도메인(선택)·별칭·정규식(선택). 흔한 단어 상호는 정규식으로 오탐 방지 | [Peec](https://docs.peec.ai/identifying-your-competitors) |
| 제외 규칙(모회사·매체·마켓플레이스·AI 엔진) | **어느 도구도 공개 안 함** → Findable 자체 설계 | 확인 필요 |
| 한도·요금제 | 경쟁사 수 상한은 대부분 확인 필요. Peec 은 프로젝트(브랜드) 단위 요금제, Semrush 는 추가 도메인 월 $99. 프로젝트 간 경쟁사 목록 공유·템플릿은 확인 필요 | [Semrush](https://www.semrush.com/kb/1493-ai-visibility-toolkit), [Peec 요금 정리](https://www.get-ryze.ai/blog/peec-ai-review-pricing-2026) |
| 한국 | LLM Pulse 가 네이버 AI 브리핑을 추적하고 국내 경쟁사는 사용자가 직접 추가. 한국어 자동 발굴 문서는 못 찾음 | [LLM Pulse](https://llmpulse.ai/blog/introducing-naver-ai-briefing/) |
| 0%여도 보이는 화면 | Semrush(업종 상위 경쟁사 중앙값 비교, 내가 빠진 프롬프트), Ahrefs(점유율 나란히), Rankscale(내가 없고 경쟁사만 인용된 검색어) | 위와 같음 |

**결론:** "도메인 → 제안 → 사용자 승인"과 "첫 측정 후 답변에서 2회 이상 나온 브랜드 제안"이 업계 공통 패턴이다. 승인 전 자동 확정은 하지 않는다.

## 2. Findable 현황 (코드 확인)
| 경로 | 동작 | 상태 |
|---|---|---|
| 저장 | `Brand.competitors`(문자열 목록 또는 `{none:true}` '없음' 표식), 정규화·중복 제거·**최대 20개**(별칭과 같은 상한) | 플랜별 경쟁사 상한은 **없음** |
| 온보딩 4단계 후보 제안 | ① 모델 기억(싼 호출) → 3곳 미만이면 ② 사이트→서비스 분야→웹 검색(ChatGPT)→이름 추출 (10/15 개선) | 화면은 후보를 **기본으로 채워 둠**(2026-08-21 결정) |
| 첫 측정 후 후보 | 프로필 편집기에 '이런 브랜드가 함께 언급됐어요' 칩: 2회 이상·자사/등록 경쟁사 제외·최대 5개·기본 미선택(G4a) | Peec 방식과 같음. 횟수 표시는 아직 없음 |
| 사용처 | 표기 병합(점유율 집계), 질문 제안의 대안 질문, 경쟁 비교 화면. 거르는 용도(화이트리스트)로는 안 씀 | |
| 브랜드 추가(플랜) | 브랜드 한도 free 1 · starter 3 · growth 5 · scale/enterprise 무제한. 추가한 브랜드도 같은 온보딩 순서를 타서 **브랜드마다 따로** 후보를 제안·저장 | 브랜드 간 공유·복사 없음 |

## 3. 점검에서 나온 문제 (12개 사례 실호출) 와 이번 수정
| 문제 | 사례 | 수정 |
|---|---|---|
| 기억만 쓰면 신생 카테고리는 0곳 | Findable 3/3 빈 배열 | 웹 검색 근거 경로 추가 |
| 자사(다른 언어 표기)가 후보에 | 당근 → 'Karrot' | 추출 단계에 자사 이름·도메인 줄기 전달, 어떤 언어든 제외 |
| 같은 회사 하위 브랜드 중복 | SK AX → Accenture 4개·Deloitte 2개 | 첫 단어 같은 이름은 하나로 + 추출 프롬프트가 대표 이름으로 합침 |
| 인접 업종 잡음 | 스타벅스 → 배달앱·POS, 토스 → 배달의민족 | 추출 프롬프트에 '같은 서비스 분야만, 인접 업종·매체·AI 서비스 제외' |
| 시장·규모 무시 | 노우버스 → Accenture·McKinsey, 프롬맘 → 해외 베이비 브랜드만 | 타깃 시장(한국/해외)과 '비슷한 규모·성격'을 질문에 반영 |
| 국내 한정으로 물으면 해외 진짜 경쟁사 누락 | Findable 국내 한정 → 블랙키위·썸트렌드만(Profound 없음) | 시장 지정 시 ① 그 시장 ② 시장 지정 없음 두 번 묻고 번갈아 합침 → 결과: Profound·Scrunch AI·AthenaHQ·Brandlight + 인접 SEO 도구 |
| 사이트를 못 읽으면 후보 0 | 무신사(차단) | 모델 기억 경로로 물러남(무신사는 기억으로 4곳 나옴). 둘 다 없으면 수동 입력 안내 |
| 서비스 분야 판단이 빗나감 | 멜트헤일로(마스크팩)→'안티에이징 스킨케어' → 고가 브랜드 후보 | **미해결** — 제품 단위 재료(소제목·상품명)를 분야 판단에 더 싣는 개선 필요(후속) |
| 응답 시간 | 12~48초(렌더링 포함) | **미해결** — 온보딩에서 비동기·진행 표시 필요(후속) |

수정 후 결과(국내 시장 지정, 실호출): 토스 → 카카오페이·뱅크샐러드·카카오뱅크·핀다…, 프롬맘 → 아토팜·궁중비책·일리윤…, 노우버스 → 베스핀글로벌·메가존클라우드·LG CNS…, 인디고차일드 → 제일기획·이노션·HSAD…, 스타벅스 → 이디야·메가MGC·빽다방…, 당근 → 번개장터·중고나라·헬로마켓(자사 영문명 제거됨), Nike(해외) → Adidas·Foot Locker·Puma….

## 4. 앞으로 어떻게 할지 (대표 결정 필요 항목 포함)
| # | 항목 | 근거 | 승인 |
|---|---|---|---|
| 1 | **후보를 기본 미선택으로** 바꾸기(현재 기본 채움). 오류율이 0은 아니고(인접 SEO 도구·분야 빗나감), Otterly 사고와 질문 설계 원칙(사람이 승인한 것만)이 같다. 대신 [추천으로 담기] 버튼 | Peec·Scrunch·Ahrefs 모두 사용자 확인 후 추가 | **대표 결정**(2026-08-21 결정 변경) |
| 2 | 후보에 **이유·횟수 표시**(예: '답변 6개 중 4개에서 함께 나옴', '웹 검색에서 많이 언급') | Peec 언급 횟수 표시 | 문구 승인 |
| 3 | **거절 기억**(같은 후보 반복 방지) | Peec 거절 X, Scrunch dismiss | 저장 위치: 새 컬럼 없이 `Brand.competitors` JSON 에 `dismissed` 목록(스키마 변경 없음) — 구현 전 보고 |
| 4 | 경쟁사별 **별칭**(한글·로마자·약칭) 입력 | Peec 별칭·Ahrefs 이름 변형. 이미 저장 형식(`{name, aliases}`)은 지원, 입력 화면만 없음 | 화면 승인 |
| 5 | 경쟁사 추가 시 **과거 측정 소급 재계산** | Scrunch backfill | 읽기 전용 재계산이라 구현 가능(점수 불변·표시만) |
| 6 | **플랜별 경쟁사 상한**: 제안 — free 3 · starter 5 · growth 10 · scale/enterprise 20(현재 모든 플랜 20). 경쟁사는 질문 한도(promptLimit)에 포함하지 않음 | 경쟁 도구 상한은 확인 필요(공개 수치 없음) → **우리 설계 제안**이며 근거 없음 | **대표 결정** |
| 7 | **브랜드 추가 시**: 브랜드마다 후보를 새로 제안하되, '다른 브랜드의 경쟁사 가져오기' 선택 버튼(같은 업종 브랜드용)은 선택 사항. 에이전시처럼 브랜드가 많은 플랜(scale 이상)은 일괄 추가 | Peec 은 프로젝트별 목록(공유 확인 필요) | **대표 결정** |
| 8 | 경쟁사가 없어도 보이는 **나란히 비교 + 내가 빠진 질문 목록** | Semrush·Rankscale | 화면 승인(대시보드 설계와 함께) |
| 9 | 후보 생성 **비동기화**(온보딩에서 진행 표시, 백그라운드 생성) | 응답 12~48초 | 화면 승인 |
| 10 | 분야 판단 개선(제품 단위 재료) | 멜트헤일로 사례 | 개발 |

## 5. 알려진 한계
- 후보는 호출마다 달라질 수 있다(웹 검색 기반). 같은 브랜드를 두 번 돌리면 일부가 바뀐다.
- 인접 업종(예: Findable 의 Semrush·Ahrefs·Similarweb)이 섞인다 — 후보일 뿐 사람이 고른다.
- 웹 검색 호출 비용: 브랜드당 ChatGPT 검색 1~2회(약 ₩40~80 추정)+ Haiku 2~3회. 가입·브랜드 추가마다 발생.
