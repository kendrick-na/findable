## 0. 오늘의 대상 정의

| 개념 | 정의 | 핵심 질문 |
|------|------|-----------|
| **프로덕션 릴리스** | 개발분을 프로덕션(main→배포)으로 내보내는 행위 | 무엇이·언제·어떻게 프로덕션에 나가나? 되돌릴 수 있나? |
| **릴리스 노트** | 이번 릴리스에 무엇이 바뀌었는지 기록 | 사용자·미래의 나에게 변경을 설명하는가? |

**Day16(배포 자동화)과의 차이**: Day16 = "push하면 어떻게 배포되나"(파이프라인). Day19 = "**무엇을** 릴리스할지 결정·기록·되돌리기"(릴리스 관리). 배포는 자동이어도 릴리스 결정은 사람 몫.

**Day17·18과의 연결**: Day17 untracked cron, Day18 legal 정정·런북 = **전부 아직 릴리스 안 된 변경**. 오늘은 그것들을 포함해 "쌓인 것을 어떻게 내보낼지"를 다룬다.

## 1. 블라인드 재검증 — 실측 발견 (★ 4건)

### D19-1 [확인사실] ★ 프로덕션(main)과 개발분의 격차가 매우 큼 — 릴리스가 밀려 있음
- `main`이 프로덕션(www.findable.co.kr 배포원). feature 브랜치 = `feature/login-branding-2026-07`.
- **격차: feature가 main보다 13커밋 앞 + 미커밋 111파일**(modified 61 · untracked 50).
- main..feature 13커밋에는 실질 기능 다수: 로그인 브랜딩·대시보드 개선·crew stuck 가드(**Day15 실습발 commit 2ce7f1b 포함**)·SoV→매출 카드·엔진 라우팅·원가전략·측정결함 P0/P1 정합·haiku 전환.
- **문제**: 프로덕션에 없는 개선이 13커밋+111파일 쌓여 있음 = **릴리스 단위가 비대**. 한 번에 머지하면 "무엇이 문제를 일으켰는지" 추적 불가(큰 배치 릴리스의 고전적 위험). Day16 D16-1(CI가 Vercel 자동배포 위임)과 결합하면 머지 순간 전량 프로덕션行.

### D19-2 [확인사실] ★ 릴리스 노트/CHANGELOG 문화 부재
- `CHANGELOG*`·`RELEASE*` 파일 0건. 릴리스 노트를 남긴 흔적 없음.
- 유일한 변경 기록 = **git 커밋 메시지**. 다행히 컨벤셔널 커밋(`feat(audit):`·`fix(auth):`) 규율은 우수 → 릴리스 노트 자동생성의 재료는 있음.
- **문제**: 커밋 메시지는 개발자용. "이번 배포로 사용자에게 무엇이 바뀌었나"를 정리한 릴리스 노트가 없어, 프로덕션에 나간 변경을 사람이 요약·추적할 방법이 없음. B2B 계약·지원사업 실사에서 "변경 관리 체계" 감점 요인.

### D19-3 [확인사실] 미커밋 변경 111개 = 릴리스는커녕 커밋도 안 됨
- untracked 50에 **Day17 sweep cron(web·api 이중구현)·daily-ops-digest cron**, modified 61에 홈 컴포넌트 11개·audit 12개·Day18 legal 정정 포함.
- **위험 3중**: (a) 워킹트리 유실 위험(커밋 안 됨) (b) 무엇이 완성분이고 무엇이 실험분인지 뒤섞임 (c) 다음 릴리스에 **의도 안 한 변경이 딸려나갈** 위험(sweep 이중구현 같은 미정리분).
- Day17 D17-1(sweep untracked)의 릴리스 관점 재확인 = "정리 안 하고 머지하면 이중구현이 프로덕션에 박힘".

### D19-4 [확인사실] 롤백 재료는 있으나 릴리스 절차로 안 묶임
- Vercel Instant Rollback 존재(Day16·18 런북에 기록). 즉 "나쁜 릴리스"는 되돌릴 수 있음.
- 그러나 **"무엇을 릴리스했는지" 기록(D19-2)이 없어 롤백 판단이 어려움** — 뭘 되돌리는지 모르면 롤백도 도박. 릴리스 노트 ↔ 롤백은 한 쌍.

| 항목 | 실태 | 등급 | 최대 갭 |
|------|------|------|---------|
| 릴리스 단위 | 13커밋+111파일 미릴리스, 비대 | **D** | 큰 배치 = 추적 불가·되돌리기 어려움 |
| 릴리스 노트 | CHANGELOG 0·커밋메시지만 | **D** | 사용자/실사용 변경요약 없음 |

## 3. 판단 — 오늘 가장 가치 있는 개입

**"릴리스 자동화 도구 도입"이 아니다.** Vercel 자동배포는 이미 있다(Day16). 진짜 gap은 **밀린 릴리스를 안전하게 내보내는 절차 + 변경을 기록하는 습관**.

1. **D19-3 미커밋 정리 → 논리적 커밋 분할(P0)** — 111파일을 성격별로 묶어 커밋(홈/audit/cron/legal). 특히 **Day17 sweep 이중구현은 커밋 전 단일화(BL-Day17-01) 선결**. 안 그러면 릴리스에 미정리분이 박힘.
2. **D19-2 릴리스 노트 첫 도입(P1)** — 커밋 메시지(컨벤셔널)를 재료로 이번 릴리스 노트 1건 수기 작성. `docs/_적용/릴리스노트.md` 시작 + 형식 확립. 도구 자동화는 나중.
3. **D19-1 릴리스 전략(P1·문서)** — 13커밋을 한 번에 머지할지, 안정분만 먼저 뽑을지 결정. 롤백 계획과 세트.

→ **오늘 실제로 할 수 있는 것 = 릴리스 노트 초안 작성(문서, 저위험)**. 커밋 분할·머지는 실제 git 조작이라 사용자 확인 필수(§7.3, 특히 다른 세션 미커밋 작업 진행 중).

**⚠️ 경계**: 커밋·머지·배포는 되돌리기 어려운 outward-facing 행위 → 사용자 명시 승인 없이 실행 금지. 이번 산출물은 재검증·릴리스 노트 초안·전략 제안까지.
