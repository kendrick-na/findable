## 1. 운영 이관 체크리스트 (재현 가능한 이관 절차)

미래의 나 또는 첫 합류자가 "이 회사의 운영을 넘겨받는다"면 이 목록만 보고 확인 가능해야 함.

### 1-A. 배포·인프라
- [ ] 프로덕션 도메인: www.findable.co.kr(web) / app.findable.co.kr(app) / api(배포 여부 [확인필요])
- [ ] Vercel 프로젝트 3개 root 분리 (web·app·api), ignoreCommand=skip-ci.js
- [ ] 프로덕션 브랜치 = **main**. 현재 작업 브랜치 = feature/login-branding-2026-07
- [ ] 배포 방식 = Vercel Git 자동배포 (push → 빌드). GitHub Actions 게이트 없음(Day16 판단=1인 과투자)
- [ ] env parity 게이트 = `bash scripts/check-app-env-parity.sh` (앱 간 코드 이동 시 런타임 키 확인)

### 1-B. 데이터·스키마
- [ ] DB = Neon PostgreSQL + Prisma (Supabase 아님)
- [ ] 격리 = 앱레벨 `where:{organizationId}` (DB-level RLS 불가, relationMode=prisma)
- [ ] ⚠️ Tracking은 org 키 없이 brandId만 → `scoped.ts` 헬퍼로 brand 경유 강제 (최대 위험 지점, 미커밋 5개 중 1개)
- [ ] 개인정보: IP 수집·무기한 보존(파기 cron 미도입), 처리방침 정정분 미배포([확인필요] 배포 시점)

### 1-C. 운영 자동화 (cron 3개)
- [ ] `sweep-stuck-jobs` (web, 매일 01:00) — 멈춘 AI 진단 정리
- [ ] `daily-ops-digest` (web, 매일 00:00) — 운영 집계
- [ ] `keep-alive` (api, 매일 01:00) — Neon 보온 (api 배포 시에만 실행)

### 1-D. 관측·장애 대응
- [ ] 관측 3종: Sentry(예외) / Logtail(구조화 로그) / PostHog(퍼널)
- [ ] ⚠️ 운영자 장애 알림 부재 (D17-5) — stuck·장애가 log.warn만, 아무도 안 봄. 이관 시 최우선 갭
- [ ] 런북: `docs/_적용/런북_장애대응.md` 5유형 (사이트다운·stuck·엔진장애·결제실패·개인정보요청)

### 1-E. 릴리스 관리
- [ ] 릴리스노트: `docs/_적용/릴리스노트.md` (최신이 위, 롤백의 지도)
- [ ] ⚠️ **현재 초안이 13커밋 기준 → 33커밋으로 갱신 필요** (BL-Day20-01)
- [ ] 롤백 = Vercel Instant Rollback (직전 READY 배포로 복귀)

## 2. 릴리스 드라이런 — 33커밋 main 이관 시나리오 (문서 위 검증, 미실행)

실제 머지·배포 전에 "만약 지금 이관한다면" 순서를 문서로 돌려봄. 각 단계에 **위험·게이트** 표기.

| # | 단계 | 명령/행위 | 게이트·위험 |
|---|---|---|---|
| 1 | 미커밋 5개 성격 확정 | `git diff` 5파일 검토 | 완성분 vs 실험분 구분. scoped.ts는 격리 핵심 → 반드시 검수 |
| 2 | 릴리스노트 33커밋 갱신 | 초안 → 33커밋 사용자 언어 재작성 | AI 초안 후 사용자 검수 (BL-Day20-01) |
| 3 | env parity 확인 | `bash scripts/check-app-env-parity.sh` | PERPLEXITY 등 app 누락 키 재확인 |
| 4 | 로컬 검증 | web tsc·biome (app은 로컬빌드 불가→tsc 갈음) | 통과 필수 |
| 5 | main 머지 | `git checkout main && git merge feature/...` | ⚠️ **고위험·outward-facing·사용자 승인 필수** |
| 6 | 배포 관찰 | Vercel 빌드 → READY 확인 | 실패 시 6-B로 |
| 6-B | 롤백 | Vercel Instant Rollback | 런북 §1 절차 |
| 7 | 릴리스노트 확정 | [미배포·초안] → [2026-MM-DD 릴리스] | 배포 성공 후 |
| 8 | 사후 관찰 | Sentry·cron 실행 로그 24h | ⚠️ 운영자 알림 부재라 수동 확인 필요(D17-5) |

**드라이런 판정**: 1~4·7·8은 저위험(문서·검증). **5(머지)·6(배포)만 고위험** → 이 두 단계는 사용자 명시 승인 게이트. 나머지는 승인 전에도 준비 가능.
