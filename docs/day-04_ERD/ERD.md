## 1. 엔티티 표 (실제 9모델)

격리 기준 컬럼 = **"데이터가 새면 가장 곤란한 단위"**. Findable은 **B2B 워크스페이스 격리 → `organizationId`(org_id 패턴)**.

| 엔티티 | 핵심 컬럼 | 관계 | 민감도 | 삭제방식 | 격리 기준 |
|---|---|---|---|---|---|
| **Organization** | id·name·ownerId(Clerk)·plan·billingStatus·billingCustomerId | 1:N User·Brand·Report | 🔴 billing | hard | (자기 자신=org) |
| **User** | id(Clerk)·email U·name·organizationId | N:1 Organization | 🟡 email | hard | organizationId |
| **Brand** | id·organizationId·name·domain·industry·language·competitors(JSON)·entityVariants(JSON) | N:1 Org, 1:N Prompt·Tracking·Report | 🟢 | Cascade | **organizationId ★** |
| **Prompt** | id·brandId·text·language·category·isAutoGenerated | N:1 Brand, 1:N Tracking | 🟢 | Cascade | brand.organizationId |
| **Engine** | id(chatgpt…)·name·provider·language·isActive·ordering | 1:N Tracking | 🟢 전역시드 | — | (격리 불필요) |
| **Tracking** | id·brandId·promptId·engineId·rawResponse·brandMentioned·mentionPosition·sentiment·citedSources(JSON)·**shareOfVoice**·errorMessage·trackedAt | N:1 Brand·Prompt·Engine | 🟡 원문 | Cascade | **brand.organizationId ★(직접 org 없음⚠️)** |
| **Report** | id·brandId?·organizationId?·type·pdfUrl·data(JSON)·generatedAt | N:1 Brand·Org(둘 다 nullable) | 🟡 | Cascade | organizationId ∥ brandId |
| **AuditJob** | id·email·domain·status·result(JSON)·crewStatus·crewResult(JSON)·**ipAddress**·createdAt | (org 없음) | 🟡 email·ip | hard | ❌**org밖**: email·ipAddress |
| **Lead** | id·email·domain·source·metadata(JSON) | (org 없음) | 🟡 email | hard | ❌**CRM내부**: 앱 노출 안 함 |

★ = 격리(스코핑) 기준 컬럼. ⚠️ = Tracking엔 직접 org 키 없음 → **brand 조인 경유 필수**(우회 위험, rls_policy §위험).

## 2. 관계 (텍스트 ERD)

```
Organization ─1:N─ User
     │
     ├─1:N─ Brand ─1:N─ Prompt ─┐
     │        │                 ├─▶ Tracking (Brand × Prompt × Engine 교차)
     │        └─1:N─────────────┘        ▲
     │                              Engine ─1:N (시드 7)
     └─1:N─ Report (brandId·orgId 둘다 nullable)

[org 밖·비로그인 PLG]  AuditJob(email·ip·crew)   Lead(source)
```

## 3. 설계 판단 (Track A 발견)

1. **`competitor`가 JSON** → 경쟁사 SoV 시계열 추적(Should 승격 시) 하려면 정규 테이블화 필요. → schema_draft.sql §대안 + 백로그 BL-009.
2. **`Tracking`에 직접 orgId 없음** → 앱레벨 격리 우회 위험. → rls §위험1 + 백로그 BL-006.
3. **`relationMode="prisma"`** → DB-level RLS 불가 = **앱레벨 스코핑이 유일 격리선**(스키마가 이미 확정).
4. **`entityVariants`** 한국어 엔티티 그라운딩이 **이미 스키마에 존재** → Day02 한국어 USP가 코드에 반영됨(긍정 확인).
5. **`AuditJob`/`Lead`는 org 밖** → 비로그인 진입점이라 org 방어선 없음 → ipAddress rate limit이 유일 방어(실재 여부 [확인필요]).

> Non-Scope(CMS 발행·API/SSO·모바일·결제 심화)에 닿는 테이블은 만들지 않음 — 현 스키마에도 없음(PRD Scope 일치 확인).
