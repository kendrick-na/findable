# 카카오페이 승인 후 라이브 실행 런북

목적: Findable의 일반결제와 월 정기결제를 카카오페이 라이브 환경에서 안전하게 시작한다.

## 코드에서 완료한 것

- 일반결제 요청을 카카오페이 V2 채널 요구사항인 `EASY_PAY`로 변경했다.
- 정기결제는 첫 회 결제 뒤 다음 달 예약을 생성한다.
- 이후 예약 결제가 `Paid` 웹훅으로 들어오면 다음 달 예약을 한 건만 이어 생성한다.
- 예약 결제 ID·시각을 조직에 저장해 웹훅 재전송에서 중복 예약/중복 청구를 막는다.
- 해지 시 예약 취소 → 빌링키 삭제 → DB 상태 초기화 순서를 유지한다.
- 결제 완료 뒤 요금제 화면에 다음 결제 예정일을 표시한다.

## 대표가 지금 할 일 — 순서 고정

### 1. 포트원 라이브 채널 두 개 확인

포트원 콘솔에서 **카카오페이 일반결제용**과 **카카오페이 정기결제(빌링키)용** 채널이 각각 `LIVE`인지 확인한다.

- 일반결제 라이브 채널키
- 정기결제 라이브 채널키
- 상점 ID
- PortOne API Secret

일반결제와 정기결제 채널키를 서로 바꾸면 결제창 또는 빌링키 발급이 실패한다.

### 2. 포트원 웹훅부터 생성

포트원 콘솔에서 웹훅을 생성하고, **Findable 앱의 프로덕션 도메인**으로 아래 경로를 등록한다.

```text
https://{Findable-앱-프로덕션-도메인}/webhooks/payments
```

- 이벤트: `Transaction.Paid` 포함 결제 상태 이벤트
- 생성된 Webhook Secret은 다음 단계에서 Vercel에 입력
- URL은 `www` 랜딩 페이지가 아니라 로그인·`/billing`이 있는 **앱 배포**를 사용

### 3. Vercel `findable-app` Production 환경변수 교체/추가

값은 채팅·문서·Git에 붙여넣지 않는다. Vercel 환경변수 입력창에만 넣는다.

| 환경변수 | 값 |
|---|---|
| `PORTONE_API_SECRET` | 포트원 라이브 API Secret |
| `PORTONE_WEBHOOK_SECRET` | 방금 만든 웹훅 Secret |
| `NEXT_PUBLIC_PORTONE_STORE_ID` | 라이브 상점 ID |
| `NEXT_PUBLIC_PORTONE_CHANNEL_KEY` | 카카오페이 일반결제 라이브 채널키 |
| `NEXT_PUBLIC_PORTONE_CHANNEL_KEY_BILLING` | 카카오페이 정기결제 라이브 채널키 |

`NEXT_PUBLIC_`로 시작하는 값은 빌드 시점에 브라우저 번들에 반영되므로, 입력 뒤 반드시 새 프로덕션 배포가 필요하다.

### 4. DB 마이그레이션 배포

이 릴리스에는 정기결제 예약 상태를 저장하는 Prisma 마이그레이션이 포함된다.

```bash
cd /Users/easymilli/Downloads/바이브코딩/01_개발_제품/Findable
bun run migrate:deploy
```

배포 로그에서 `20260922_billing_schedule_state`가 적용됐는지 확인한다. 적용 전에는 정기결제를 판매하지 않는다.

### 5. 프로덕션 배포

환경변수와 마이그레이션이 준비된 뒤 `findable-app`을 프로덕션에 배포한다. 배포가 끝난 뒤 실제 브라우저에서 `/billing`을 새로고침해 카카오페이 결제 버튼이 상담 링크가 아닌 결제 흐름으로 들어가는지 확인한다.

### 6. 첫 실결제는 대표 계정으로, 한 번에 한 경로만

Starter(청구액 108,900원)에서 아래 순서로 확인한다. 실제 금액이 결제되므로 대표가 직접 실행·확인한다.

1. **일반결제 1회**: 카카오페이 창 → 결제 완료 → 플랜 활성화 → PortOne 결제 조회 → 웹훅 2xx
2. **정기결제 1회**: 사전고지 → 동의 → 빌링키 발급 → 첫 회 결제 → 다음 달 예약 생성
3. **정기결제 해지**: 요금제 화면 해지 → 다음 예약 취소 → 빌링키 삭제 → 다음 청구 없음

각 단계가 끝날 때까지 두 번째 결제를 시작하지 않는다. 테스트 결제의 취소/환불은 포트원·카카오페이 정산 화면에서 별도로 확인한다.

### 7. 첫 고객에게는 정기결제보다 1회 Sprint부터 판매

실결제 3경로가 정상인 것이 확인되기 전에는 고객에게 월 자동결제를 권하지 않는다. 첫 고객에게는 **14일 Findability Sprint 1회 결제**를 먼저 제안하고, 반복 사용 의사가 확인된 뒤 월 자동결제로 전환한다.

## 라이브 전 금지사항

- 테스트 채널키와 라이브 채널키를 섞지 않는다.
- `PORTONE_WEBHOOK_SECRET` 없이 실제 결제를 열지 않는다.
- 마이그레이션 없이 정기결제를 열지 않는다.
- 고객 결제/구독 상태를 수동 DB 수정으로 처리하지 않는다. PortOne 결제 상태와 웹훅 로그를 먼저 확인한다.
