## 2. 변하지 않는 최상위 원칙

1. 사람에게 유용하고 만족스러운 원본 콘텐츠를 먼저 만든다.
2. 검색 순위, AI 언급·인용, Google News·Discover 노출은 서로 다른 결과이며 어느 것도 보장하지 않는다.
3. AI는 조사·초안·검수 보조에 사용하되, 공개 발행은 사람 승인 뒤에만 한다.
4. 일반론보다 Findable이 직접 측정한 데이터, 재현 가능한 방법론, 원출처가 있는 주장을 우선한다.
5. 콘텐츠를 국문과 영문으로 발행할 때는 제목·핵심 질문·주장·근거·구조를 1:1 매핑한다. 번역이 아니라 의미가 다른 별도 글을 만들지 않는다.
6. 검색엔진별 비공개 가중치를 추측해 키워드 반복, 가짜 언급, 링크 도배, 대량 페이지 생성을 하지 않는다.
7. 고객사 글은 고객사 퍼블리셔 공간에서만 보여주고, Findable 공식 인사이트에는 Findable 퍼블리셔 글만 노출한다.

### 2.1 AI 보조 콘텐츠의 사람 중심 기준

AI 사용 여부를 감추는 것이 목표가 아니다. 독자가 읽었을 때 실제 사람이 조사하고 판단해 쓴 원본 콘텐츠여야 한다.

- AI는 자료 정리·초안·번역 보조까지만 맡기고, 최종 주장·사례·해석은 편집자가 확인한다.
- Findable의 실제 측정, 관찰, 시행착오, 방법론, 한계를 글에 포함한다.
- 내용 없는 도입과 반복적인 결론 문장을 제거한다.
- 모든 문단을 같은 길이·같은 어조·같은 템플릿으로 만들지 않고, 질문·근거·해석·실행이 자연스럽게 이어지게 편집한다.
- AI가 만들어낸 가짜 경험, 가짜 인터뷰, 가짜 통계, 가짜 인용, 확인하지 않은 최신 정보는 사용하지 않는다.
- 여러 글에 동일한 문장·목차·FAQ를 복제하지 않는다.
- 주장과 편집 책임자를 추적할 수 있도록 내부 검수 기록을 남긴다.
- 사람 중심성은 문체 흉내가 아니라 독자에게 새로운 정보와 판단 근거를 제공하는지로 평가한다.

### 2.2 Humanizer식 최종 편집 패스

발행 전 한국어 초안에는 [im-not-ai의 `humanize-korean` 스킬](https://github.com/epoko77-ai/im-not-ai/tree/main/codex/skills/humanize-korean) 원칙을 적용한다. 목적은 AI 탐지기를 속이는 것이 아니라, AI가 자주 만드는 공허하고 획일적인 문장을 사람이 읽고 신뢰하기 어려운 글로 내보내지 않는 것이다.

- 추상적인 칭찬·과장·홍보 표현을 실제 근거와 구체적인 관찰로 바꾼다.
- 같은 접속어, 같은 문장 길이, 같은 3단 나열 구조가 반복되는지 확인한다.
- 의미 없는 서론, 결론 재진술, “중요합니다/살펴보겠습니다”식 상투 문장을 삭제한다.
- 필요한 경우 짧은 문장과 긴 설명을 섞되, 억지로 구어체·오탈자·불완전한 문장을 넣어 사람처럼 보이게 만들지 않는다.
- 브랜드 관점의 판단과 독자에게 유용한 사실을 구분한다.
- `humanize-korean` 통과를 SEO 성과나 인간 작성 증명의 근거로 주장하지 않는다.
- 최종 사실 확인과 발행 책임은 스킬이나 AI가 아니라 사람 편집자에게 있다.
- 의미·사실·수치·날짜·고유명사·인용문은 100% 보존하고, 변경률 30% 초과는 경고, 50% 초과는 롤백한다.
- 번역투·기계적 병렬·상투 관용구·피동 남용·접속사 남발·균일한 리듬·영어 인용 과다를 우선 점검한다.

## 3. 주제 선정 규칙: 무엇을 쓸 것인가

### 3.0 발행 전 중복·잠식 검사 — 필수 게이트

새 글은 작성 전에 국문·영문 각각의 **공개 글, 비공개 초안, 용어집, 리포트, 가이드, 랜딩 페이지**와 대조한다. 제목의 단어가 다른지만 보지 않고 아래 세 축을 비교한다.

1. **주제 중복:** 같은 문제·개념·대상을 설명하는가
2. **검색 의도 잠식:** 같은 독자가 같은 검색 질문의 답을 찾는가
3. **답변·구조 중복:** 결론, H2 흐름, 체크리스트, 사례가 상당 부분 겹치는가

판정은 다음처럼 운영한다.

- 세 축 중 2개 이상이 겹치면 **발행 금지**. 기존 글을 업데이트하거나 새 글의 질문·독자·산출물을 바꾼다.
- 1개만 겹치면 차별화 문장을 먼저 적고, 기존 글과의 내부 링크 관계를 설계한 뒤 진행한다.
- 기존 글을 확장하는 편이 더 유용하면 새 URL을 만들지 않고 **기존 글 업데이트**를 선택한다.
- 공개 URL을 직접 확인하고, 대시보드의 초안 목록과 동일 언어·영문 매핑 글도 확인한다. 확인하지 못한 범위는 “미확인”으로 기록한다.
- 검사 결과를 콘텐츠 생산 카드에 `중복 검사일`, `비교한 URL/문서`, `판정`, `차별화 포인트`로 남긴다.

### 3.0.1 검색 수요·키워드 검증 — 필수 게이트

“SEO에 좋을 것 같다”는 이유만으로 글을 만들지 않는다. 발행 후보마다 국문·영문 검색 수요를 확인하고, 확인한 근거와 확인하지 못한 범위를 기록한다.

- **Google:** Search Console의 실제 노출·쿼리, Google Ads Keyword Planner 또는 확인 가능한 검색 결과의 관련 질문·자동완성
- **Naver:** Search Advisor의 실제 유입 쿼리, Naver DataLab·검색광고 키워드 도구 등 확인 가능한 수요 신호
- **AI/GEO:** ChatGPT·Claude·Perplexity·Gemini·Naver AI 검색에서 실제 질문으로 반복되는 표현과 답변 빈틈

판정 규칙:

1. 검색량·노출·쿼리 데이터가 확인된 주제는 `데이터 확인`으로 기록하고, 기간·지역·언어·도구를 함께 적는다.
2. 정확한 월간 검색량을 확인하지 못했지만 자동완성·관련 질문·실제 유입·반복 질문이 확인된 주제는 `수요 신호 확인`으로 기록한다.
3. 근거가 전혀 없으면 `가설`로 표시하고, 트래픽이 높다고 표현하거나 우선 발행하지 않는다.
4. 검색량이 높아도 기존 글과 검색 의도가 겹치면 발행하지 않는다. 수요와 중복 검사는 모두 통과해야 한다.
5. 높은 검색량만 좇지 않고 `수요 × 관련성 × 근거의 독창성 × 전환 가능성 × 경쟁 공백`으로 우선순위를 정한다.
6. 검색량 수치가 제공하는 도구·시점·국가·기기 조건이 다르면 서로 직접 비교하지 않는다.

콘텐츠 생산 카드에는 `키워드`, `언어`, `검색 시장`, `확인 도구`, `확인일`, `수요 근거`, `판정(데이터 확인/수요 신호 확인/가설)`을 남긴다. 검색 도구에 접근하지 못한 경우에도 그 사실을 숨기지 않는다.

### 3.1 우선순위

각 아티클은 발행 전에 다음을 기록한다.

- 검색자가 실제로 묻는 질문 또는 해결하려는 문제
- 핵심 키워드와 동의어·관련 질문
- 한국어/영어 검색 의도 차이
- 현재 검색 결과의 빈틈: 오래된 정보, 근거 부족, 한국 시장·AI 엔진 데이터 부족 등
- Findable이 직접 제공할 수 있는 원본 관찰·데이터·방법론
- 연결할 기존 가이드·용어집·리서치·관련 글

우선순위는 **검색 수요만 높은 주제**가 아니라 `질문 수요 × Findable의 독자 근거 × 차별적 해결 가능성 × 지속성`으로 판단한다.

정확한 검색량을 확인하지 못했다면 “트래픽이 높다”고 표현하지 말고 “검색자가 반복적으로 묻는 문제로 판단되는 주제”라고 기록한다.

### 3.2 Query Fan-Out 대응

Google이 관련 질문을 확장해 검색하는 Query Fan-Out은 공식적으로 확인된 메커니즘이다. 그러나 “fan-out 전용 해킹”이나 질문 변형별 페이지 대량 생성은 전략으로 채택하지 않는다.

하나의 강한 원문 안에서 다음을 자연스럽게 다룬다.

- 정의: 무엇인가
- 원인: 왜 발생하는가
- 판단: 어떻게 확인하는가
- 실행: 무엇을 고치는가
- 비교: SEO·GEO·AEO의 차이는 무엇인가
- 후속 질문: 실제 독자가 이어서 물을 질문

## 4. 아티클 원고 규칙

### 4.1 기본 구조

모든 SEO/GEO 아티클은 다음 순서를 기본으로 한다.

1. 검색 의도를 반영한 고유 제목
2. 첫 2~3문장의 결론형 답변
3. 왜 이 질문이 중요한지
4. 핵심 개념 또는 원인
5. 단계별 진단·측정 방법
6. 실제 예시·표·수치 또는 관찰 기록
7. 한계와 예외
8. 실행 체크리스트
9. 관련 질문 FAQ
10. 출처·방법론·측정일
11. 관련 Findable 콘텐츠 링크

### 4.2 권장 최소 품질 기준

자동 품질검사와 편집자가 다음을 확인한다.

- 본문 2,500자 이상을 기본선으로 삼되, 짧은 정의 페이지는 예외 사유를 기록한다.
- H2 3개 이상. 제목만 바꾼 얇은 페이지는 발행하지 않는다.
- 첫 단락 안에 질문에 대한 직접 답변이 있다.
- 핵심 주장마다 원출처 링크 또는 Findable의 재현 가능한 측정 근거가 있다.
- 외부 출처는 최소 1개 이상이며, 출처가 없는 수치·비교·배율은 쓰지 않는다.
- 수치에는 표본, 기간, 대상, 측정 방법, 출처를 함께 적는다.
- SEO title은 고유하고 과장 없이 작성하며 중복 접미사를 만들지 않는다.
- meta description과 excerpt는 실제 본문을 요약하며 서로 모순되지 않는다.
- 작성자, 발행일, 수정일은 화면·메타·구조화 데이터가 일치한다.
- 문단은 한 질문 또는 한 주장 단위로 나눠 AI와 사람이 발췌하기 쉽게 한다.
- 결론을 반복하는 키워드 삽입, 숨은 텍스트, 가짜 FAQ, 자체 생성 별점은 금지한다.

### 4.3 GEO 인용 가능성 규칙

AI 답변에 인용될 가능성을 높이기 위해 다음을 우선한다.

- 정의를 짧고 단정적인 문장으로 쓴다.
- 하나의 문장에 하나의 검증 가능한 주장만 둔다.
- “Findable의 측정 기준에서는…”처럼 관찰의 주체와 범위를 밝힌다.
- 통계는 `수치 + 날짜 + 표본 + 방법 + 출처` 형식으로 쓴다.
- 공식 문서, 학술 논문, 원자료, 공개 데이터셋을 우선 링크한다.
- 주장과 출처를 멀리 떨어뜨리지 않는다.
- 마지막에만 결론을 몰아넣지 않고 핵심 답변을 앞부분에도 둔다.
- 브랜드명·도메인·제품 설명을 모든 언어에서 일관되게 유지한다.

구조화 데이터는 파싱 마찰을 줄이는 인프라이지 인용률 상승을 보장하는 장치가 아니다. `llms.txt`도 선택적 안내 파일일 뿐 핵심 GEO 전략으로 과대평가하지 않는다.

### 4.4 E-E-A-T 및 신뢰성

- 공식 글은 Findable의 편집 주체를 명확히 한다.
- 고객사 글은 실제 퍼블리셔·브랜드를 명시하고 익명 발행하지 않는다.
- 저자 페이지 또는 조직 소개로 연결 가능한 경우 `Person` 또는 `Organization` 정보를 일관되게 사용한다.
- 측정 글은 측정일, 질문 세트, 엔진 범위, 표본과 한계를 밝힌다.
- 편집·번역·AI 보조 여부가 사실관계상 중요하면 내부 검수 기록에 남긴다.

## 5. 국문·영문 매핑 규칙

국문과 영문은 다음 항목을 하나의 매핑 묶음으로 관리한다.

| 항목 | 규칙 |
|---|---|
| 주제 | 같은 질문과 같은 독자 문제 |
| 제목 | 직역보다 자연스러운 검색어를 쓰되 의미는 동일 |
| 결론 | 결론·조건·예외를 누락하지 않음 |
| 근거 | 같은 원출처 또는 언어별 공식 원출처 |
| 수치 | 표본·기간·분모를 동일하게 유지 |
| 내부 링크 | 대응하는 국문·영문 페이지로 연결 |
| 메타 | locale에 맞는 title, description, OG, canonical |
| hreflang | 자기참조와 상호 반환 링크, canonical과 동일한 URL |
| 이미지 | 주제·구도 규칙은 동일하되 이미지 안에는 텍스트를 넣지 않음 |

번역 과정에서 영어 글에만 새 주장이나 새 통계를 추가하지 않는다. 추가 근거가 필요하면 양쪽 원고에 반영한다.

## 6. 채널별 검색·AI 유통 기준

### 6.1 Google 일반 검색

**필수:** 공개 접근, HTTP 200, 크롤링 허용, indexable 본문, 고유 title/H1, canonical, 정확한 sitemap·lastmod, 모바일 경험, 빠른 응답, 내부 링크.

**권장:** SSR/SSG/ISR로 크롤러와 사용자에게 본문을 안정적으로 제공, semantic HTML, Article/Breadcrumb JSON-LD, visible byline/date, 관련 대표 이미지.

**금지:** 중복 URL 난립, 잘못된 canonical, 로케일 교차 canonical, 미래 날짜, 키워드 도배, 검색어 변형별 저가치 페이지 대량 생성.

### 6.2 Google AI 검색

Google은 AI 검색을 별도 GEO 해킹으로 보지 않고 기존 검색의 기술·품질 원칙 위에 둔다. 페이지가 Google 검색에 색인되고 snippet 대상이어야 하며, AI 검색 노출은 보장되지 않는다.

적용 기준:

- Googlebot과 필요한 공개 페이지의 접근을 막지 않는다.
- 첫 화면과 서버 HTML에 핵심 답변을 둔다.
- 사람이 읽는 본문과 구조화 데이터를 일치시킨다.
- 근거가 있는 원본성·전문성·최신성을 제공한다.
- Query Fan-Out으로 확장될 후속 질문을 한 글 안에서 자연스럽게 다룬다.
- Search Console의 일반 검색 및 생성형 AI 성과 리포트로 관찰한다.

### 6.3 Naver 웹 검색·AI Briefing

Naver의 정확한 C-Rank·D.I.A 가중치와 AI Briefing 인용 산식은 공개되지 않았다. 따라서 업계 추정 수치를 공식 규칙처럼 사용하지 않는다.

적용 기준:

- 고유하고 명확한 title, H1, 본문 구조를 유지한다.
- 사용자가 원하는 답을 앞에 둔다.
- 네이버 서치어드바이저 소유확인, sitemap, RSS, 수집 요청을 관리한다.
- IndexNow 지원 경로가 있는 경우 발행 URL을 통지한다.
- 네이버 블로그·카페는 네이버 생태계 내 보조 채널로 보고, 자체 도메인 원문을 별도로 유지한다.
- 네이버 AI Briefing의 노출·인용은 적합성·신뢰성·최신성에 따른 자동 결과이며 보장하지 않는다.

### 6.4 ChatGPT·Claude·Perplexity·Gemini

각 서비스의 전체 검색·인용 모델과 가중치는 공개되지 않았다. 다음은 공통적으로 안전한 운영 기준이다.

- 공개 페이지를 로그인·결제·JS 상호작용 뒤에만 두지 않는다.
- 해당 서비스의 공식 크롤러·검색봇을 robots와 방화벽에서 불필요하게 차단하지 않는다.
- 서버 렌더링 HTML, 명확한 제목, 작성자, 게시일, 원출처를 제공한다.
- 브랜드명·도메인·설명·공식 프로필을 일관되게 연결한다.
- 짧은 정의·직답·측정 결과·한계를 함께 제공한다.
- 엔진·질문·지역·날짜를 고정한 반복 측정으로 언급·인용·정확성을 별도 기록한다.

OpenAI는 ChatGPT 검색에서 `OAI-SearchBot` 접근 허용을 공식 안내한다. 다만 허용해도 결과 노출이나 인용은 보장되지 않는다. Claude·Perplexity·Gemini도 동일하게 “공개 접근 + 품질 + 관련성”을 기본 가설로 두고 실측한다.

## 7. Google News·Discover 기준

### 7.1 Google News

Google News는 블로그라고 자동 제외되거나, `NewsArticle` 스키마만 넣는다고 자동 입장되는 구조가 아니다.

- 콘텐츠가 Google에 색인되고 뉴스 정책을 준수해야 한다.
- 제목은 기사의 본질을 정확히 전달해야 한다.
- 작성자·발행일·수정일을 화면과 구조화 데이터에 일치시킨다.
- `Article` 또는 `NewsArticle` JSON-LD를 사용해 제목·작성자·이미지·날짜를 명확히 한다.
- 최신 뉴스성 콘텐츠는 `/news-sitemap.xml`에 최근 2일 창으로 정확하게 포함한다.
- `news:name`은 실제 발행 퍼블리셔 이름을 사용한다.
- 게시일을 미래로 만들거나 기사 내용의 사건 날짜를 발행일로 오인시키지 않는다.
- Google News 노출과 AI 검색 인용 사이에 직접 인과관계가 있다고 약속하지 않는다.

### 7.2 Google Discover

Discover는 색인되고 정책을 준수한 콘텐츠가 자동으로 자격을 얻을 수 있지만, 노출은 보장되지 않는다.

- 유용하고 독창적이며 시의성 또는 독자 관심이 있는 콘텐츠를 만든다.
- 과장·클릭베이트·충격 유도 제목과 이미지를 사용하지 않는다.
- 대표 이미지는 페이지 주제와 직접 관련되어야 한다.
- 가급적 1,200px 이상, 16:9, 300,000픽셀 이상 고해상도를 사용한다.
- `max-image-preview:large`를 허용하고 `og:image` 또는 구조화 데이터의 대표 이미지와 실제 페이지 이미지를 일치시킨다.
- 이미지 하나에 너무 많은 문구를 넣지 않는다. Findable의 브랜드 스타일을 유지하되 이미지에는 텍스트를 넣지 않는다.
- Discover는 관심사 기반이므로 색인·품질 조건 충족이 노출을 보장하지 않음을 명시한다.

## 8. 대표 이미지 규칙

아티클 대표 이미지는 [인사이트 이미지 스타일 가이드](./insights-image-style-guide.md)를 따른다. 최신 4개 자산을 직접 대조한 [스타일 감사 기록](./insights-image-style-audit-2026-09-04.md)과 그 문서의 canonical prompt를 함께 기준으로 삼는다.

고정 기준:

- 거칠지 않은 미세한 종이결의 따뜻한 한지 계열 아이보리 바탕
- 기존 인사이트와 같은 가로형 16:9, 기존 실측 자산 기준 1672×941
- 좌측·우측의 기존 여백과 편집형 다이어그램 배치 유지
- 글 주제를 설명하는 검색창·문서·출처·연결선·노드 등 2~5개의 시각 요소를 하나의 흐름으로 구성
- 검정·네이비·세이지를 기반으로 Findable 오렌지 `#ff7a4d`를 핵심 포인트로 사용하는 제한된 색상
- 이미지 안에 제목, 설명, URL, 회사명, 랜덤 텍스트를 삽입하지 않음
- 가짜 로고·임의 생성 회사 로고·의미 없는 박스·아이콘 나열·다크 3D·네온 금지
- Findable 오렌지가 빠진 일반적인 AI 일러스트 스타일 금지
- 기존 인사이트와 무관한 큰 구형·랜덤 노드·종이 더미만 있는 일반적인 AI 추상화 금지
- `alt`는 이미지를 장식품처럼 설명하지 말고, 실제 주제와 시각적 내용을 자연스럽게 설명
- 생성 시안은 별도 승인 전까지 게시물이나 배포에 연결하지 않음

Google Discover용 대표 이미지는 텍스트가 적고 주제와 관련성이 높아야 하므로, 정보 전달은 이미지가 아니라 페이지의 제목·본문·alt·구조화 데이터로 담당한다.

## 9. 기술·메타·발행 체크리스트

### 발행 전 중복성 게이트

- [ ] 공개 인사이트·가이드·리포트·용어집과 제목만이 아니라 검색 의도까지 대조했다.
- [ ] 대시보드 초안 및 국문·영문 매핑 콘텐츠와 대조했다.
- [ ] 중복이 발견되면 새 글을 발행하지 않고 기존 글 업데이트 또는 차별화된 새 주제로 전환했다.
- [ ] 비교 URL, 검사일, 판정, 차별화 포인트를 생산 카드에 기록했다.

### 검색 수요 게이트

- [ ] Google과 Naver에서 관련 키워드·질문 수요를 확인했다.
- [ ] 국문·영문 각각의 키워드와 검색 의도를 기록했다.
- [ ] 검색량 또는 반복 질문 근거에 도구·기간·지역·언어를 적었다.
- [ ] 확인하지 못한 수치를 ‘트래픽 높음’으로 표현하지 않았다.
- [ ] 높은 검색량이어도 중복·잠식 검사와 독창적 근거 검사를 통과했다.

### 발행 전 자동·개발 검수

- [ ] HTTP 200이며 공개 접근 가능
- [ ] `noindex`·로그인·robots 차단 없음
- [ ] 고유 title, H1, meta description, excerpt 존재
- [ ] canonical이 자기 언어의 정본 URL을 가리킴
- [ ] 국문·영문 hreflang이 서로 반환하고 `x-default`가 있음
- [ ] Article/BlogPosting과 Breadcrumb JSON-LD가 화면 내용과 일치
- [ ] author, datePublished, dateModified가 화면과 일치
- [ ] 대표 이미지 URL이 1,200px 이상·16:9이며 404가 아님
- [ ] `max-image-preview:large`와 OG 이미지가 설정됨
- [ ] 본문 외부 출처·내부 관련 링크 확인
- [ ] sitemap, RSS, 필요 시 news sitemap·IndexNow 대상 확인
- [ ] 고객사 퍼블리셔 글이 Findable 공식 허브에 섞이지 않음

### 편집자 검수

- [ ] 제목이 실제 질문을 정확히 표현함
- [ ] 첫 단락에 직접 답변이 있음
- [ ] 독창적인 데이터·관찰·방법론이 있음
- [ ] 모든 수치에 출처·기간·표본·분모가 있음
- [ ] 공식/실측/추정/미확인을 구분함
- [ ] 질문형 H2와 후속 질문이 자연스럽게 포함됨
- [ ] 국문·영문 내용과 수치가 매핑됨
- [ ] 키워드 반복이나 홍보 문구가 본문을 지배하지 않음
- [ ] 사실과 의견, 측정 결과와 전망을 구분함
- [ ] 독자가 읽고 다음 행동을 알 수 있음

### 승인·발행

`draft → publisher_review → quality_check → moderation_review(조건부) → published`

- AI 초안은 공개하지 않는다.
- 검수 전에는 `noindex: true`를 유지한다.
- 공개 후에만 sitemap·RSS·llms.txt·news sitemap 발견 대상이 된다.
- 발행 후 URL Inspection, Google Search Console, Naver Search Advisor에서 상태를 관찰한다.
- 색인 요청은 새 URL·중요 수정에 한해 사용하고, 반복 요청을 순위 상승 수단으로 보지 않는다.

## 10. 측정과 보고 규칙

노출·인용을 말할 때는 다음 지표를 섞지 않는다.

| 지표 | 정의 |
|---|---|
| 색인 | 검색엔진이 URL을 색인했는지 |
| 검색 노출 | 검색 결과에 노출·클릭됐는지 |
| AI 언급률 | 고정 질문 세트의 답변 중 브랜드가 언급된 비율 |
| AI 인용률 | 정한 분모의 답변 중 출처 링크 또는 인용이 확인된 비율 |
| Share of Voice | 같은 질문 세트에서 브랜드와 경쟁 브랜드의 언급 비중 |
| 정확성 | 브랜드 설명·제품·링크가 사실과 맞는지 |

측정 보고서에는 반드시 엔진, 모델/서비스, 질문, 언어, 지역, 실행일, 반복 횟수, 분모, 원문 응답, 판정 규칙을 기록한다. 한 번의 답변이나 한 번의 검색으로 알고리즘 성과를 결론내리지 않는다.

비교는 같은 질문 세트·같은 엔진 범위·같은 분모·같은 기간 기준으로만 한다. 인용률 상승을 보장하거나 Google·Naver·AI 내부 점수를 안다고 주장하지 않는다.

## 11. 금지 목록

- SEO/GEO 알고리즘을 안다고 단정하는 문구
- 검색량을 확인하지 않고 “트래픽이 높은 키워드”라고 보고
- 검색어 변형마다 거의 같은 글을 대량 생성
- 외부 통계·배율·사례를 출처 없이 작성
- 자기 회사의 별점·리뷰·권위를 구조화 데이터로 과장
- 고객사 글을 Findable 공식 인사이트에 혼합
- 국문·영문 URL을 서로 다른 글처럼 운영
- 다국어 페이지의 canonical/hreflang 불일치
- 이미지에 가짜 로고나 이미지 생성 텍스트를 넣음
- 승인 전 자동 발행·색인 요청
- 색인·News·Discover·AI 인용을 보장한다고 판매

---

## 12. 운영상 미확정·정기 재검토 항목

다음은 규칙으로 확정하지 않고 분기별 또는 큰 검색 업데이트 후 재검증한다.

- Claude·Perplexity·Gemini의 내부 인용 가중치
- Naver C-Rank·D.I.A·AI Briefing의 비공개 가중치
- 저자 Person 스키마가 인용률을 몇 배 높인다는 수치
- 특정 질문형 H2·FAQ의 인용 상승 배율
- Google News와 AI Overview 인용의 직접 상관관계
- 신생 도메인의 이른바 Sandbox 효과
- `llms.txt`의 검색·AI 인용 효과

재검증되지 않은 가설은 랜딩 카피, 고객 약속, 자동 발행 규칙에 반영하지 않는다.
